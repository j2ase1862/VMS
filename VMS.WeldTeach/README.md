# VMS.WeldTeach — CAD 용접 경로 오프라인 티칭 (PoC)

`docs` 외부의 개발 명세서(`CAD_Welding_Path_Specification.pdf` v1.0.0)에 대한 **기술 검증(PoC) 프로젝트**.
목표는 전체 시스템에서 유일하게 검증되지 않았던 **CAD 커널(STEP B-Rep) 리스크 제거**다.
점군 취득·ICP 정합은 VMS 기존 자산(멀티뷰 스캔, Point Cloud Registration 툴)을 재사용하므로 PoC 범위에서 제외.

## PoC 범위

| 명세서 단계 | 포함 여부 | 구현 |
|---|---|---|
| Step 1 — STEP 로드 · B-Rep 렌더링 · Ray-Casting 엣지 피킹 | O | `CadKernelService` + `RayCaster` + Helix 뷰어 |
| Step 2 — 위상 추적 · C1(15°) 엣지 체이닝 | O | `EdgeChainService` |
| Step 3 — 6-DoF 토치 포즈(이등분 벡터) + ZYX 오일러 | O | `TorchPoseService` (JSON 내보내기 포함) |
| Step 3 — ICP 비전 정합 (T_align) | O | `IcpService`(자체 멀티스타트 ICP) + `PointCloudService` |
| 로봇 벤더 전송 | X (벤더 미정) | JSON 포즈 파일까지만 |

## 사용법

1. 실행 후 **[샘플 시편 생성]** — T-필릿 용접 시편(베이스 100×60×8 + 리브 60×8×30)이 STEP 으로 생성·로드된다. 또는 **[STEP 열기]** 로 실제 도면 로드.
2. 모서리에 마우스 호버 → 주황색 강조. 클릭 → 연속 모서리 자동 체이닝 + 경로 목록에 추가.
   **여러 모서리를 순차 클릭하면 경로가 쌓이고, 목록 순서(순번 뱃지·3D 라벨) = 용접 순서.**
   같은 경로의 모서리를 다시 클릭하면 해제. 목록에서 경로 선택 → 토치 화살선(하늘색)과
   6-DoF 포즈 표 표시. [전체 지우기]/항목 ✕ 로 정리.
3. **[경로 내보내기 (JSON)]** — 모든 경로를 용접 순서대로 저장 (CAD 좌표계 기준, ICP 의 `T_align` 적용 전).
4. **포즈 간격(mm)** — 로봇에게 넘길 목표점(웨이포인트) 사이 거리. 경로를 호 길이 기준으로
   균일 재샘플링해 포즈를 만든다 (예: 314mm 원형 심 — 1.5mm→211개, 8mm→40개).
   - 툴바 **기본 포즈 간격**: 새로 추가하는 경로에 적용, [전체 적용]으로 일괄 반영.
   - 패널 **선택 경로 간격**: 경로마다 개별 설정 (직선 넓게 / 곡선 좁게) — 그 경로만 즉시 재계산.
   - **곡률 적응**: 켜면 간격은 최대치가 되고, 곡선 구간은 현 오차 ≤0.05mm 기준으로 자동 촘촘
     (간격 √(8·R·e)). 예: 최대 8mm — 직선 8mm 유지, R50 원형 심은 4.5mm(71포즈)로 자동 조밀.
   - **설정 우선순위 규칙**: 툴바(기본값)는 "앞으로 추가할 경로"에만 적용되고 기존 경로는
     [전체 적용]을 눌러야 덮어써진다. 선택 경로의 간격/적응 설정은 항상 그 경로에 우선 —
     예: 툴바 적응 체크 + 선택 경로 적응 해제 = 그 경로는 균일 간격, 새 경로만 적응 ON.
     경로 선택 시 패널 값은 그 경로의 저장 설정으로 자동 동기화(표시일 뿐, 재계산 아님).
   - **전체 보기**: 모든 경로의 포즈 점·토치 화살선을 동시에 표시 (최종 검수용).
   - 각 경로의 간격·적응 여부는 목록 요약 `@값[·적응]`과 JSON(`spacingMm`/`adaptive`)에 기록.
5. **점군 정합 (툴바 2행)** — [점군 열기](PLY/XYZ) 또는 [합성 점군 생성](기지 오프셋+0.05mm 노이즈)
   → [CAD 정합 실행 (ICP)]. 정합되면 점군이 CAD 위에 겹쳐 표시되고 RMSE/인라이어가 나오며,
   이후 [경로 내보내기]는 모든 포즈를 로봇 좌표계로 변환(T_align 적용, JSON 에 행렬 포함)해 저장.
   - ICP: 자체 구현 — k-d 트리 대응 + Horn 쿼터니언 + 트리밍 + **멀티스타트**(무게중심/±bbox
     오프셋/요 회전 16종 — 부분 스캔의 상면↔밑면 국소최소 회피, 실측으로 확인된 함정),
     정합은 ≤4천점 서브샘플, 최종 RMSE 는 **점-표면(점-삼각형) 거리**로 평가
     (점-점 거리는 샘플 간격이 하한을 지배해 과대평가).
   - 검증: T-필릿 합성 상면 스캔(부분 가시) — 표면 RMSE 0.04mm(노이즈 수준, 명세 기준 0.2mm 통과),
     T_align 복원 오차 ≤0.2mm, 심 포즈 로봇 좌표 변환 일치. 파이프 피팅 11k 점 — RMSE 0.2mm,
     정합 ~15s. 큰 회전(>30°) 초기 오프셋은 거친 정합 미구현으로 범위 외.
6. 피킹 임계값·체이닝 각도·포즈 간격 옆 파란 ? 아이콘에 마우스를 올리면 도움말 팝업이 열린다.
7. 창은 VMS 공통 커스텀 크롬(WindowStyle=None + 자체 타이틀바/닫기 버튼), 기본 1536×864(FHD 80%).

## 그라인딩 모드 (스캔 점군 커버리지 경로)

CAD 없이 3D 스캔 점군에서 직접 가공 영역을 잡아 커버리지 경로와 공구 포즈를 만든다.
**OCCT 를 쓰지 않으므로** CAD 커널 라이선스 리스크가 용접 모드에만 국한된다.
명세: `docs/design/weldteach-grinding-scan-coverage-spec.md`.

1. 툴바 **공정 모드**에서 [그라인딩] 선택 → [점군 열기](.vpc/PLY/XYZ) 또는
   [합성 표면] 콤보(평면 / 30° 경사 / 원통 셸 / 사인 범프 / 구멍 패널) + [생성].
   점군을 넣으면 전처리(복셀 1mm → 통계적 이상치 제거 → PCA k=20 법선)가 자동 실행된다.
2. **영역 선택** — 뷰포트 드래그. 라쏘(올가미) / 브러시(궤적 반경) 중 선택,
   무수정=새 영역 · Shift=추가 · Ctrl=제거. 목록 순서가 곧 가공 순서다.
   깊이 밴드(mm)는 화면에서 겹쳐 보이는 뒷면이 함께 잡히는 것을 막는다.
3. **커버리지 생성** — 공구 직경 × (1 − 겹침률) = 스텝오버. 영역 점군의 PCA 주평면에
   높이맵을 만들고 스텝오버 간격 스캔라인을 배치한다(구멍·경계에서 세그먼트 자동 분할).
   - 간격은 주평면 등간격이 아니라 **표면 호길이 기준**이라 경사·곡면에서도 실제 간격이
     유지된다(보정 없으면 원통 40° 가장자리에서 1.10배까지 벌어짐).
   - 마진(mm)은 영역 경계에서 안쪽으로 띄우고, 지그재그는 홀수 라인을 역방향 왕복시킨다.
4. **공구 포즈** — 커버리지 생성 시 함께 계산된다. 리드각(기본 10°)은 공구를 진행 방향으로,
   틸트각은 진행 축 둘레로 기울인다. 패스 수 ≥2 면 패스마다 패스당 깊이만큼 법선 반대로
   파고든다. 뷰포트에 공구 축이 청록 화살선으로 표시된다.
5. **로봇 좌표 변환 (선택)** — 경로는 **카메라(스캔) 좌표계**에서 만들어지므로 CAD 정합이
   필요 없다. 로봇이 그대로 쓰려면 핸드-아이 캘리브레이션 결과 `T_cam2base` 를
   [행렬 불러오기]로 넣는다(캘리브레이션 자체는 외부 도구 소관). 허용 형식은 모두
   **행 우선(row-major), mm**:
   - JSON 2차원 배열 `[[r,r,r,tx],[r,r,r,ty],[r,r,r,tz],[0,0,0,1]]`
   - JSON 평탄 배열(숫자 16개 또는 12개 — 마지막 행 생략 가능)
   - `tCam2BaseRowMajor` 키를 가진 JSON — **내보낸 경로 파일을 그대로 다시 넣어도 읽힌다**
   - 공백/쉼표 구분 숫자 12·16개 텍스트

   불러올 때 강체 변환인지 검사한다(회전부 정규직교·행렬식 > 0·마지막 행 `0 0 0 1`) —
   스케일이 섞였거나 단위(m↔mm)가 틀리면 이유를 알려주고 거부한다.
6. **경로 내보내기 (JSON)** — 가공 순서대로 영역·파라미터·스캔라인·패스별 포즈를 저장.
   `T_cam2base` 가 입력돼 있으면 모든 포즈를 로봇 베이스 좌표계로 변환하고 행렬을 함께
   기록한다. 미입력이면 카메라 좌표계 그대로 저장하고 `frame` 필드에 그 사실을 적는다.

## 뷰포트 조작 (양 모드 공통)

| 동작 | 조작 |
|---|---|
| 회전 | 우클릭 드래그 |
| **이동(팬)** | **Shift + 우클릭 드래그** 또는 휠(가운데)클릭 드래그 |
| 확대/축소 | 휠 스크롤, Ctrl + 우클릭 드래그 |

좌클릭은 카메라에 배정하지 않는다 — 용접 모드는 엣지 피킹, 그라인딩 모드는 라쏘/브러시
영역 선택에 쓰기 때문. 제스처는 `MainWindow.xaml` 의 `HelixViewport3D` 에 명시 선언돼
있고(라이브러리 기본값에 의존하지 않음), 뷰포트 좌상단에 같은 내용이 상시 표시된다.

## 헤드리스 검증 · 진단 모드

`VMS.WeldTeach.exe --selftest` → `%TEMP%\weldteach_selftest.log`
- 용접: 샘플 생성→로드→위상→메싱→심 체이닝→이등분 벡터→포즈→ICP→GC 해머 3라운드 (`SELFTEST OK`)
- 그라인딩 `GRINDING M1~M6`: 전처리·법선 / 라쏘·브러시 / 커버리지 / 곡면·구멍·스텝오버 3D 보정 /
  리드·틸트 포즈·다층 패스·JSON / `.vpc` 파일을 거치는 전체 체인 스모크

GUI 진단 모드:
- `--open <step경로> [--pick <엣지Id>] [--capture <png경로>] [--stay]` — GUI 와 동일한 로드 경로
- `--weldcap <png>` — 용접 모드 샘플 시편 생성 → 캡처 (툴바 넘침 확인용)
- `--grindcap <png>` — 그라인딩 전환 → 합성 표면 → 중앙 라쏘 → 커버리지 생성 → 캡처
- `--switchcap <접두사>` — 모드/데이터 전환 잔상 회귀: 그라인딩+점군 → 용접+STEP →
  그라인딩 복귀 → 용접 재복귀 를 `_1~_4.png` 로 캡처
- `--analyze <step경로> [엣지Id]` → `%TEMP%\weldteach_analyze.log` (끝점 간격 분포·체이닝 덤프)

트레이스는 `%TEMP%\weldteach_diag.log`, 로드 실패 상세는 `%TEMP%\weldteach.log`.

## 기술 선택과 리스크

- **CAD 커널: NuGet `Occt.NET 7.9.0`** (OpenCASCADE 7.9 C++/CLI 래퍼, x64 전용).
  - **라이선스 리스크**: 패키지에 라이선스 명시가 없다(중국 개인/업체 배포, 기부 요청만 존재).
    PoC 용도로만 사용하고, **제품화 시에는 OCCT 원본(LGPL-2.1 + 예외) 직접 빌드 + 자체 C++/CLI 래퍼**
    (NativeVision 경험 활용) 또는 상용 Eyeshot 으로 교체할 것. `ICadKernelService` 인터페이스로 격리해 둠.
  - **배포 무게**: 네이티브 DLL 104개(≈230MB, ffmpeg/Qt 등 불필요 종속 포함). 제품화 시 자체 빌드로 축소.
  - **초기화 함정**: XS(STEP) 계열 DLL 은 이름 기반 동적 로드라 네이티브 폴더가 **프로세스 PATH** 에
    있어야 한다. `CadKernelService` 정적 생성자에서 처리(패키지 기본 `OcctConfiguration` 은 불충분).
  - **파이널라이저 결함 (치명)**: 래퍼의 GC 파이널라이저가 내부 참조(NoRelease) 객체까지 네이티브
    delete 를 호출해 **힙 손상(0xC0000374)·UI 행**이 발생한다 — 스택 덤프로 확인(2026-07-28).
    `OcctLifetime.Keep()` 으로 모든 OCCT 객체의 `DeleteOnFinalize` 를 꺼서 회피. 부작용으로
    로드당 소량(수백 KB~수 MB) 네이티브 누수 — PoC 허용, 자체 래퍼 교체 시 해소.
  - **벤더 홍보 팝업**: STEP 리더/라이터 생성 시 배포사(北京腾雪科技) 홍보 팝업
    (클래스 `Comet_PopupWindow`) 이 뜬다. 소유 스레드가 메시지를 펌프하지 않아 WM_CLOSE /
    ShowWindow / SetWindowPos 가 전부 무효(실측) — 소유 스레드와 무관하게 동작하는
    **DWM 클로킹**(`DwmSetWindowAttribute` + `DWMWA_CLOAK`, 자기 프로세스 창은 허용)으로
    화면에서 제거한다 (`VendorPopupSuppressor`, 0.1s 감시 스레드).
- 토치 법선은 **지점별 pcurve UV 평가** — 원통 등 곡면 심에서도 경로를 따라 방향이 회전한다
  (파이프 피팅 원형 심으로 검증, 2026-07-28). pcurve 가 없는 특수 면만 면 중심 법선으로 대체.
- **Helix LinesVisual3D 함정**: 보이는 상태에서 `Points.Add` 반복 시 점마다 라인 메쉬 전체를
  재생성해 O(N²) — 실파일(242엣지)에서 UI 가 14초+ 정지했다. 컬렉션을 채운 뒤
  **한 번에 교체 할당**할 것 (MainWindow 렌더 코드 참조).
- UI 는 VMS 본체 디자인 토큰(`Themes/` — Colors·Typography·Spacing·Controls)을 이식해
  다른 VMS 앱과 동일한 룩(Indigo/Slate 다크, ModernButton/Button.Subtle, 다크 DataGrid).
- 진행각(push/drag)·작업각 오프셋 파라미터, 로봇 벤더별 오일러 규약 변환은 명세 보강 후 구현.
