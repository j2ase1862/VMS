# VMS.WeldTeach — Claude Code Guidelines

루트 `CLAUDE.md`(MVVM·명명·DI 규약)를 그대로 상속한다. 이 문서는 **3D 기하 코드에만
추가로 적용되는 규약**이다. 상충 시 이 문서가 우선한다.

이 프로젝트는 로봇이 물리적으로 움직일 궤적을 생성한다. 판정 시스템(VMS 본체)과 달리
**출력이 틀리면 소재가 파손되거나 로봇이 충돌한다.** 아래 불변식은 스타일 권고가 아니라
안전 요구사항이다.

---

## 1. 좌표계·단위 규약 (전역)

| 항목 | 규약 |
|---|---|
| 좌표계 | 우수(right-handed) |
| 길이 단위 | **mm** — 예외 없음. m 단위 값은 경계에서 즉시 변환 |
| 각도 단위 | 내부 계산은 rad, **외부 인터페이스(JSON·UI·파라미터)는 deg** |
| 오일러 | **ZYX intrinsic, deg** — 다른 순서를 쓸 경우 반드시 필드로 선언 |
| 변환 행렬 | **열벡터 규약 (p′ = T·p)** |
| WPF `Matrix3D` | **행벡터 규약**이므로 경계에서 전치한다. 내부로 들여올 때·내보낼 때 각 1회, 중간에서 재전치 금지 |

`Matrix3D`를 다루는 코드는 그 변수가 행벡터 규약인지 열벡터 규약인지 **변수명 또는 주석에
명시**한다. `MatrixRows()`처럼 전치가 일어나는 지점에는 이유를 남긴다.

## 2. 강체변환 검증 의무

외부에서 들어오는 모든 변환 행렬(핸드-아이 `T_cam2base`, ICP 결과, 파일 로드)은
**사용 전에 강체성을 검증**한다. 검증 실패는 조용한 폴백이 아니라 **거부 + 사유 통지**다.

- 회전부 정규직교: ‖RᵀR − I‖∞ ≤ 1e-6
- det(R) > 0 (반사 변환 거부)
- 마지막 행 = (0, 0, 0, 1)
- 스케일 성분 없음 (각 열 노름 = 1 ± 1e-6)

단위 혼입(m ↔ mm)은 스케일 검사에서 잡힌다. 이미 `HandEyeMatrix`가 이 검사를 구현하고
있으므로, **새 경로에서도 그 함수를 우회하지 말 것.**

## 3. 표면·경로 생성 불변식

### 3.1 소재 바깥쪽 보장 (최우선)

> **생성된 모든 경로점과 포즈점은 소재 표면의 바깥쪽 반공간(+법선 방향)에 있어야 한다.
> 이 보장이 불가능한 셀·구간은 경로를 만들지 말고 제외한다.**

높이맵 셀이 상면과 하면을 동시에 포함하면(2.5D 위반) **평균 높이는 소재 내부**다.
위반 셀은 다음 중 하나로 처리한다. 조용히 통과시키는 것은 금지.

1. 마스크에서 제외 (기본)
2. 또는 평균이 아닌 **공구 쪽 극값(+e3 방향 `hMax`)** 사용

카운터를 증가시키고 결과 레코드에 담는 것은 **처리가 아니다.** 감지했으면 행동한다.

일반 원칙: **덜 깎는 실패(재작업)와 파고드는 실패(파손) 중, 항상 전자를 선택한다.**
불확실한 셀·경계·노이즈 구간은 모두 보수적으로 처리한다.

### 3.2 단계 간 비침습 원칙

> **파이프라인 하류 단계는 상류 단계의 출력을 수정하지 않는다.**

특히 곡면 피팅 모드(`UseSurfaceFit = true`)에서는 **높이·법선의 유일한 출처가 피팅
곡면**이다. 후처리 평활을 포함해 어떤 단계도 그 값을 사후 변경하지 않는다.
피팅으로 얻은 정밀도를 뒤 단계가 되돌리면 옵션의 존재 이유가 사라진다.

평활이 필요한 경우:
- 높이맵 모드에서만 적용
- **높이(h) 성분만** 평활한다. 위치 3성분을 함께 평균하면 볼록 구간에서 코드 단축
  (코너 커팅)이 생긴다
- 위치를 바꿨으면 **법선도 같은 규칙으로 갱신**한다. 위치와 법선의 불일치는 공구 자세
  오차로 직결된다

### 3.3 오프셋·다층 패스

다층 패스의 절입은 오프셋 곡면 생성이다. 오목 구간에서 누적 깊이가 국부 곡률반경을
넘으면 **오프셋 곡면이 접히고 경로가 자기교차**한다.

- 누적 절입 깊이 `d = (passCount − 1) × depthPerPassMm`
- 영역 내 최소 오목 곡률반경 `R_min = 1 / κ_max` (오목 방향만)
- **`d < R_min` 을 위반하면 패스 수를 자동 제한하고 사용자에게 통지**한다

`depthPerPassMm`의 기준축을 문서화한다. 현재 구현은 **표면 법선** 기준이므로, 공구축
기준 실효 깊이는 `d · cos(리드·틸트 합성각)`이다. 이 차이를 UI 툴팁과 JSON 주석에
명시하거나, 공구축 기준으로 전환한다. **암묵적으로 두지 않는다.**

### 3.4 알고리즘 비용 상한

보수적 처리(과커버 쪽 치우침)는 옳지만 **비용에 상한이 있어야 한다.**
밴드 신장률처럼 국부 최악값이 영역 전체에 전파되는 계산은 상한을 두고, 초과 시 조용히
받아들이지 말고 **사용자에게 영역 분할을 권고**한다.

## 4. 외부 인터페이스 자기 완결성

> **저장·전송되는 모든 파일은 자기 자신만으로 해석 가능해야 한다.**

경로 JSON을 처음 받는 제3자(로봇 포스트프로세서, 고객사 통합 담당)가 **소스 코드 없이**
아래를 알 수 있어야 한다.

| 필드 | 예 |
|---|---|
| `units` | `"mm"` |
| `frame` | `"robot_base"` / `"camera"` |
| `eulerConvention` | `"ZYX_intrinsic_deg"` |
| `toolAxis` | `"X"` — 포즈 프레임에서 공구축에 해당하는 축 |
| `travelAxis` | `"Z"` — 진행 방향 축 |
| `matrixConvention` | `"column_vector_row_major"` |
| `schemaVersion` | `"1.0"` |

`toolAxis`/`travelAxis`는 특히 중요하다. 현재 프레임은 X = 공구축, Z = 진행 방향인데
협동로봇 플랜지는 통상 Z가 어프로치 축이라 **정확히 어긋나 있다.** 이 매핑이 변환기
코드에만 암묵적으로 존재하면 로봇 기종 추가 시 반드시 사고가 난다.

스키마를 바꿀 때는 `schemaVersion`을 올리고 `CHANGELOG.md`에 남긴다.

## 5. 구현 전 필수 절차

새 기하 기능을 구현하기 전에, **먼저 아래 실패 케이스에서의 동작을 서술**한 뒤 착수한다.

1. **오버행** — 주평면에 단사 투영되지 않는 형상
2. **관통 구멍 테두리** — 마스크 경계 + 높이 불연속
3. **얇은 리브/벽** — 한 셀에 양면
4. **오목 곡면** — 오프셋 접힘, 공구 간섭
5. **영역 경계의 슬리버** — 극소 세그먼트
6. **점 밀도 불균일** — 스캔 각도에 따른 빈 셀
7. **법선 뒤집힘** — 시점 정렬 실패 구간

"해당 없음"이라는 답도 유효하지만, **답을 건너뛰는 것은 안 된다.**

## 6. 테스트 요구사항

`VMS.WeldTeach.Tests` (xUnit)에 아래를 유지한다. `--selftest`(엔드투엔드 스모크)는
이를 대체하지 않는다.

- **수치 회귀** — 합성 표면(평면 / 30° 경사 / 원통 셸 / 사인 범프 / 구멍 패널)별로
  라인 수·커버 면적·표면 편차·법선 오차를 수치로 단언한다
- **불변식 테스트** — §3.1(바깥쪽 보장), §3.3(자기교차)은 반드시 테스트로 강제한다
- **옵션 조합 회귀** — 기능을 하나 추가할 때마다 **기존 옵션과의 조합**을 검증한다.
  단계별로 각각 통과하는 것과 함께 켰을 때 통과하는 것은 다르다
- **스키마 테스트** — §4의 필수 필드 존재를 단언한다

## 7. 이 프로젝트에서 특히 조심할 것

- **OCCT는 용접 모드 전용이다.** 그라인딩 경로에 CAD 커널 의존을 도입하지 않는다.
  라이선스 리스크가 용접 모드에 격리된 현재 구조를 깨지 말 것
- **`Occt.NET` 객체는 `OcctLifetime.Keep()`을 거친다.** 파이널라이저가 힙을 손상시킨다
  (0xC0000374, 2026-07-28 스택 덤프 확인)
- **Helix `LinesVisual3D`에 `Points.Add`를 반복하지 않는다.** O(N²) — 컬렉션을 채운 뒤
  한 번에 교체 할당한다
