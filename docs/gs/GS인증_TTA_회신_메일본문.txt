구자경 수석님, 안녕하세요.

검토해 주셔서 감사합니다. 문의하신 5개 항목에 대해 아래와 같이 회신드리며, 6번에 생산 관리 웹(BODA.VMS.Web)의 시험범위 확인을 함께 요청드립니다.

시험 대상 버전은 BODA VMS v1.47.3(2026-10-29 공개)으로 정했습니다. 아래 시험자료는 모두 이 버전으로 기대 결과를 산출 · 재확인한 뒤 동결했습니다. 착수 전 결함 수정 등으로 버전이 바뀌면, 시험자료를 새 버전으로 다시 대조해 확정 버전과 함께 알려 드리겠습니다.


■ 1. AI 학습 기능 및 MLOps 시험범위 — 둘 다 제외 요청

이해하신 내용이 맞습니다. AI 학습 · 재학습 기능과 BODA.VMS.MLOps 모두 이번 시험범위에서 제외를 요청드립니다.

- AI 학습 기능: v1.44.0 부터 VMS 제품에서 학습 도구 자체를 제거했습니다. 모델 학습은 별도 플랫폼(BODA.VMS.MLOps)에서만 하며, 라인에 배포되는 VMS 는 학습된 모델로 검사만 합니다. 따라서 별도의 인증 전용 빌드 없이, 공개 배포 설치 파일(VMS-1.47.3.msi)이 그대로 시험 제출본입니다.
  · 설치 폴더에 학습 프로그램(VMS.DeepLearning.exe)과 학습 스크립트(scripts 폴더)가 없고,
  · 설치 마법사 · VisionSetup 메뉴에도 학습 관련 항목이 없습니다.
  설치 후 위 두 가지로 범위 제외를 바로 확인하실 수 있습니다.
- BODA.VMS.MLOps(웹 기반 학습 플랫폼): 별도 서버에 설치되는 선택 구성 요소로 제품 설치 파일에 들어 있지 않으며, 사용자 매뉴얼 9장 도입부에도 "인증 범위 밖의 선택 구성 요소"로 명기되어 있습니다.
- 제품 본체에는 MLOps 서버에서 모델을 내려받는 연동 설정(서버 주소 · 라인 토큰)이 있으나, 시험 환경에서는 해당 설정을 비운 상태로 제공하므로 관련 기능이 비활성으로 고정됩니다. 딥러닝 검사 도구는 로컬 ONNX 파일만으로 동작합니다.

다만 학습이 끝난 모델을 불러와 추론하는 검사 도구(Detection · Segmentation · RF-DETR-seg · Classify · Anomaly · OCR · Ensemble)는 검사 런타임의 일부이므로 범위에 포함됩니다. 관련 시험자료는 4번에 정리했습니다.


■ 2. 3D 관련 기능 및 시험방법

말씀하신 대로 3D 카메라 없이 저장된 점군 파일(.vpc)을 이용해 시험할 예정입니다.

이 방식은 시험을 위한 임시 우회가 아니라, 제품에 정식으로 내장된 오프라인 작업 경로입니다. 카메라가 없는 사무실에서 저장된 점군으로 레시피를 만들고 검증하는 것이 제품의 표준 작업 방식이며, 사용자 매뉴얼에도 절차가 기재되어 있습니다.

[시험 절차]
1) VisionSetup 실행 → 당사 제공 3D 레시피 불러오기(Import)
2) 상단 메뉴 [3D] › [Load 3D Data] 로 당사 제공 .vpc 파일 로드(레시피에 저장된 높이 범위로 높이 맵이 자동 생성됩니다)
3) [Run All] → 산출 측정값 · 판정 결과를 당사 제공 기대 결과표와 대조

[시험 가능한 기능 범위] (모두 저장 점군 입력으로 동작)
- 점군 필터(VoxelGrid 다운샘플 · 이상점 제거): 처리 후 점 개수
- 높이 맵 생성 · 높이 구간 추출(Height Slicer): 지정 높이 구간의 추출 영역
- 점군 자르기(Mask Crop): 높이 구간 · 지정 영역 안의 점만 남긴 점 개수
- 평면 피팅(Plane Fit): 평면 방정식 · 평탄도 · 평탄도 판정
- 점군 정합(Registration, ICP 6DOF): 정합 변환 · 정합 오차 · 정합 신뢰도 판정
- 기준 점군 대비 편차(Deviation): 편차(mm) · 공차 초과 영역 · 판정
- 클러스터(3D 객체 검출): 덩어리 개수 · 치수 · 개수/치수 판정
- 직선 피팅(Line Fit): 직선 방향 · 길이 · 직진도 판정
- 3D 기하 연산(Geometry 3D): 점 · 직선 · 평면 간 거리 / 각도 · 판정
- 점군 저장 · 불러오기: 저장 후 재로드 시 동일 점군

[시험자료] 실촬영 점군 8개(정상 7 · 허용 각도 밖 1) + 실촬영본을 가공한 불량 3개(높이 · 길이 결손 · 비틀림) + 기준 점군 1개, 그리고 직선 피팅용으로 참값(길이 · 굽음)을 알고 있는 합성 점군 4개입니다.

[시험 대상에서 제외를 요청드리는 3D 항목] (실장비가 반드시 필요)
- 3D 카메라 촬영 파라미터 설정 및 실촬영(노출 · 점군 후처리 프리셋 등)
- 핸드아이 캘리브레이션 및 로봇 멀티뷰 스캔 — 3D 카메라와 로봇이 동시에 필요(3번 참조)

참고로, 당사가 제공하는 저장 점군에는 촬영 카메라의 내부 파라미터가 함께 저장되어 있어, 3D 객체 치수(길이 · 폭)는 저장 점군만으로 mm 로 자동 환산됩니다. 높이(Z) 방향 측정은 항상 mm 입니다. 정합 · 편차 · 평면 피팅의 가로 · 세로 방향 값은 점군 좌표(카메라 화소) 기준으로 계산되며, 당사가 같은 기준으로 산출한 기대값을 함께 제공합니다.


■ 3. 외부 장비 연동 범위

[시험 대상에 포함 — 2D 산업용 카메라 · 디지털 IO 보드] (모두 당사 반입)
- 2D 산업용 카메라(GigE Vision): Basler acA2440-20gc(컬러 · 500만 화소) 1대
- 렌즈: 16mm F1.4(2/3인치) 1조
- 조명: IFS-RFD-126*M30.5R-VW 1조
- 디지털 IO 보드: ADLink PCI-7432(DASK x64 드라이버) 1매
- 검사 샘플 부품: 당사 생산 부품 수 점

- 카메라 제조사 런타임(Basler pylon Runtime)과 IO 보드 드라이버(ADLink DASK x64)는 당사가 시험 PC 에 설치합니다.
- 카메라 연동으로 확인 가능한 기능: 카메라 검색 · 연결 · 단일 촬영 · 연속 라이브 · 노출 등 파라미터 설정 · 하드웨어 트리거 · AUTO RUN 연속 검사. 반입 카메라가 컬러 기종이라 색상 검사 기능도 실촬영으로 확인 가능합니다.
- IO 보드 연동으로 확인 가능한 기능: 외부 트리거 입력(DI)에 의한 검사 개시, 판정 결과 출력(DO), 검사 시퀀스 운전(트리거 대기 → 촬영 → 판정 → 결과 출력(당사 반입 경광등 점등)).
- IO 보드는 PCI 슬롯에 장착하는 카드이므로, 시험 PC 를 당사가 지참하는 것을 전제로 기재했습니다. 시험기관 PC 를 사용해야 한다면 알려 주시기 바랍니다. 그 경우 IO 보드 실물 시험은 어려워, 검사 시퀀스 운전은 PLC 시뮬레이션 모드로 확인하는 방안을 협의드리겠습니다.

[시험 대상에서 제외를 요청드리는 연동]
- 3D 카메라(Mech-Mind Mech-Eye): 시험 기간 중 장비 확보 불가 — 저장 점군으로 대체(2번)
- 로봇(Universal Robots · Doosan · Jaka · ABB · Fanuc): 3D 카메라와 함께 쓰는 멀티뷰 스캔 · 핸드아이 캘리브레이션 전용 기능이라, 3D 카메라 제외 시 단독으로 시험할 대상이 없음
- PLC(Mitsubishi MC · Siemens S7 · LS XGT · Omron FINS · Modbus TCP): 시험 기간 중 실장비 확보가 어려움 — 내장 시뮬레이션 모드로 시험 희망(아래 참조)

PLC 연동에 대해 — 제품에는 내장 시뮬레이션 모드가 있어, 실장비 없이 PLC 신호 입출력 화면과 통신 동작을 확인할 수 있습니다. 사전 체크리스트 35번에 기재한 시뮬레이터가 이것입니다. 검사 시퀀스 운전(트리거 대기 → 촬영 → 판정 → 결과 출력) 자체는 위에서 반입하는 IO 보드 실물로 시험 가능하므로, PLC 는 통신 연동 확인만 시뮬레이션 모드로 진행하고자 합니다.

다만 시뮬레이션 모드로 확인하는 방식이 인증 시험으로 인정되지 않아 PLC 연동을 시험범위에서 제외해야 한다면 알려 주시기 바랍니다.


■ 4. 시험자료 — 도구별 레시피 · 이미지 · 기대 결과표

VisionSetup 도구 팔레트의 검사 도구 40종 전부에 대해, 도구마다 시연용 레시피 + 입력 이미지(또는 점군) + 기대 결과표를 한 묶음으로 준비했습니다. 기대 결과는 사람이 추정한 값이 아니라 시험 대상 버전(v1.47.3)으로 레시피를 실제로 실행해 확인한 값이며, 동결 직전에 같은 버전으로 다시 실행해 전부 일치함을 확인했습니다.

[4-1. 딥러닝 추론 도구]
- 객체 검출(Detection): 모델 1개(D-FINE 기반, 2클래스) · 이미지 12장(검출 대상 있음 10 · 없음 2) · 기대 결과: 이미지별 개수, 객체마다 클래스 · 신뢰도 · 박스 + 정답표
- 인스턴스 분할(RF-DETR-seg): 모델 1개(RF-DETR-seg 기반, 2클래스) · 이미지 10장 · 기대 결과: 이미지별 개수 · 클래스 · 신뢰도 · 박스 · 마스크 화소 수 + 정답표
- 시맨틱 분할(Segmentation): 모델 1개(DeepLabV3 기반, 배경 + 2클래스) · 이미지 6장 · 기대 결과: 이미지별 클래스 화소 수 · 비율
- 분류(Classify): 모델 1개(ResNet 기반, 4클래스 — 양품 1 · 불량 3) · 이미지 22장 · 기대 결과: 이미지별 클래스 · 신뢰도 · 판정
- 이상 탐지(Anomaly): 모델 1개(PatchCore 기반) · 이미지 52장(시험용 정상 10 · 불량 12 + 임계값 자동 산출용 정상 30) · 기대 결과: 이미지별 이상 점수 · 판정, 산출 임계값
- 문자 인식(OCR, ONNX 엔진): 제품 설치본에 동봉된 인식 모델 사용(별도 제공 없음) · 이미지 10장 · 기대 결과: 이미지별 인식 문자열 · 신뢰도 + 정답표
- 앙상블 판정(Ensemble): 위 검출 · 이상 탐지 모델 재사용 · 이미지 6장 · 기대 결과: 판정 방식 4종(AND · OR · 가중합 · 합의)별 기대 판정
- 결함 허용성 확인용: 손상 ONNX 1 · 규약 불일치 ONNX 1 · 0바이트 파일 1 · 이미지 2장 · 기대 결과: 해당 도구만 "모델 로드 실패"로 격리되고 같은 스텝의 다른 도구 · 다음 이미지 · 다음 스텝은 중단 없이 계속
→ 합계: 학습된 ONNX 모델 5개 + 결함 확인용 3개 · 이미지 120장

[4-2. 규칙 기반(비 AI) 검사 도구]
판정(OK/NG)을 하는 기능마다 정상과 불량을 함께 넣고, 도구의 특징 기능(회전 · 다중 인스턴스 · 가림 등)마다 장면을 하나씩 두었습니다.
- 영상 전처리 · 변환 7종(Blur · Morphology · Image Enhance · Grayscale · Threshold · Edge Detection · Histogram): 2장 — 기준 1 · 대비 낮은 것 1
- Polar Unwrap(원형 → 띠 펼침): 4장 — 원형으로 인쇄된 문자 띠를 펼쳐 문자 인식. 정상 2(기준 · 35° 회전) · 다른 로트 1 · 글자 인쇄 누락 1
- Feature Match · Shape Match(패턴 매칭): 8장 — 학습용(정위치) · 회전 · 180° 회전 · 이동 · 크기 변화 · 다중 인스턴스 · 일부 가림 · 대상 없음
- Match Align · Multi-Step Align(정렬): 4장 · 8장 — 기준 · XY 이동 · 회전 · 허용 범위 밖(Multi-Step 은 장면마다 시야 2장)
- Blob(입자 분석): 5장 — 개수 정상 · 개수 초과 · 개수 부족 · 면적 미달 · 형상 불량
- Caliper · Line Fit · Circle Fit · Geometry(치수 측정): 5장 — 폭 · 구멍 중심 거리 · 각도. 공차 내 2 · 항목별 공차 밖 3
- Image Rectify(왜곡 보정 후 측정): 5장 — 위 치수 측정 이미지를 보정 후 다시 측정
- Result(판정 종합): 5장 — 위 치수 측정 이미지. 모두 합격 / 하나라도 합격 두 방식
- Code Reader(DataMatrix · GS1): 4장 — 정상 2 · 일부 손상(판독 성공) 1 · 판독 불가 1
- OCR(문자 인식, Tesseract 엔진): 4장 — 정상 2 · 기대 문자열 불일치 1 · 인쇄 불량 1
- OCV(문자 검증): 5장 — 기준 학습 1 · 일치 2(이동 · 회전 포함) · 결자 1 · 잉크 얼룩 1
- Color Match · Color Extract(색상 검사): 4장 · 4장 — 기준색 정상 2 · 색상 상이 1 · 탈색 1
- Photometric Stereo(조명 4방향 표면 결함): 8장 — 정상 장면 · 결함(긁힘 · 찍힘) 장면 각각 조명 4방향
- 카메라 캘리브레이션: 35장 — 체커보드 18 · 원형 그리드 17. 실물 타겟 보드를 반입하므로 라이브 촬영이 기본이고 저장본은 결과 대조용
- 좌표 보정(Fixture) · 배치 테스트: 위 이미지를 재사용(별도 준비 없음)
→ 합계 이미지 110장. 딥러닝 자료와 합치면 이미지 230장 · 점군 16개(2번)입니다.

- Polar Unwrap · Photometric Stereo 는 원리를 정확히 재현한 합성 이미지로 시험자료를 구성했습니다. Polar Unwrap 은 원형 라벨 둘레에 로트 번호를 인쇄한 장면(2448 × 2048), Photometric Stereo 는 같은 장면을 조명 방위 0 · 90 · 180 · 270°(고도 45°)로 비춘 4장 한 벌(1024 × 768 흑백)이며, 합성할 때 정한 참값(인식할 로트 문자열 · 결함 종류)을 기대 결과와 함께 제공합니다. Photometric Stereo 는 조명 방향 제어 장비를 반입하지 않으므로 저장 이미지로 시험합니다.
- 그 밖의 이미지는 반입 카메라의 실제 촬영 해상도(2448 × 2048) PNG 이며(일부 불량 장면은 실촬영본을 가공), 개인정보는 포함되지 않습니다.
- 실물 부품 라이브 촬영과 병행할 예정입니다. 저장 이미지는 기대 결과와의 일치를, 라이브 촬영은 실제 장비 연동 동작(카메라 파라미터 · 하드웨어 트리거 · AUTO RUN 연속 운전)을 각각 확인하는 용도입니다.

[4-3. 제공 형태]
- 전체를 압축 파일 1개(GS_TestData_v1.47.3.zip, 약 1.9GB)와 그 SHA-256 해시로 제공합니다. 압축 안에는 파일별 SHA-256 목록(모델 파일 포함)이 들어 있어, 시험 중 자료가 바뀌지 않았음을 확인하실 수 있습니다.
- 시험 PC 의 D:\ 에 풀어 D:\GS_TestData 로 두시면 됩니다(레시피에 모델 · 기준 점군 경로가 이 위치로 적혀 있습니다).
- 맨 위 README.md 에 도구 → 묶음 색인이 있고, 묶음마다 README(확인 순서 · 도구 설정값 · 장면 설명) · 레시피 · 이미지 · 기대 결과표가 있습니다. 판정 기준값이 레시피 안에 들어 있어, 레시피를 불러온 뒤 이미지를 넣으면 기대 결과가 재현됩니다. 이미지 폴더를 배치 테스트에 지정하면 한 번에 결과표(CSV)를 받아 대조하실 수도 있습니다.
- 모델은 전부 Apache-2.0 / BSD-3-Clause 계열 공개 백본을 당사 샘플로 미세조정한 것으로, 배포 제약이 없습니다. 모델별 출처 · 라이선스 명세를 첨부합니다(「시험용 딥러닝 모델 출처 · 라이선스 명세」).

[참고 사항 두 가지]
1) 추론은 CPU 만으로 결정적으로 재현됩니다(GPU 가 있으면 가속될 뿐, 없어도 동작). 같은 이미지 · 같은 설정이면 항상 같은 결과가 나오므로 기대 결과표와 1:1 대조가 가능합니다.

■ 5. 인앱 업데이트 기능 — 범위 포함 요청

이번 시험범위에 포함을 요청드립니다. 시험 방법과 필요한 환경은 다음과 같습니다.

[시험 방법] 제품의 업데이트 기능은 당사 공개 배포 저장소(GitHub Releases)의 최신 릴리스를 조회하는 방식입니다. 이미 공개되어 있는 직전 버전(v1.47.3 바로 이전의 공개 버전)을 시험 PC 에 설치한 뒤 [업데이트 확인] → 다운로드 → SHA-256 무결성 검증 → 설치를 실행하면, 시험 대상 버전으로 올라가는 전 과정을 그대로 확인하실 수 있습니다. 시험을 위해 별도로 만든 임시 배포본이 아니라 실제 고객에게 나가는 배포 경로 그대로이며, 버전 확인 · 다운로드 · 무결성 검증 · 설치 · 재시작까지 자동으로 진행됩니다. 1번에서 말씀드린 대로 공개 배포본이 곧 시험 제출본이므로, 업데이트 후 설치된 구성도 제출본과 같습니다.

[필요한 환경]
- 시험 PC 의 외부 인터넷 접속 — api.github.com(버전 조회)과 objects.githubusercontent.com(설치 파일 다운로드) 2개 호스트. 내려받는 설치 파일은 약 390MB 입니다.
- 시험 PC 의 인터넷 접속은 당사가 무선랜 동글을 지참해 시험기관 무선망에 연결하는 방식을 희망합니다. 시험기관 망 사용이 어려우면 알려 주시기 바랍니다.
- 이 기능을 제외한 모든 검사 기능은 인터넷 없이(폐쇄망) 동작합니다.

시험 기간 중에는 공개 배포를 중지해, 인앱 업데이트의 도착 버전이 시험 대상 버전에서 바뀌지 않도록 하겠습니다.


■ 6. 생산 관리 웹(BODA.VMS.Web) — 시험범위 포함 및 제품 구성 확인 요청

VMS 와 함께 쓰는 생산 관리 웹(BODA.VMS.Web v1.11.0)도 이번 시험범위에 포함을 요청드립니다.

- 같은 설치 파일에 들어 있습니다. VMS-1.47.3.msi 설치 마법사의 "설치 구성 선택" 화면에서 "Web 서버 포함"을 고르면 시험 PC 에 함께 설치되고, 시스템 설정 마법사에서 관리자 계정을 만들면 브라우저로 http://<시험 PC>:5292 에 접속해 사용하실 수 있습니다. 시험 PC 1대로 VMS 와 웹을 함께 시험할 수 있습니다.
- 주요 기능: 대시보드(생산 · 품질 지표) · 작업지시 · 생산 이력 · 검사 이미지 조회 · 알람 / 안돈 보드 · 불량 코드 · 감사 로그 · 품질 보고서(PDF) · 사용자 가입 승인 · 비밀번호 변경. VMS 의 검사 결과가 웹으로 올라가는 연동도 함께 확인하실 수 있습니다.
- 웹을 쓰지 않는 단독 모드(Web 서버 주소를 비움)로도 VMS 는 모든 검사 기능이 동작하며, 이 경우 검사 이력은 PC 안에만 남습니다.

[확인 요청] 당사는 VMS(검사 런타임 · 비전 설정 · 시스템 설정)와 BODA.VMS.Web 을 하나의 제품으로 시험받기를 희망합니다. 제품 설명서의 적용 범위와 사용자 매뉴얼(8장)도 이 구성으로 작성했습니다. 웹을 별도 제품으로 보셔야 하거나 시험 수수료 산정이 달라진다면 알려 주시기 바랍니다.
