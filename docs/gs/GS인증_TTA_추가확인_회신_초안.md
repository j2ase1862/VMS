## 1. AI 학습 기능 및 MLOps 시험범위 — 둘 다 제외 요청

이해하신 내용이 맞습니다. **AI 학습 · 재학습 기능과 BODA.VMS.MLOps 모두 이번 시험범위에서 제외**를 요청드립니다.

- **AI 학습 기능**: VMS 제품에는 **학습 기능이 들어 있지 않습니다**. 모델 학습은 별도 플랫폼(BODA.VMS.MLOps)에서만 하며, 라인에 배포되는 VMS 는 학습된 모델로 검사만 합니다. 따라서 **공개 배포 설치 파일(`VMS-1.47.3.msi`)이 그대로 시험 제출본**입니다.
  - 설치 폴더에 학습 프로그램(`VMS.DeepLearning.exe`)과 학습 스크립트(`scripts\`)가 없고,
  - 설치 마법사 · VisionSetup 메뉴에도 학습 관련 항목이 없습니다.

  설치 후 위 두 가지로 범위 제외를 바로 확인하실 수 있습니다.
- **BODA.VMS.MLOps** (웹 기반 학습 플랫폼): 별도 서버에 설치되는 선택 구성 요소로 제품 설치 파일에 들어 있지 않으며, 사용자 매뉴얼 9장 도입부에도 "인증 범위 밖의 선택 구성 요소"로 명기되어 있습니다.
- 제품 본체에는 MLOps 서버에서 모델을 내려받는 연동 설정(서버 주소 · 라인 토큰)이 있으나, **시험 환경에서는 해당 설정을 비운 상태로 제공**하므로 관련 기능이 비활성으로 고정됩니다. 딥러닝 검사 도구는 로컬 ONNX 파일만으로 동작합니다.

다만 **학습이 끝난 모델을 불러와 추론하는 검사 도구(Detection · Segmentation · RF-DETR-seg · Classify · Anomaly · OCR · Ensemble)는 검사 런타임의 일부이므로 범위에 포함**됩니다. 관련 시험자료는 4번에 정리했습니다.

## 2. 3D 관련 기능 및 시험방법

말씀하신 대로 **3D 카메라 없이 저장된 점군 파일(.vpc)을 이용해 시험**할 예정입니다.

이 방식은 시험을 위한 임시 우회가 아니라, **제품에 정식으로 내장된 오프라인 작업 경로**입니다. 카메라가 없는 사무실에서 저장된 점군으로 레시피를 만들고 검증하는 것이 제품의 표준 작업 방식이며, 사용자 매뉴얼에도 절차가 기재되어 있습니다.

**시험 절차**
1. VisionSetup 실행 → 당사 제공 3D 레시피 불러오기(Import)
2. 상단 메뉴 [3D] › [Load 3D Data] 로 당사 제공 `.vpc` 파일 로드 (레시피에 저장된 높이 범위로 높이 맵이 자동 생성됩니다)
3. [Run All] → 산출 측정값 · 판정 결과를 당사 제공 기대 결과표와 대조

**시험 가능한 기능 범위** (모두 저장 점군 입력으로 동작)

| 기능 | 확인 내용 |
|---|---|
| 점군 필터 (VoxelGrid 다운샘플 · 이상점 제거) | 처리 후 점 개수 |
| 높이 맵 생성 · 높이 구간 추출 (Height Slicer) | 지정 높이 구간의 추출 영역 |
| 점군 자르기 (Mask Crop) | 높이 구간 · 지정 영역 안의 점만 남긴 점 개수 |
| 평면 피팅 (Plane Fit) | 평면 방정식 · 평탄도 · 평탄도 판정 |
| 점군 정합 (Registration, ICP 6DOF) | 정합 변환 · 정합 오차 · 정합 신뢰도 판정 |
| 기준 점군 대비 편차 (Deviation) | 편차(mm) · 공차 초과 영역 · 판정 |
| 클러스터 (3D 객체 검출) | 덩어리 개수 · 치수 · 개수/치수 판정 |
| 직선 피팅 (Line Fit) | 직선 방향 · 길이 · 직진도 판정 |
| 3D 기하 연산 (Geometry 3D) | 점 · 직선 · 평면 간 거리 / 각도 · 판정 |
| 점군 저장 · 불러오기 | 저장 후 재로드 시 동일 점군 |

**시험자료**: 실촬영 점군 8 개(정상 7 · 허용 각도 밖 1) + 실촬영본을 가공한 불량 3 개(높이 · 길이 결손 · 비틀림) + 기준 점군 1 개, 그리고 직선 피팅용으로 참값(길이 · 굽음)을 알고 있는 합성 점군 4 개입니다.

**시험 대상에서 제외를 요청드리는 3D 항목** (실장비가 반드시 필요)

- 3D 카메라 촬영 파라미터 설정 및 실촬영 (노출 · 점군 후처리 프리셋 등)
- 핸드아이 캘리브레이션 및 로봇 멀티뷰 스캔 — 3D 카메라와 로봇이 동시에 필요 (3번 참조)

**참고**: 당사가 제공하는 저장 점군에는 촬영 카메라의 내부 파라미터가 함께 저장되어 있어, 3D 객체 치수(길이 · 폭)는 저장 점군만으로 mm 로 자동 환산됩니다. 높이(Z) 방향 측정은 항상 mm 입니다. 정합 · 편차 · 평면 피팅의 가로 · 세로 방향 값은 점군 좌표(카메라 화소) 기준으로 계산되며, **당사가 같은 기준으로 산출한 기대값을 함께 제공**합니다.

## 3. 외부 장비 연동 범위

**시험 대상에 포함 — 2D 산업용 카메라 · 디지털 IO 보드**

| 구분 | 제조사 · 모델명 | 수량 | 준비 |
|---|---|---|---|
| 2D 산업용 카메라 (GigE Vision) | Basler acA2440-20gc (컬러 · 500 만 화소) | 1 대 | 당사 반입 |
| 렌즈 | 16mm F1.4 (2/3인치) | 1 조 | 당사 반입 |
| 조명 | IFS-RFD-126*M30.5R-VW | 1 조 | 당사 반입 |
| 디지털 IO 보드 | ADLink PCI-7432 (DASK x64 드라이버) | 1 매 | 당사 반입 |
| 검사 샘플 부품 | 당사 생산 부품 | 수 점 | 당사 반입 |

- 카메라 제조사 런타임(Basler pylon Runtime)과 IO 보드 드라이버(ADLink DASK x64)는 당사가 시험 PC 에 설치합니다.
- **카메라 연동**으로 확인 가능한 기능: 카메라 검색 · 연결 · 단일 촬영 · 연속 라이브 · 노출 등 파라미터 설정 · 하드웨어 트리거 · AUTO RUN 연속 검사. 반입 카메라가 컬러 기종이라 색상 검사 기능도 실촬영으로 확인 가능합니다.
- **IO 보드 연동**으로 확인 가능한 기능: 외부 트리거 입력(DI)에 의한 검사 개시, 판정 결과 출력(DO), 검사 시퀀스 운전(트리거 대기 → 촬영 → 판정 → 결과 출력(당사 반입 경광등 점등)).
- IO 보드는 PCI 슬롯에 장착하는 카드이므로, **시험 PC 를 당사가 지참하는 것을 전제**로 기재했습니다. 시험기관 PC 를 사용해야 한다면 알려 주시기 바랍니다. 그 경우 IO 보드 실물 시험은 어려워, 검사 시퀀스 운전은 PLC 시뮬레이션 모드로 확인하는 방안을 협의드리겠습니다.

**시험 대상에서 제외를 요청드리는 연동**

| 장비 | 제외 사유 |
|---|---|
| 3D 카메라 (Mech-Mind Mech-Eye) | 시험 기간 중 장비 확보 불가 — 저장 점군으로 대체 (2번) |
| 로봇 (Universal Robots · Doosan · Jaka · ABB · Fanuc) | 3D 카메라와 함께 쓰는 멀티뷰 스캔 · 핸드아이 캘리브레이션 전용 기능이라, 3D 카메라 제외 시 단독으로 시험할 대상이 없음 |
| PLC (Mitsubishi MC · Siemens S7 · LS XGT · Omron FINS · Modbus TCP) | 시험 기간 중 실장비 확보가 어려움 — 내장 시뮬레이션 모드로 시험 희망 (아래 참조) |

**PLC 연동에 대해** — 제품에는 **내장 시뮬레이션 모드**가 있어, 실장비 없이 PLC 신호 입출력 화면과 통신 동작을 확인할 수 있습니다. 사전 체크리스트 35번에 기재한 시뮬레이터가 이것입니다. 검사 시퀀스 운전(트리거 대기 → 촬영 → 판정 → 결과 출력) 자체는 위에서 반입하는 **IO 보드 실물로 시험 가능**하므로, PLC 는 통신 연동 확인만 시뮬레이션 모드로 진행하고자 합니다.

다만 시뮬레이션 모드로 확인하는 방식이 인증 시험으로 인정되지 않아 PLC 연동을 시험범위에서 제외해야 한다면 알려 주시기 바랍니다.

## 4. 시험자료 — 도구별 레시피 · 이미지 · 기대 결과표

VisionSetup 도구 팔레트의 **검사 도구 40 종 전부**에 대해, 도구마다 **시연용 레시피 + 입력 이미지(또는 점군) + 기대 결과표**를 한 묶음으로 준비했습니다. 기대 결과는 사람이 추정한 값이 아니라 **시험 대상 버전(v1.47.3)으로 레시피를 실제로 실행해 확인한 값**이며, 동결 직전에 같은 버전으로 다시 실행해 전부 일치함을 확인했습니다.

### 4-1. 딥러닝 추론 도구

| 기능 (도구) | 모델 (ONNX) | 입력 이미지 | 기대 결과 자료 |

**합계: 학습된 ONNX 모델 5 개 + 결함 확인용 3 개 · 이미지 120 장**

**이번 시험범위에 포함**을 요청드립니다. 시험 방법과 필요한 환경은 다음과 같습니다.

**시험 방법** — 제품의 업데이트 기능은 당사 공개 배포 저장소(GitHub Releases)의 최신 릴리스를 조회하는 방식입니다. 이미 공개되어 있는 **직전 버전(v1.47.3 바로 이전의 공개 버전)을 시험 PC 에 설치한 뒤 [업데이트 확인] → 다운로드 → SHA-256 무결성 검증 → 설치**를 실행하면, **시험 대상 버전으로 올라가는 전 과정**을 그대로 확인하실 수 있습니다. 시험을 위해 별도로 만든 임시 배포본이 아니라 실제 고객에게 나가는 배포 경로 그대로이며, 버전 확인 · 다운로드 · 무결성 검증 · 설치 · 재시작까지 자동으로 진행됩니다. 1번에서 말씀드린 대로 공개 배포본이 곧 시험 제출본이므로, 업데이트 후 설치된 구성도 제출본과 같습니다.

**필요한 환경**

- 시험 PC 의 외부 인터넷 접속 — `api.github.com`(버전 조회), `github.com` · `release-assets.githubusercontent.com`(설치 파일 다운로드) 3개 호스트. 내려받는 설치 파일은 약 390MB 입니다.

- 이 기능을 제외한 모든 검사 기능은 인터넷 없이(폐쇄망) 동작합니다.

**시험 기간 중에는 공개 배포를 중지**해, 인앱 업데이트의 도착 버전이 시험 대상 버전에서 바뀌지 않도록 하겠습니다.
