1. 시스템 개요

BODA VMS 는 산업용 카메라로 제품을 촬영해 양품/불량을 판정하는 머신 비전 검사 시스템입니다. 검사를 실제로 수행하는 검사 라인 PC, 여러 라인의 생산 실적과 품질을 한곳에서 관리하는 생산 관리 서버(BODA.VMS.Web), 그리고 딥러닝 검사 모델을 만들고 배포하는 ◆AI 학습 플랫폼(BODA.VMS.MLOps)으로 구성됩니다. 이 매뉴얼은 설치 담당자, 검사 레시피를 만드는 엔지니어, 현장 작업자, 관리자가 각자 필요한 장을 찾아 볼 수 있도록 시스템 구성 → 설치 → 프로그램별 조작 → 검사 설정 → 웹 관리 → 유지보수 순서로 되어 있습니다.

1.1 시스템 구성

검사 라인 PC

라인마다 PC 1대를 두고, 카메라 · IO 보드(◆PLC) · 필요 시 ◆로봇을 연결합니다. 이 PC 에는 다음 프로그램이 함께 설치됩니다.

프로그램사용자역할
VMS (검사 운전)현장 작업자 · 반장 매일 쓰는 메인 화면입니다. 작업자 로그인 → 작업지시 선택 → [AUTO RUN] 으로 연속 검사를 돌리고, 판정 결과·수량·NG 이력을 보여 주며 검사 결과를 서버에 올립니다. IO 보드(◆PLC)와 주고받는 트리거·판정 신호(시퀀스)도 이 프로그램이 처리합니다.
VMS.VisionSetup (레시피 편집)비전 엔지니어 검사 레시피를 만드는 작업 공간입니다. 40 종의 비전 도구를 끌어다 놓고 연결해 검사 순서를 만들고, 관심 영역(ROI)과 판정 기준을 정합니다. 시퀀스 편집기, 카메라 캘리브레이션, 배치 테스트, 예제 템플릿 갤러리가 여기에 있습니다.
VMS.AppSetup (시스템 설정 마법사)설치 담당자 카메라 · IO 보드 · Web 서버 주소 · 보안 모드 · 라이선스를 5 단계 마법사로(◆PLC · ◆로봇 옵션이 있으면 PLC · 로봇 단계가 더해져 7 단계, ◆MLOps 서버 주소도 이 마법사에서) 설정합니다. 설치 후 최초 1 회 실행하며, 설비가 바뀔 때만 다시 엽니다.

생산 관리 서버 — BODA.VMS.Web

브라우저(Chrome)로 접속하는 웹 프로그램입니다. 작업지시 · Lot · 작업자 · 제품 · 불량 코드 같은 기준 정보를 관리하고, 라인에서 올라온 검사 결과로 생산 이력 · 알람 · 파레토 · SPC · OEE · 보고서를 만듭니다. VMS 설치 파일에 동봉되어 있어 라인 PC 와 같은 PC 에 Windows 서비스로 켤 수도 있고, 별도 서버 PC 에 설치해 라인 여러 대(최대 100 대)를 붙일 수도 있습니다. Web 서버 없이 검사만 하는 단독 모드도 지원합니다(§4.9).

◆AI 학습 플랫폼 — BODA.VMS.MLOps (선택)

딥러닝 검사 도구가 쓰는 모델(ONNX 파일)을 만드는 서버입니다. 라인에서 올라온 불량 사진을 모아 웹에서 라벨링하고, GPU 가 있는 ◆학습 워커 PC 가 학습을 돌려 모델 레지스트리에 등록하면, 라인 PC 는 레시피의 참조(model://…)로 운영 모델을 자동으로 내려받습니다. ◆MLOps 를 쓰지 않는 현장은 이 서버 없이 운영해도 됩니다.

1.2 운영 흐름 한눈에

설치와 레시피 작성이 끝난 뒤 현장에서 매일 반복되는 흐름은 다음과 같습니다.

  1. 관리자(Web)가 오늘의 작업지시(제품 × 수량 × 레시피)를 등록합니다. 필요하면 Lot 을 발행합니다.
  2. 작업자(VMS)가 헤더의 [Login...] 으로 사번과 PIN 을 입력해 로그인합니다.
  3. [Work Orders] 에서 작업지시를 고르면 레시피가 자동으로 불러와지고 [AUTO RUN] 이 켜집니다.
  4. [AUTO RUN] 을 누르면 시퀀스에 따라 트리거 대기 → 촬영 → 검사 → 판정 신호 출력이 반복됩니다.
  5. 검사 1 건마다 결과가 서버로 올라가고, 헤더의 진행 수량(예: 5/100)이 실시간으로 올라갑니다. 불량(NG)이 나오면 서버에 알람이 자동 생성됩니다.
  6. 계획 수량에 도달하면 작업지시가 자동으로 완료되고 완료 알림 창이 뜹니다. 다음 작업지시를 바로 고를 수 있습니다.
  7. 관리자(Web)는 대시보드 · 안돈 보드 · 생산 이력 · 품질 분석 화면에서 실적을 확인합니다.
단독 모드 현장은 1 · 2 · 3 · 7 단계가 없습니다. 레시피를 고른 뒤 바로 [AUTO RUN] 을 누르며, 검사 이력은 이 PC 의 생산 이력 조회 창(§4.10)에서 봅니다.

1.4 핵심 용어

작업자 (Operator)사번 + PIN 으로 VMS 나 키오스크에서 출근하는 현장 인력입니다. 등급은 Operator / Lead / Supervisor.

1.6 기본 구성과 확장 옵션 (◆)

같은 설치 파일 하나에 모든 기능이 들어 있고, 어떤 기능이 화면에 보이는지는 라이선스가 정합니다. 기본 구성은 2D 검사 · 저장된 점군(.vpc) 3D 검사 · 딥러닝 추론 · IO 보드 · 생산 관리 웹이고, 아래 다섯 가지는 라이선스에 따로 넣어야 보이는 확장 옵션입니다. 이 매뉴얼은 확장 옵션에 ◆ 를 붙였습니다.

확장 옵션 (라이선스 표시 이름)켜지는 것없을 때
◆3D 카메라 촬영3D 카메라(Mech-Mind) 연결, 카메라 화면의 Depth Map · Point Cloud 탭과 [Save 3D], VisionSetup 스텝의 3D 스캔 설정(§5.13)3D 카메라 연결이 거부됩니다. 저장된 점군은 VisionSetup [3D] › [Load 3D Data] 로 열어 검사할 수 있습니다
◆로봇 연동 · 멀티뷰설정 마법사 Robot 단계(§3.6), 웨이포인트 스텝 · 멀티뷰 스캔 · 핸드아이(§5.13), 얼라인 도구의 Robot Transform, 상태바 ROBOT 칩로봇 단계를 건너뛰고 관련 버튼이 숨겨집니다
◆MLOps 서버 연동설정 마법사 고급 설정의 MLOps 주소 · 라인 토큰(§3.3), 딥러닝 도구의 [레지스트리…](§5.13), 이미지 저장 설정의 NG 이미지 MLOps 전송(§4.6), OCR Synth Data(§5.12)모델은 파일 경로로만 지정합니다
◆PLC 연동설정 마법사 PLC 단계(§3.5), 도구의 PLC Output(§5.6), 시퀀스의 MainPLC · Reset 신호 · PLC Monitor(§5.10), 상태바 PLC 칩IO 보드로만 신호를 주고받습니다
◆라인스캔 · 롤러 검사라인스캔 카메라 종류(§3.4), 사이드 패널 Roller Inspection(§4.6)에어리어 카메라만 고를 수 있습니다

지금 PC 의 라이선스에 무엇이 들어 있는지는 설정 마법사 마지막 단계(보안 · 라이선스, §3.8)의 확장 옵션 줄에 나옵니다 — "기본 구성 (확장 옵션 없음)", "확장 옵션 전부", 또는 켜진 옵션 이름. 옵션은 라이선스를 발급할 때 정합니다(§13.7).

알아 둘 것: 라이선스 파일이 없거나 옵션 항목이 없는 예전 라이선스, 서버 좌석으로 붙는 라인 PC 는 확장 옵션이 전부 켜진 것으로 동작합니다. 고객에게 기본 구성만 보여야 하는 현장(GS 시험 PC 등)은 옵션이 비어 있는 라이선스를 반드시 설치합니다.

1.7 머신비전 기초 — 좋은 사진이 검사의 절반

검사 도구는 사진에 찍힌 것만 판단합니다. 결함이 사진에 또렷이 보이지 않으면 어떤 도구 설정으로도 잡을 수 없습니다. 레시피를 만들기 전에 아래 다섯 가지를 먼저 맞춥니다.

항목무엇이고, 어떻게 맞추나
조명결함을 드러내는 것은 카메라가 아니라 조명입니다. 흠집 · 찍힘처럼 표면 요철은 비스듬한 저각 조명(바 · 링 저각)에서, 이물 · 얼룩처럼 색 · 밝기 차이는 정면 확산 조명(돔 · 동축)에서, 외곽 치수는 뒤에서 비추는 백라이트에서 잘 보입니다. 주변 형광등 · 햇빛이 섞이면 결과가 흔들리므로 가림막을 둡니다.
노출 · 게인노출(Exposure)은 셔터가 열려 있는 시간, 게인(Gain)은 신호 증폭입니다. 먼저 노출로 밝기를 맞추고, 움직이는 제품은 번지지 않게 노출을 짧게 · 조명을 밝게 합니다. 게인을 올리면 밝아지지만 잡음도 커집니다. 밝은 부분이 하얗게 날아가거나(포화) 어두운 부분이 뭉개지지 않는지 히스토그램으로 확인합니다(§4.5 · §6.2).
해상도 · 시야(FOV)한 화소가 실제로 몇 mm 인지(mm/px)가 잴 수 있는 정밀도를 정합니다. 예: 시야 120 mm 를 2448 화소 카메라로 찍으면 약 0.05 mm/px 입니다. 잡아야 할 가장 작은 결함이 최소 3~5 화소는 되게 시야를 좁히거나 화소가 많은 카메라를 씁니다. mm 로 재려면 캘리브레이션을 합니다(§5.9).
초점 · 피사계 심도제품 높이가 달라지거나 위치가 흔들려도 선명해야 합니다. 렌즈 조리개를 조이면(F 값을 키우면) 초점이 맞는 깊이가 넓어지지만 어두워지므로 조명으로 보충합니다.
트리거 · 위치제품이 같은 자리에 왔을 때 찍어야 같은 기준으로 검사됩니다. 센서 · 설비 신호를 IO 보드(◆PLC)로 받아 찍는 외부 트리거를 쓰고(§5.10), 위치가 조금씩 다르면 패턴 매칭 + 위치 보정(Fixture)으로 검사 영역을 따라가게 합니다(§7.3).
순서: 조명 → 노출 · 게인 → 초점 → 해상도 확인 → 캘리브레이션 → 레시피. 사진이 나쁘면 도구 문턱을 아무리 고쳐도 과검 · 미검이 함께 늡니다. 이 순서는 VisionSetup 의 첫 레시피 만들기(7장)와 같습니다.
