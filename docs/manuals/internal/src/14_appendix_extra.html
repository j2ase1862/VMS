13.6 명령줄 인자 (사내 참고)

프로그램 · 인자뜻
VMS.exe --instance 이름이름 붙은 인스턴스로 실행(§11.5). 이름은 영문 · 숫자 · _ · - 1~32 자. 환경 변수 BODA_VMS_INSTANCE 로도 지정
VMS.exe --cleanup-images화면 없이 이미지 보존 정리만 하고 끝냄. VMS 는 켜 둔 동안 스스로 정리하므로(§11.2), VMS 를 꺼 두는 PC 의 예약 작업용. VMS 가 실행 중이어도 돌 수 있음
VMS.AppSetup.exe --instance 이름그 인스턴스의 설정을 엶
VMS.VisionSetup.exe --instance 이름 [레시피 파일]그 인스턴스로 실행하고, 레시피 파일을 주면 시작할 때 엶
VMS.Updater.exe <MSI 경로> [--current 버전]인앱 업데이트가 자동으로 실행하는 설치 창. 직접 쓰지 않음(§2.7)
msiexec /i VMS-1.48.1.msi /qn INSTALLWEB=0조용히 설치, 동봉 Web 제외(1 이면 포함)
msiexec /fa VMS-1.48.1.msi /qn /norestart조용히 복구 설치

AppSetup 의 --apply-web-config · --start-web-service · --import-license 는 마법사가 관리자 권한으로 자기 자신을 다시 부를 때 쓰는 내부 인자이고, --capture-… 인자들은 개발 빌드(DEBUG)에서 매뉴얼 그림을 찍는 데만 있습니다. 보안 모드를 시험용으로 바꾸는 환경 변수(BODA_VMS_SECURITY_MODE · BODA_VMS_RELAX_SECURITY)는 현장 PC 에 두지 않습니다.

13.7 LicGen — 라이선스 발급 (사내 전용)

사내 전용 · 발급 담당자만. LicGen 과 서명 키는 고객에게 주지 않고, 설치 파일에도 들어 있지 않습니다. 상세 절차 · 예시 · 오류표는 docs/licgen_admin_manual.md, 키 운영은 docs/license_operations.md 에 있습니다.

라이선스 발급

  1. 고객 PC 의 지문 코드를 받습니다 — 설정 마법사 마지막 단계(§3.8)의 지문 코드 [복사]. 형식 XXXXX-XXXXX-XXXXX.
  2. 사내 PC 에서 BODA VMS 라이선스 발급 (LicGen — 사내 전용) 창을 열고 [라이선스 발급] 탭에 고객명, 종류(Production · Trial · Internal), 서명 키, 대상 PC 지문, 좌석 수, 유지보수 만료, 실행 만료, 확장 옵션을 넣습니다. 확장 옵션은 체크 상자 5 개입니다 — 3D 카메라 촬영 · 로봇 연동 · 멀티뷰(한 상자) · MLOps 서버 연동 · PLC 연동 · 라인스캔 · 롤러 검사(한 상자). 유지보수 만료가 지나도 실행 · 업데이트는 그대로 되고 고객 PC 의 라이선스 상태에 "유지보수 만료" 로 표시만 됩니다.
  3. [발급] → "발급 확인" 창에서 내용을 확인합니다. 규칙에 어긋나면 "발급 규칙 위반" 이 나옵니다 — 고객명 · 지문 필수, 좌석 1 이상, Trial · Internal 은 실행 만료 필수, Internal 은 90 일 이내, 지문 *(모든 PC)는 Internal 만.
  4. 만들어진 license.lic 를 고객 PC 의 설정 마법사 [라이선스 파일 가져오기...] 로 설치합니다(§2.6). 파일은 C:\ProgramData\BODA\VMS\license.lic 에 들어갑니다.

라이선스 번호는 LIC-연도-순번 으로 자동으로 붙습니다. 확장 옵션을 하나도 고르지 않으면 기본 구성 라이선스입니다(§1.6). 옵션 칸이 생기기 전에 발급해 옵션이 적혀 있지 않은 라이선스는 확장 옵션 전부로 동작합니다.

발급 대장

[발급 대장] 탭에 발급한 라이선스가 한 줄씩 남습니다(라이선스 ID · 고객명 · 종류 · 지문 · 좌석 · 유지보수 · 실행 만료 · 발급 시각 · 발급자 · 비고 — 옵션 열은 없음). 긴 고객명 · 비고는 줄여 보이고 마우스를 올리면 전체가 나옵니다. 줄을 고르고 비고를 적어 [비고 저장] 합니다. 대장 파일은 발급 PC 의 %USERPROFILE%\.boda-licgen\ledger.jsonl 이며 손으로 고치지 않습니다.

  • 발급한 주가 끝나기 전에 위쪽 [백업 실행] 으로 서명 키 · 대장을 오프라인 USB 두 개에 백업합니다. 창 위쪽 배너는 백업 미반영 발급 건수를 매체마다 보여 줍니다(예: T7 Shield [..] 0건 · KGD-SSD [..] 3건). 두 매체 모두 0건이 되어 노란 글자가 사라져야 끝입니다 — 한 매체만 갱신하면 다른 매체의 건수가 남고 경고도 그대로입니다.
  • Production · Trial 은 운영 키, Internal 은 개발 키로 서명합니다. 비밀 키 파일(*.private.pem)은 리포 · 클라우드 · 메일 · 메신저에 두지 않습니다.
  • 같은 일을 명령줄로 하려면 licgen issue · verify · fingerprint · backup 을 씁니다(관리자 매뉴얼의 CLI 표).
