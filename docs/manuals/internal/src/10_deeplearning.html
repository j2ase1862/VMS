10. 딥러닝 모델 준비

딥러닝 검사 도구(§6.11 — Detection · Segmentation · RF-DETR-seg · Classify · Anomaly)는 학습된 모델 파일(ONNX)로 동작합니다. OCR 은 식별 도구라 레지스트리 단추가 없고, 기본 엔진을 그대로 쓰거나 Expert Mode 의 Custom Det/Rec Model 에 직접 학습한 모델 파일을 지정합니다. 모델의 라벨링 · 학습 · 등록은 AI 학습 플랫폼 BODA VMS MLOps(9장)에서 합니다. VMS 와 VisionSetup 은 만들어진 모델을 불러와 검사에 씁니다.

  1. 학습 — MLOps 에서 데이터셋을 라벨링하고 학습 작업을 실행합니다(§9.5 · §9.6). 끝난 모델은 모델 레지스트리에 후보 버전으로 등록됩니다.
  2. 승격 — 모델 레지스트리에서 결과를 확인하고 스테이징 · 운영 단계로 올립니다(§9.9).
  3. 레시피에 지정 — VisionSetup 딥러닝 도구의 Model Path 옆 [레지스트리…] 로 모델을 고르면 model:// 참조가 들어갑니다(§9.10). VisionSetup 은 레시피를 열 때와 [선택] 할 때, 라인 PC 의 VMS 는 레시피를 불러올 때(사이드 패널 [Load] · 작업지시 선택 · ◆PLC 레시피 변경 등) 그 참조가 가리키는 버전을 내려받아 둡니다. 받아 둔 모델은 MLOps 서버가 꺼져 있어도 씁니다. 운영 버전을 새로 승격했으면 라인에서 레시피를 다시 불러와야 새 버전을 받습니다. 모델 파일을 직접 받아 둔 경우에는 Model Path 에 .onnx 경로를 지정해도 됩니다.

10.1 OCR 합성 데이터로 학습하기

날짜 · 로트 번호처럼 형식이 정해진 문자열은 VisionSetup 의 OCR Synth Data(§5)로 학습 데이터를 만들어 MLOps 에서 학습할 수 있습니다.

  1. OCR Synth Data 에서 출력 형식을 PaddleOCR rec 로 두고 [Generate] 로 데이터를 만듭니다.
  2. 출력 폴더 안의 train_crops · val_crops 폴더와 train_rec.txt · val_rec.txt · dict.txt 를 모두 골라 압축합니다. 서버는 zip 맨 위의 train_rec.txt · val_rec.txt · dict.txt(또는 ppocr_keys_v1.txt)와, 목록에 적힌 경로의 사진만 봅니다 — 사진 폴더 이름은 목록과 맞기만 하면 됩니다. 출력 폴더째 압축하면 업로드가 거절됩니다.
  3. MLOps 의 [데이터셋 버전] ▸ [버전 업로드] 에서 작업 유형 OCR, 형식 ppocr 로 올리고(§9.7) 학습 작업을 실행합니다.

10.2 GPU · TensorRT 로 추론 빠르게 하기

딥러닝 검사 도구(Detection · Classify · Anomaly · Segmentation · RF-DETR-seg)는 기본으로 CPU 에서도 돌지만, NVIDIA GPU 가 있으면 몇 배 빨라집니다. 실행 백엔드는 VisionSetup 메뉴 Inference Settings... 의 Inference Engine Settings 창에서 PC 전체에 한 번 정합니다.

Execution Provider뜻
AutoCuda → DirectML → Cpu 순서로 이 PC 에서 쓸 수 있는 첫 백엔드를 씁니다(기본). TensorRT 는 Auto 에 들어가지 않으므로 쓰려면 직접 고릅니다
CpuCPU 만 씁니다. 가장 느리지만 어느 PC 에서나 같은 결과
CudaNVIDIA GPU 를 바로 씁니다. CUDA · cuDNN 이 설치되어 있어야 합니다
DirectMLWindows 의 DirectX 로 GPU 를 씁니다(NVIDIA 가 아닌 GPU 도 가능)
TensorRTNVIDIA GPU 에서 가장 빠릅니다. 모델을 처음 불러올 때 엔진을 만드느라 시간이 걸리고(모델 · GPU 에 따라 다름), 그 뒤로는 캐시를 써서 빠릅니다. TensorRT 가 설치되어 있어야 합니다
  1. GPU PC 에 NVIDIA 드라이버(525 이상), CUDA 12.x(12.4 권장), cuDNN 9.x, TensorRT 10.x 를 설치하고, TensorRT 의 bin 폴더를 시스템 Path 에 넣은 뒤 재부팅합니다. 버전 조합은 VMS 에 들어 있는 ONNX Runtime 1.21 기준입니다.
  2. VisionSetup → Inference Settings... 에서 Execution Provider 를 고릅니다.
  3. TensorRT 라면 TensorRT Engine Cache Folder 를 확인합니다. 만든 엔진을 이 폴더에 저장해 두고 다음 실행부터 재빌드를 건너뜁니다. 비워 두고 저장하면 기본 폴더(설정 폴더의 trt_cache)를 씁니다.
  4. 지원 GPU 면 Enable TensorRT FP16(반정밀도)을 켤 수 있습니다. 더 빨라지지만 효과는 모델 · GPU 에 따라 다르고, 점수가 소수점 아래에서 조금 달라질 수 있습니다.
  5. [Save] 를 누릅니다. 바뀐 설정은 다음에 모델을 불러올 때(레시피를 다시 열 때)부터 적용됩니다.

확인: 관리자 PowerShell 에서 nvidia-smi 가 GPU 를 보여 주는지, 레시피를 연 뒤 같은 사진의 실행 시간이 줄었는지 봅니다. Inference Settings 창에서 이 PC 에서 쓸 수 없는 백엔드에는 "(이 PC 에서 사용 불가)" 가 붙고, 창 아래 "실제 사용 백엔드" 줄에 마지막 모델 로드 때 실제로 쓴 백엔드가 보입니다. Detection · Segmentation · RF-DETR-seg 는 Run Results 의 ExecutionProvider 값으로도 확인할 수 있습니다. GPU 환경이 없거나 깨져 있으면 멈추지 않고 CPU 로 돌아갑니다(System Log 의 "추론 장치 설정: …" 줄은 고른 값입니다).

주의: 이 설정은 PC 단위입니다(%LocalAppData%\BODA VISION AI\system_config.json 의 onnxExecutionProvider · tensorRTCachePath · tensorRTFp16). VisionSetup 과 VMS 가 같은 값을 씁니다. 라인 PC 와 학습 워커를 겸하는 PC 는 검사와 학습이 같은 GPU 를 나눠 씁니다(§2.4).
