9. AI 학습 플랫폼 (BODA.VMS.MLOps)

⚙ 이 장은 딥러닝 검사 도구의 모델을 만들고 배포하는 엔지니어 · 관리자용이며, MLOps 는 인증 범위 밖의 선택 구성 요소입니다. MLOps 서버 없이 검사만 운영하는 현장은 건너뛰어도 됩니다.

MLOps 는 브라우저로 접속하는 웹 프로그램(http://서버주소:5310)입니다. 라인에서 올라온 불량 사진을 모아 라벨링하고, GPU 학습 워커가 학습을 돌려 만든 모델을 레지스트리에서 단계별(후보 → 스테이징 → 운영)로 관리하며, 라인 PC 는 레시피에 적힌 참조로 운영 모델을 자동으로 내려받습니다. 설치는 §2.4, 라인 PC 쪽 설정은 §3.3(고급 설정)과 §4.6(Image Saving) 을 참고하세요.

9.1 로그인과 역할

  • MLOps 는 별도 계정이 없고 BODA.VMS.Web 의 계정으로 들어갑니다. 로그인 화면에 Web 에서 로그인해 받은 액세스 토큰(JWT)을 붙여 넣는 방식이며, 두 서버가 같은 서명 키를 쓰기 때문에 그대로 통합니다.
  • 현재는 Web 의 Admin 계정만 모든 기능을 쓸 수 있습니다. MLOps 안에는 Viewer(조회) · Labeler(라벨링) · Engineer(학습 · 스테이징 승격) · Admin(운영 승격 · 워커 · 라인 PC 관리) 역할 체계가 있지만, Web 의 User · Guest 계정으로는 화면이 "역할 없음" 으로 표시되고 기능이 열리지 않습니다.
  • 라인 PC 와 학습 워커는 사람이 로그인하지 않고 토큰(ln_… · wk_…)으로 붙습니다. 토큰은 발급 시 한 번만 표시되며 서버에는 해시만 남습니다.

9.3 전체 흐름 — 수집에서 배포까지

  1. 라인 NG 수집 — 라인 PC 의 Image Save Settings 에서 [NG 이미지 MLOps 전송] 을 켜고 양품 샘플 비율(N 장에 1 장)을 정합니다(§4.6). 사진이 결과 그래픽 없는 원본으로 수집 사진 화면에 쌓입니다.
  2. 데이터셋에 담기 — 수집 사진에서 출처 "라인 NG", "데이터셋에 안 담긴 것만" 으로 걸러 고른 뒤 [데이터셋에 담기](데이터셋 + 학습/검증/시험 분할).
  3. 라벨링 — 데이터셋 상세에서 [라벨링 시작]. 사각형 · 폴리곤 · SAM 클릭으로 라벨을 붙이고 [저장하고 다음]. Engineer 가 [검토 승인].
  4. 판 뜨기 — [버전 만들기] 로 지금의 이미지와 라벨을 굳혀 학습 대상 버전을 만듭니다.
  5. 학습 제출 — 학습 작업 → [작업 제출]: 데이터셋 버전 · 모델 계열 · 스크립트 · 사전학습 가중치 · 하이퍼파라미터.
  6. 워커 실행 — GPU 워커가 작업을 가져가 학습하고 진행률 · 로그 · 학습 곡선을 실시간으로 올립니다. 끝나면 모델이 후보(Candidate) 버전으로 자동 등록됩니다.
  7. 승격 — 모델 상세에서 버전의 [스테이지] 로 후보 → 스테이징(Engineer) → 운영(Admin). 라인으로 나가는 결정은 항상 사람이 합니다.
  8. 레시피 연결 — VisionSetup 딥러닝 도구의 Model Path 옆 [레지스트리…] 로 모델을 고르면 model://{모델ID}@production 참조가 저장됩니다(§6). 라인 PC 는 레시피를 열 때 운영 버전을 내려받아 캐시하고, 검사 중에는 네트워크를 쓰지 않습니다.
  9. 모니터링 — 라인 모니터링에서 모델 버전별 불량률 · 신뢰도를 비교하고, 권고가 붙으면 [재학습] 으로 5 단계부터 다시 돕니다.
자동으로 되는 것은 수집 · 사전 라벨 · 판 뜨기 · 후보 등록 · 재학습 권고까지입니다. 스테이징 · 운영 승격과 롤백은 항상 사람이 결정하며, 데이터가 쌓였다고 사람 없이 재학습이 도는 일은 없습니다.

9.4 수집 사진

  • 필터: 출처(라인 NG · 양품 샘플 / 직접 올림, 기본 라인 NG), "데이터셋에 안 담긴 것만"(기본 켜짐), 태그(예: verdict:ng, recipe:PUT-10), 파일명 검색.
  • 카드를 클릭해 선택하고 [데이터셋에 담기] → 데이터셋과 분할(학습 · 검증 · 시험)을 고릅니다. 사진은 복제되지 않고 참조로 담깁니다.
  • 사진이 올라오지 않으면 라인 PC 의 [NG 이미지 MLOps 전송] 스위치와 라인 PC 등록 · 토큰(§9.11)을 확인하세요.

9.5 데이터셋 · 라벨링

  • [새 데이터셋] — 이름 · 작업 유형(검출 · 분류 · 이상탐지 · 세그멘테이션 · OCR) · 클래스(쉼표 구분, 순서가 클래스 번호) · 설명. 작업 유형과 클래스는 만든 뒤 바꿀 수 없습니다. 이상탐지는 정상 클래스(good · normal · ok · 정상)가 필요합니다.

라벨링 캔버스

  • 작업 유형별 도형 — 검출: 사각형 · 폴리곤 / 세그멘테이션: 폴리곤 / 분류 · 이상탐지: 이미지당 클래스 하나 / OCR: 사각형 + 문자열.
  • 단축키 — ←/→ 이전 · 다음 이미지, 끌어서 그리기, 휠 확대, Alt+끌기 이동, 숫자키로 클래스 선택, Delete 삭제, Esc 선택 해제. 폴리곤은 클릭으로 점을 찍고 오른쪽 클릭 또는 Enter 로 닫습니다.
  • SAM 클릭 — 객체를 클릭하면 경계를 자동으로 만들어 줍니다. Shift+클릭(또는 오른쪽 클릭)은 빼고 싶은 곳, Tab 으로 더 크게 · 작게 후보 순회, Backspace 로 마지막 점 취소, Enter 로 확정해야 라벨이 됩니다. 서버에 SAM 모델이 없으면 이 모드는 나타나지 않습니다.
  • 클래스 선택은 "다음에 그릴 것"만 정합니다. 이미 붙은 라벨의 클래스는 라벨 목록의 팔레트 메뉴로 바꿉니다. 이미지 1 장은 한 사람만 작업할 수 있으며(잠금 10 분, 저장 시 연장) 남이 잡고 있으면 읽기 전용입니다.
  • 진행 패널의 [검토 승인] / [반려] 는 Engineer 이상이 누릅니다.

작업은 대기 → 배정됨 → 준비 중 → 학습 중 → 내보내는 중 → 업로드 중 → 성공(또는 실패 · 취소됨) 순으로 진행됩니다. 상세 화면에서 진행률 · 로그 · 학습 곡선(손실 · mAP50) · 아티팩트(ONNX · 지표 · 곡선 · 로그) · 재현성 정보(데이터셋 해시 · 스크립트 해시 · GPU · 패키지)를 보고, 끝난 작업은 [같은 설정으로 재실행] 할 수 있습니다.

9.7 데이터셋 버전

학습은 항상 버전에 대해 실행됩니다. 데이터셋에서 뜬 판이 여기에 쌓이고, 외부에서 만든 내보내기 zip 도 [버전 업로드] 로 올려 고정할 수 있습니다(이름 · 작업 유형 · 형식 · 이미지 수 · 클래스).

9.8 워커 · 사전학습 미러

  • [워커 등록] 에서 이름을 넣고 [발급] 하면 wk_… 토큰과 GPU PC 에서 실행할 명령이 표시됩니다. 워커 설치 마법사(§2.4)에 이 값을 넣습니다.
  • 상태 — 대기 중(초록) · 학습 중(파랑) · 연결 끊김(회색) · 비활성(빨강). 진단에 실패한 워커(예: CUDA 사용 불가)는 비활성으로 작업을 받지 않으며 사유가 카드에 표시됩니다.
  • [토큰 재발급] 하면 옛 토큰은 즉시 무효가 되므로 워커 설정을 갱신해야 합니다.

워커는 인터넷 대신 여기서만 사전학습 가중치를 받습니다(폐쇄망 · SSL 검사 환경 대응). [자산 추가] 로 ref(예: dfine-small-obj2coco) · 라이선스 · 출처를 등록하고 [파일 추가] 로 config.json · model.safetensors 를 올립니다.

9.9 모델 레지스트리

  • [새 모델] — 이름 · 작업 유형 · 클래스(순서가 ONNX 의 names 와 같아야 업로드가 통과) · 설명. 작업 유형은 만든 뒤 바꿀 수 없습니다.
  • 모델 상세 — 버전 표(버전 · 스테이지 · 규약 · 입력 · 지표 · 크기 · SHA-256 · 출처 · 등록)와 [상세] [다운로드] [스테이지]. [버전 업로드] 로 외부 ONNX 를 직접 올릴 수도 있습니다(YOLO 파생 모델은 라이선스 확인 문구 필수).
  • 스테이지 — 후보(Candidate) → 스테이징(Staging) → 운영(Production) → 폐기(Retired). 운영은 모델 계열당 하나뿐이라 새 버전을 승격하면 이전 운영 버전은 스테이징으로 내려갑니다. 사유는 감사 기록에 남습니다.
  • 버전 상세 드로어에서 아티팩트 정보 · 지표 · ONNX 메타데이터 · 스테이지 이력 · 라인 배포 이력(어느 라인이 언제 받아 갔는지)을 확인합니다.

9.10 레시피 바인딩

레시피의 검사 도구가 어느 모델 버전을 쓰는지 정하는 화면입니다. 보통은 VisionSetup 의 [레지스트리…] 로 "운영 추종"(@production) 참조를 저장하면 되고, 특정 버전을 고정하거나 이전 버전으로 되돌릴 때 이 화면의 [도구에 모델 연결] · [롤백] 을 씁니다. "해석 불가" 로 표시되면 운영으로 승격된 버전이 없어 라인 PC 가 모델을 받지 못하는 상태입니다.

9.11 라인 PC

  1. [라인 PC 등록] 에서 이름(예: 라인A 1호기)과 라인 ID(예: LINE-A)를 넣고 [발급] 을 누릅니다. ln_… 토큰이 한 번만 표시됩니다.
  2. 그 라인 PC 의 설정 마법사 2 단계 고급 설정에 MLOps 서버 주소와 MLOps 라인 토큰을 넣고 저장한 뒤 VMS 를 재시작합니다(§3.3).
  3. 라인 PC 가 모델을 받거나 사진을 올리면 "마지막 접속" 이 갱신됩니다. [중지] 하면 그 PC 는 새 모델을 받지도 사진을 올리지도 못하지만 이미 캐시된 모델로 검사는 계속됩니다.

9.12 라인 모니터링

운영 웹의 검사 이력을 모델 버전별로 최근 7 일과 기준 21 일로 비교합니다. 여기서 모델을 자동으로 내리지는 않습니다.
