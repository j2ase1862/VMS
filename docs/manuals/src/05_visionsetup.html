5. 검사 레시피 편집 (VMS.VisionSetup)

⚙ 이 장은 검사 레시피를 만드는 비전 엔지니어용입니다. 현장에서 검사만 수행하는 작업자는 읽지 않아도 됩니다.

VMS.VisionSetup 은 검사 레시피를 만드는 작업 공간입니다. 왼쪽 Tool Palette 에서 도구를 골라 가운데 Tool Workspace 에 놓고 연결한 뒤, 이미지를 열어 실행해 보면서 오른쪽 Tool Settings 에서 파라미터와 판정 기준을 조정합니다. 완성한 레시피를 저장하면 VMS 메인이 그대로 불러와 검사합니다. VMS 사이드 패널 External Tools 의 [Vision Tool Setup] 또는 시작 메뉴로 실행합니다.

5.3 레시피 · 스텝 · 카메라

레시피 만들기와 관리 — Recipe Manager

  1. [New] 로 레시피를 만들고 오른쪽 Properties 에서 Recipe Name · Description · Version · Author 를 입력한 뒤 [Save] 합니다.
  2. [Add Step] 으로 스텝을 추가하고 스텝의 Camera 를 고릅니다. 스텝 이름("1-1", "1-2")은 카메라 등록 순서 기준으로 자동 계산되며 바꿀 수 없습니다. 부르기 쉬운 이름이 필요하면 Step Alias(별칭)를 넣습니다.
  3. [Load] 로 레시피를 메인 화면에 불러옵니다. 왼쪽 배지가 "Now Recipe: 이름" 으로 바뀌고 Steps 표에 스텝이 나타납니다.
  4. [Duplicate] 는 스텝 · 도구 · 학습 데이터까지 통째로 복사해 "이름 - 복사본" 을 만들고, [Rename] 은 이름을 바꿉니다(Web 원장 이름은 별도). [Import] / [Export] 로 JSON 파일을 주고받으며 [Open Folder] 는 저장 폴더를 엽니다.

레시피는 %LocalAppData%\BODA VISION AI\Recipes\ 에 JSON 으로 저장되며, Web 연동 현장에서는 같은 이름으로 Web 레시피 원장에 자동 등록됩니다.

스텝과 카메라 설정

  • Camera 콤보에서 카메라를 고르면 Steps 표에 그 카메라의 스텝만 표시됩니다(제목에 "Steps — 카메라명"). 레시피를 불러오면 레시피가 쓰는 카메라가 자동 선택됩니다.
  • 스텝 버튼: Add Step · Delete Step · Duplicate Step(카메라 설정과 도구 파이프라인을 복사해 바로 뒤에 추가) · Generate Robot Waypoint Steps(로봇 멀티뷰용) · Move Up / Move Down.
  • Steps 표의 Resolution(mm/px)은 측정 도구가 픽셀을 mm 로 바꾸는 값입니다. 캘리브레이션을 적용하면 자동으로 채워지고(§5.9), 간단한 현장은 직접 입력해도 됩니다.
  • 스텝만 선택하면 오른쪽 패널이 Camera Settings 로 바뀝니다 — 스텝 정보(별칭 · 로봇 노드 번호), 2D 이미지(카메라 설정 유지 체크 · 노출 ms · 게인 dB), 3D 카메라면 3D 스캔(점군 후처리 끄기/약/중/강 · 뎁스 범위 제한 mm). 여기 값은 Acquire · Live 때 카메라에 적용되고 레시피에 저장됩니다.

다른 PC 에서 만든 레시피 — 카메라 재연결

이 PC 에 없는 카메라를 쓰는 레시피를 열면 미등록 카메라 재연결 창이 뜹니다. 스텝별로 이 PC 의 카메라를 골라 [적용 및 저장] 을 누르면 도구 · 학습 데이터를 그대로 두고 카메라만 바꿔 쓸 수 있습니다. [건너뛰기] 하면 스텝 이름이 "?-1" 로 표시됩니다.

5.4 이미지 가져오기 — 파일 · 카메라 · VMS

방법절차

받은 이미지는 2D Image 탭에 표시되고 상태바에 "이미지 로드 완료" 가 나옵니다. 이후 Run All 이 활성화됩니다.

5.5 도구 배치 · 연결 · ROI

  1. 도구 놓기 — Tool Palette 의 도구를 Tool Workspace 로 끌어다 놓습니다. 놓는 즉시 선택되어 오른쪽에 Tool Settings 가 나타납니다. 도구 이름 옆 물음표(?)에 마우스를 올리면 그 도구의 용도 · 사용법 · 결과 값 설명이 뜹니다.
  2. 연결하기 — 앞 도구 노드를 우클릭 → Connect Image(초록 실선) / Connect Coordinates(파랑 점선) / Connect Result(주황 점선) 를 고른 뒤 뒤 도구를 클릭합니다. Esc 또는 우클릭으로 취소합니다.
    • Image — 앞 도구의 결과 이미지를 뒤 도구의 입력으로 넘깁니다(예: Grayscale → Threshold → Blob).
    • Coordinates (Fixture) — 패턴 매칭이 찾은 위치 · 각도만큼 뒤 도구의 ROI 를 옮기고 기울입니다. 부품이 틀어져 놓여도 같은 자리를 검사합니다.
    • Result — 앞 도구의 결과 값을 뒤 도구가 참조합니다(예: Caliper 두 개 → Geometry, 여러 도구 → Result).
  3. ROI 그리기 — 도구를 선택하고 Tool Settings 의 Use ROI 를 켠 뒤, 이미지 뷰 툴바에서 Rectangle · RectAffine(회전 사각형) · Circle · Ellipse · Polygon 을 골라 이미지 위에 그립니다. 흰 원 핸들로 크기, 금색 원 핸들로 회전을 조정하고 [Delete] / [Clear All] 로 지웁니다. [Show ROI] · [Draw ROI] · [Clear ROI] 버튼은 Tool Settings 의 ROI Settings 에 있습니다.
  4. 이름 · 복제 — 노드 우클릭 → Rename Tool 로 이름을 바꾸고, Duplicate Tool 로 파라미터 · ROI · 학습 데이터까지 복사한 사본을 만듭니다(연결은 복사되지 않음).
각 도구 설정 상단의 Expert Mode 토글을 켜면 고급 파라미터가 나타납니다. 같은 종류의 모든 도구에 적용되고 다음 실행에도 유지됩니다. 처음에는 끈 채로 기본 파라미터만으로 시작하세요.

5.6 실행과 결과 보기 · 판정

  • 툴바 ▶ (Run All) 을 누르면 현재 스텝의 도구가 연결 순서대로 실행되고 상태바에 "실행 완료: n/m 성공" 이 표시됩니다. 도구 하나만 시험하려면 그 도구를 선택하고 ▶| (Run Selected).
  • 이미지 뷰에 결과가 겹쳐 그려지고(검출 윤곽 · 에지 · 매칭 위치 · OK/NG 배지), 아래 Run Results 표에 도구별 Pass/Fail 과 결과 값이 나옵니다. 행을 누르면 상세가 펼쳐지고 우클릭으로 복사할 수 있습니다. 이미지 소스 콤보를 Result Image 로 바꾸면 도구가 만든 결과 이미지 자체를 봅니다.
  • [Save Image] 로 현재 표시 중인 이미지를 PNG · JPG · BMP · TIFF 로 저장할 수 있습니다.

판정 규칙

도구NG 로 처리되는 경우
Blob판정을 켰을 때 면적 · 개수가 기준 범위를 벗어난 경우. 덩어리가 하나도 없으면 NG
Feature Match · Shape Match패턴을 찾지 못했거나, 커버리지 판정 · 각도/크기 판정에 걸린 경우
Geometry · Match Align · Multi-Step Align측정값(거리 · 각도 · Δ)이 기준값 ± 공차를 벗어난 경우
Detection · Segmentation · YOLOv8-seg · RF-DETR-seg객체가 0 건 검출된 경우(또는 각도 판정을 켰는데 계산 불가)
Code Reader · OCR · OCV판독 실패, 기대 문자열 불일치, 품질 등급 미달
Result연결된 도구 중 하나라도 Fail 이면 최종 NG
운전 공통카메라에서 이미지를 받지 못한 사이클

"찾아야 할 것을 하나도 찾지 못한 검사" 는 합격이 아니라 NG 입니다. 예상과 다른 NG 가 나오면 결과 화면에서 무엇이 검출되지 않았는지 먼저 확인하세요.

Result 도구 — 최종 판정과 PLC 통계

스텝의 마지막에 Result 도구를 두고 판정에 넣을 도구들을 Result 연결하면, 모두 Pass 일 때만 OK 가 됩니다. Result 도구의 PLC Output 에는 PassCount · FailCount · TotalCount 통계를 PLC 주소에 매핑할 수 있습니다. 검사 1 건의 최종 OK/NG 신호는 시퀀스 편집기의 Branch → Output Action 이 담당합니다(§5.10).

PLC Output — 결과 값을 PLC 로 보내기

도구 설정 아래의 PLC Output 에서 [+ Add PLC Mapping] 을 누르고 Key(결과 값 이름) · Device(MainPLC 또는 IO 보드) · Address(PLC 주소 또는 IO 채널) · Type 을 정하면 실행 때마다 그 값이 PLC 에 기록됩니다.

5.7 검사 기준값을 Web 에서 관리하기 (파라미터 연동)

Blob · Caliper · Line Fit · Circle Fit · Geometry · Feature Match · Shape Match · Threshold · Color Match · Height Slicer 의 판정 기준 입력란 옆에는 Web 파라미터 연동 콤보가 있습니다. 콤보에서 파라미터 코드를 고르면 운전(AUTO RUN) 때 그 코드의 Web 값을 씁니다 — 이후 기준값은 현장에서 도구 설정을 열지 않고 Web 레시피 파라미터 화면(§8.10)에서 바꿉니다.

  • 연동을 걸면 입력란 아래에 "Web 연동 중 (#코드: 값) — 운전 값은 Web 에서 변경" 배지가 붙고, 화면의 로컬 값이 Web 값과 다르면 "⚠ 로컬 값 ≠ Web 값 — 운전은 Web 값을 사용합니다" 로 바뀝니다. 화면 값은 이 창의 테스트 실행에만 쓰입니다.
  • 콤보 목록은 지금 편집 중인 레시피의 파라미터이며 Web 에서 추가 · 수정하면 곧바로 반영됩니다. 레시피를 불러올 때 상태바에 "Web 파라미터: '레시피명' 코드 N개" 진단이 표시되고, 0 개면 확인할 것을 안내합니다.
  • Web 의 Blob Tool · Dimension Tool 프리셋 항목은 이 도구들의 연동 콤보와 1:1 로 맞춰져 있습니다.

5.8 예제 템플릿 갤러리

자주 쓰는 도구 조합을 클릭 몇 번으로 현재 스텝에 만들어 줍니다. 빈 화면에서 시작하지 않고 완성된 예제에서 값만 바꾸면 되므로 처음 레시피를 만들 때 권장합니다.

  1. Steps 표에서 도구를 넣을 스텝을 먼저 선택합니다(선택하지 않으면 메뉴가 비활성).
  2. 메뉴 예제 Template 을 누르고 카테고리 탭에서 카드를 고른 뒤 [생성](또는 더블 클릭).
  3. 도구 체인이 작업 공간에 만들어집니다. 다중 스텝 템플릿은 레시피에 스텝이 새로 생깁니다.
  4. 이미지(또는 3D 데이터)를 열고 Run All 로 시험한 뒤, 각 도구를 선택해 ROI · 임계값 · 모델 파일을 우리 제품에 맞게 조정합니다.

5.9 카메라 캘리브레이션 — mm 로 재기 위한 준비

화면의 픽셀이 실제로 몇 mm 인지 카메라에 가르치는 과정입니다. 해 두면 측정 도구가 mm 로 판정하고, Image Rectify 도구가 렌즈 왜곡 · 기울어짐을 바로잡을 수 있습니다. Camera → Calibration Manager... 로 엽니다.

  1. 이미지 가져오기 — Image Source 에서 File(저장 사진) · Camera (direct)(직접 촬영) · VMS Shared Frame([Grab from VMS] — VMS 가 지금 한 장 찍어 보내 줌, 운전 · 라이브 중엔 거절) 중 고릅니다. 버튼이 눌리지 않으면 [Refresh Source Availability].
  2. 방식 고르기 — Calibration Mode:
    방식준비물알아내는 것이럴 때
    Checkerboard체커보드 인쇄물렌즈 왜곡 + mm/px화면 가장자리가 휘는 광각 렌즈
    Circles Grid (dots)원형(도트) 타겟렌즈 왜곡 + mm/px산업용 타겟 대부분. 초점이 약간 흐려도 잘 잡힘
    N-Point (planar)mm 좌표를 아는 점 4 개 이상기울어진 평면 펴기 + mm/px카메라를 수직으로 세울 수 없어 사다리꼴로 찍힐 때
    Single Scale (2 points)길이를 아는 구간 하나mm/px 만왜곡이 거의 없고 mm 환산만 필요할 때
  3. 값 입력 — Checkerboard 는 Pattern Cols/Rows 에 안쪽 교차점 수(10 칸 → 9, 가로 · 세로가 달라야 함)와 Square Size(자로 잰 칸 크기 mm). Circles Grid 는 원의 개수와 Circle Spacing(이웃 원 중심 거리, 타겟에 적힌 값), 엇갈린 배열이면 Asymmetric 체크(기본 켬). N-Point 는 이미지를 클릭해 점을 찍고 표에 mm 좌표 입력, Single Scale 은 두 점을 클릭하고 Known Length 입력.
  4. 여러 장 모으기 — Checkerboard · Circles Grid 는 한 장으로는 렌즈 값이 정해지지 않습니다. Accumulate Multi-View 를 켜고 타겟의 각도 · 위치를 바꿔 가며(화면 네 구석을 골고루) 10~20 장을 [Run Calibration] 으로 누적합니다. 다시 시작하려면 [Reset].
  5. 결과 읽기 — Reprojection Error 는 작을수록 좋습니다(체커보드 1 px 미만 양호, 2 넘으면 값 오류 의심). Pixel Size 는 알고 있는 치수를 화면에서 재 보고 맞는지 확인합니다.
  6. 레시피에 적용 — Apply 구역의 "Resolution 을 갱신할 스텝" 목록에서 스텝을 체크하고 [Apply to Current Recipe]. 결과가 레시피에 저장되고, 체크한 스텝의 Resolution 이 바뀌며, 레시피 파일이 바로 저장됩니다. 카메라로 직접 촬영했으면 그 카메라의 스텝만 기본 체크되고, 파일이면 전체가 체크되니 카메라가 여러 대인 레시피는 확인 후 해제하세요.
  • 캘리브레이션은 레시피마다 따로 보관됩니다. 카메라 · 렌즈 · 설치 높이를 바꿨다면 반드시 다시 하세요 — 옛 값이 남으면 측정값이 조용히 틀립니다.
  • [Clear Calibration from Recipe] 는 캘리브레이션만 지우고 스텝의 Resolution 은 남깁니다. 완전히 픽셀 단위로 돌리려면 Steps 표의 Resolution 도 0 으로 바꿉니다.
  • Image Rectify 도구의 Undistort 는 Checkerboard · Circles Grid 결과로, Apply Homography 는 N-Point 결과로만 동작합니다(§6.1).

5.10 시퀀스 편집기 — PLC · IO 보드 운전 흐름

AUTO RUN 의 "트리거 대기 → 촬영 → 검사 → 결과 출력 → 반복" 흐름을 노드로 정의합니다. 메뉴 Sequence 로 엽니다. 저장한 시퀀스는 process_sequence.json 에 기록되며 VMS 는 재시작 없이 다음 AUTO RUN 부터 새 시퀀스를 읽습니다.

노드

절차

  1. [디폴트 생성] 으로 기본 흐름(Start → Input Check → Inspection → Branch → Output Action → End)을 만들거나, 팔레트에서 노드를 끌어 놓고 노드 우클릭 → 연결 시작 → 대상 노드 클릭으로 잇습니다.
  2. 각 노드를 선택해 오른쪽 노드 속성에서 디바이스(MainPLC 또는 등록한 IO 보드 Device ID) · 주소 · 값을 입력합니다. IO 보드는 주소 대신 채널 번호(0~N-1) 를 넣고 ON/OFF 신호만 다룹니다.
  3. Reset 신호 주소를 두면 어느 노드에서든 그 조건이 충족될 때 즉시 Start 로 돌아갑니다.
  4. [PLC Monitor] 로 참조 주소의 현재값을 보면서, [▶ 무부하 테스트] 로 카메라 검사만 항상 합격으로 시뮬레이션한 채 트리거 · 분기 · 출력 신호가 설비와 실제로 오가는지 확인합니다. 노드가 진행에 따라 초록/빨강으로 표시되고 Cycle 수가 올라갑니다.
  5. [저장]. 필요하면 [내보내기] 로 파일로 보관하고 다른 PC 에서 [가져오기] 합니다.

5.11 배치 테스트 — 이미지 폴더로 레시피 검증

  1. 메뉴 Batch Test... 를 열고 RECIPE → CAMERA → STEP 을 고릅니다.
  2. INPUT 에 이미지 폴더(하위 폴더 재귀 가능), OUTPUT 에 CSV 리포트 경로와 실패 케이스 오버레이 저장 여부를 정합니다.
  3. [Run Batch] — PROCESSED · PASS · FAIL · AVG TIME 이 실시간으로 집계되고 Results 탭에 파일별 결과가 쌓입니다. 실패 행을 더블 클릭하면 Failure Browser(원본 · 오버레이 좌우 비교, ← → 이동)가 열립니다.
  4. [Edit Thresholds...] — 도구별 Must Succeed(실패 시 즉시 FAIL)와 결과 값의 Min..Max 범위 임계치를 정해 판정 기준을 검증합니다.
  5. [Auto-tune...] — 도구 파라미터를 From · To · Step 으로 훑으며(또는 Random search) 폴더 전체 PASS 율이 가장 높은 조합을 찾고 [Apply Best] 로 도구에 적용 · 저장합니다.
  6. 골든셋 — [Save as Golden] 으로 지금 결과를 정답으로 저장하면 이후 배치 결과가 자동 비교되어 달라진 케이스를 알려 줍니다. 레시피를 고친 뒤 회귀 확인에 씁니다.

5.12 기타 설정 창

Camera Manager

VisionSetup 에서 직접 촬영할 카메라를 등록합니다. 운전용 카메라 구성은 시스템 설정 마법사(3장)가 기준이며, 여기서는 편집 작업에 쓸 카메라를 관리합니다.

Inference Settings — 딥러닝 추론 엔진

ONNX Runtime 의 실행 백엔드(Auto · CPU · CUDA · TensorRT)를 고릅니다. GPU 가 없으면 CPU 로 자동 동작합니다. TensorRT 캐시 폴더를 두면 두 번째 실행부터 엔진 재빌드를 건너뛰고, FP16 은 RTX 계열에서 속도를 높입니다. 변경은 다음 모델 로드부터 적용됩니다.

OCR Synth Data — 합성 문자 데이터

날짜 · 로트 번호처럼 형식이 정해진 문자열을 폰트 · 배경 · 증강을 조합해 대량 생성합니다. OCR 도구의 인식 모델을 다듬을 학습 데이터로 쓰며, PP-OCR 학습 카드는 AI 학습 도구가 설치된 PC 에서만 표시됩니다.

SLM Recipe Bot

툴바의 말풍선 버튼으로 엽니다. 모델에 [Connect] 한 뒤 "원형 부품의 지름을 재고 싶어" 처럼 입력하면 레시피 구성을 제안하고, [Apply Recipe] 로 작업 공간에 만들어 줍니다. "자동 실행" 을 켜면 적용 직후 실행 결과까지 알려 줍니다.
