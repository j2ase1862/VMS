8. 생산 관리 웹 (BODA.VMS.Web)

⚙ 이 장은 관리 화면을 사용하는 관리자 · 반장 · 사무실 담당자용입니다. 현장에서 검사만 수행하는 작업자는 읽지 않아도 됩니다.

BODA.VMS.Web 은 별도 프로그램 설치 없이 브라우저(Chrome)로 접속합니다. 주소창에 http://서버주소:5292 를 입력하세요 (라인 PC 안의 동봉 서버라면 http://localhost:5292). 화면 위쪽에 메뉴 막대가 있고, 각 메뉴를 누르면 하위 항목이 펼쳐집니다. 좁은 화면(태블릿)에서는 왼쪽 위 ☰ 로 메뉴를 엽니다.

8.1 로그인 · 회원가입 · 비밀번호

  1. 아이디와 비밀번호를 입력하고 [로그인] 을 누릅니다. 처음 설치한 서버의 관리자 계정은 admin 입니다(비밀번호는 설치 시 지정, §2.3).
  2. 로그인 유지(기본 해제)를 켜면 브라우저를 닫아도 최대 30 일 동안 로그인이 유지됩니다. 끄면 브라우저를 닫거나 8 시간이 지나면 다시 로그인합니다. 벽걸이 모니터에 안돈 보드를 상시 띄우는 PC 는 켜고, 여러 사람이 쓰는 PC 는 끕니다.
  3. "아이디 또는 비밀번호가 잘못되었거나 승인 대기 중입니다" 는 세 경우를 구분하지 않는 안내입니다. 가입 직후라면 관리자 승인을 기다리세요. 5 회 연속 실패하면 15 분 동안 잠깁니다.

회원가입과 승인

  • 로그인 화면의 "회원가입" 으로 계정을 신청합니다. 비밀번호는 8 자 이상 + 대/소문자 · 숫자 · 특수문자 중 3 종, 또는 10 자 이상 + 2 종이어야 합니다.
  • 신청한 계정은 승인 대기 상태이며, 관리자가 시스템 관리 → 사용자 승인에서 역할(Guest / User / Admin)을 정해 승인해야 로그인할 수 있습니다(§8.22). 신청이 들어오면 관리자에게 알람이 생깁니다.

비밀번호 변경

관리자가 비밀번호를 초기화하면 임시 비밀번호가 발급됩니다. 임시 비밀번호로 로그인하면 비밀번호 변경 화면으로 자동 이동하며, 바꾸기 전에는 다른 화면을 쓸 수 없습니다. 현재 비밀번호 · 새 비밀번호 · 확인을 입력하고 [비밀번호 변경] 을 누릅니다.

모든 화면에 공통

  • 권한이 없는 화면에 들어가면 "이 화면에 접근할 권한이 없습니다" 안내와 [대시보드로 돌아가기] 가 표시됩니다(로그인 상태는 유지).
  • 삭제는 항상 확인 창을 거치며 되돌릴 수 없습니다. 이력이 참조하는 항목(작업지시가 있는 제품, 출근 이력이 있는 작업자 등)은 삭제 대신 비활성화하도록 안내합니다.
  • 이름 · 코드 중복은 "무엇이 겹쳤는지" 사유와 함께 거절됩니다. 목록이 200 건에서 잘리면 그 사실을 화면에 표시합니다.
  • Ctrl + 마우스 휠로 화면을 확대할 수 있습니다. 다크 모드는 브라우저별로 기억됩니다.

8.3 대시보드

공장 전체 현황을 한 화면에 보여 줍니다. 검사 결과나 라인 상태가 바뀌면 새로 고침 없이 갱신됩니다.

최근 7일 생산 추세전체 · 합격 · 불량 꺾은선(데이터 2 일 이상일 때).

8.4 안돈 보드

벽걸이 모니터용 전체 화면 현황판입니다. 현장 모니터링 → 안돈 보드를 누르면 새 탭으로 열리며 로그인이 그대로 이어집니다. 30 초마다 자동 갱신되고 알람 · 라인 상태 변화는 즉시 반영됩니다.

  • 라인 카드 — #번호 · 상태(RUNNING / IDLE / DOWN) · 라인 이름 · 진행 중 작업지시와 진척률(없으면 "활성 작업지시 없음") · Total / Pass / NG / NG%. 미해제 알람이 있으면 ⚠ 띠, Critical 은 점멸합니다.
  • 오른쪽 패널 — TODAY 검사 수 · Pass · NG · NG Rate, 활성 알람 목록, 예측 사전 경보(예측 NG율 10% 이상 "위험", 5~10% "주의"), 마지막 갱신 시각과 실시간 연결 상태(Live / Offline).
상시 표시 PC 는 로그인할 때 "로그인 유지" 를 켜 두세요. 브라우저를 껐다 켜도 로그인 화면 대신 현황판이 뜹니다.

8.5 알람

  • 불량(NG)이 올라오면 검사마다 Major 알람이 자동으로 생깁니다("NG @ 라인 — Recipe …", 메시지에 NG 코드 · Lot · 시리얼). 라인의 생존 신호가 끊기면 Offline 알람이 생기고 복구되면 자동으로 해제됩니다. 회원가입 신청도 Info 알람으로 올라옵니다.
  • 기본 필터는 미확인입니다. 처리 상태(미확인 · 확인됨 · 해제됨) · 심각도(치명 · 중대 · 경미) · 유형(NG 발생 · 오프라인 · 기타)으로 추립니다.
  • 확인 — "봤다"는 표시입니다. 미확인 건수(ALM 배지)에서 빠집니다. NG 알람은 자동 해제가 없어 쌓이므로 헤더의 [모두 확인] 으로 한 번에 처리할 수 있습니다.
  • 해제 — 조치 내용(원인 · 조치 · 재발 방지)을 입력해야 종결됩니다. 해제자 · 시각 · 조치 내용이 목록에 남습니다.
  • 확인 · 해제는 User 이상만 할 수 있습니다. 알람은 품질 기록이라 삭제되지 않습니다.

8.6 생산 이력

  1. 라인 · 작업지시 · LOT(작업지시를 먼저 고르면 활성) · 시작일 · 종료일(기본 최근 7 일) · 결과(합격 / 불량)를 고르고 [조회].
  2. 요약 카드에 기간 총 검사 · 양품 · NG · 평균 불량률이 표시되고, 목록에는 번호 · 라인 · 레시피 · WO / LOT · 결과 · NG 코드 · 검사 시각이 나옵니다. 시작일과 종료일을 같은 날로 두면 하루치만 봅니다.
  3. NG 행(또는 사진이 있는 OK 행)의 [상세] 를 누르면 불량 상세 창이 열립니다 — 라인 · 레시피 · NG 코드 · 검사 시각, NG 사진, 도구별 측정값(도구 · 유형 · 측정값 · 최소 · 최대 · 결과).
  4. [Excel 내보내기] 는 현재 필터의 결과를 xlsx 로 저장합니다(User 이상).
  • 검사 사진이 보이려면 라인 PC 의 Image Save Settings 에서 "NG 이미지 Web 전송" 이 켜져 있어야 합니다(§4.6). 사진 열람은 로그인한 사용자만 가능합니다.
  • 네트워크가 끊겼다가 복구되어 몇 시간치가 한꺼번에 올라와도 검사한 시각으로 기록됩니다.
  • 검사 이력은 읽기 전용입니다 — 수정하거나 지울 수 없습니다.

8.7 작업 지시

작업지시는 계획됨 → 진행 중 → 완료 → 종료 순서로만 진행되며 되돌릴 수 없습니다. 라인 PC 에서 첫 검사 결과가 도착하면 자동으로 진행 중이 되고, 계획 수량에 도달하면 자동으로 완료됩니다.

작업지시 등록

  1. [작업 지시 등록] 을 누릅니다(User 이상). 지시 번호는 WO-YYYYMMDD-NNN 으로 자동 채번됩니다.
  2. 제품과 생산 라인을 고릅니다. 제품에 기본 레시피가 있으면 첫 레시피 줄이 자동으로 채워집니다.
  3. 레시피 줄에 레시피와 계획 수량을 넣습니다. 여러 제품이 섞여 흐르는 라인은 [레시피 추가] 로 줄을 더해 레시피별 계획 수량을 따로 둘 수 있습니다(혼합 레시피 작업지시). 같은 레시피를 두 줄에 넣을 수는 없습니다.
  4. 완료 기준 — "총 생산 수량"(기본)은 판정과 무관하게 검사한 개수, "양품 수량"은 합격 수량이 계획에 도달할 때 완료됩니다. 계획 시작일 · 비고는 선택입니다.

행 버튼

버튼표시 조건동작
시작계획됨진행 중으로 바꿉니다(라인에서 첫 결과가 오면 자동으로도 바뀜).
완료진행 중수동 완료. 그 라인의 VMS 도 즉시 검사를 멈추고 완료 창을 띄웁니다.
종료완료영구 마감. 이후 검사 결과를 받지 않습니다.
LOT항상이 작업지시의 Lot 목록 창(아래).
수정 / 삭제계획됨수정은 User 이상, 삭제는 Admin. 생산이 시작된 뒤에는 제품 · 라인을 바꿀 수 없고 수량 · 비고만 고칠 수 있습니다. Lot 이나 검사 이력이 있으면 삭제 대신 종료 처리합니다.

Lot 발행과 마감

  • [LOT] → 로트 창에서 [로트 발행] 을 누르면 {날짜}-{지시번호}-{순번} 번호의 Lot 이 "진행중" 으로 만들어집니다. 한 작업지시에 여러 Lot 을 동시에 열어 둘 수 있습니다.
  • 묶음 생산이 끝나면 행의 자물쇠 아이콘으로 마감합니다. 마감한 Lot 은 VMS 의 Lot 콤보에서 수 초 안에 사라집니다. 종료된 작업지시에는 Lot 을 추가할 수 없습니다.
  • VMS 에서는 열린 Lot 이 1 개면 자동 선택되고, 여러 개면 작업자가 Ctx 의 Lot 콤보에서 골라야 검사가 그 Lot 에 귀속됩니다(§4.3).

수량이 올라가지 않는 경우

완료 · 종료된 작업지시, 다른 라인에 배정된 작업지시, 작업지시에 없는 레시피, 다른 작업지시의 Lot 으로 올라온 검사는 이력에는 남지만 수량에는 집계되지 않으며 라인 PC 의 System Log 에 경고가 남습니다(§4.7).

8.8 제품

제품 코드(고유, 예: PRD-A001) · 제품명 · 사양 · 기본 레시피를 등록합니다. 작업지시를 만들 때 여기 등록된 제품 중에서 고르며, 기본 레시피는 작업지시 등록 시 자동으로 채워집니다. 작업지시가 참조하는 제품은 삭제할 수 없고 "비활성화" 로 목록과 신규 작업지시에서 숨깁니다(이력은 유지).

8.9 작업자

  • 작업자 마스터 — 사번 · 이름 · 부서 · 등급(Operator 일반 작업자 / Lead 반장 / Supervisor 관리자) · PIN(4~8 자리 숫자). 등급은 VMS 화면에서 무엇을 볼 수 있는지를 정합니다(§4.12). 수정 시 PIN 을 비워 두면 기존 PIN 이 유지됩니다. 출근 이력이 있는 작업자는 삭제할 수 없으며 "사용 안 함" 으로 바꾸면 열린 세션도 함께 닫힙니다.
  • 출근 이력 — 라인 · 기간으로 조회. 출근 · 퇴근(근무 중이면 "근무중") · 근무 시간 · 종료 사유(로그아웃 · 교대 변경 · 자동 종료). 라인 PC 가 정전 등으로 사라지면 마지막 생존 신호 시각으로 자동 종료됩니다. 최신 200 건까지 표시됩니다.
  • 키오스크 링크 — 라인별 키오스크 주소(/kiosk/라인번호). 라인 단말기 브라우저에 전체 화면으로 띄워 두면 작업자가 사번 · PIN 으로 출근 · 교대 · 퇴근을 할 수 있습니다(로그인 불필요).

8.10 레시피 파라미터 (검사 기준값)

레시피의 검사 기준값(파라미터)을 Web 에서 관리하는 화면입니다. VisionSetup 의 도구 설정에서 파라미터 코드를 연동해 두면(§5.7), 현장에서 도구 설정을 열지 않고 여기서 값만 고쳐도 라인 PC 가 1 분 안에 받아 씁니다. 조회는 User 이상, 편집은 Admin 만 할 수 있습니다.

  1. 화면 위에서 라인을 고른 뒤 레시피를 고릅니다. 레시피는 라인별로 관리됩니다.
  2. VisionSetup 에서 만든 레시피는 같은 이름으로 자동 등록되어 목록에 나타납니다. Web 에서 먼저 만들 때는 [레시피 등록] 으로 이름 · 설명을 넣습니다(대상 라인이 안내됩니다).
  3. [프리셋 추가] — Pattern Tool(점수 · 각도 · 배율 · 위치, 7 개) / Blob Tool(임계값 · 면적 기준과 공차 · 개수 기준과 공차, 7 개) / Dimension Tool(기준값 · 공차, 3 개)을 한 번에 만듭니다. 미리보기에서 코드 범위를 확인하고 [n개 추가] 를 누른 뒤 각 행의 값을 입력합니다.
  4. [항목 추가] — 분류(Pattern / Blob / Dimension) · 파라미터 코드(레시피 안에서 고유한 숫자) · 값 · 설명 · 단위 · 규격 하한(LSL) · 규격 상한(USL) · 활성. LSL/USL 을 둘 다 넣으면 SPC 관리도에서 Cp/Cpk 를 계산할 수 있습니다.
  5. [레시피 복사] 는 파라미터까지 통째로 "이름 - 복사본" 을 만들고, [이름 변경] 은 이름을 바꿉니다. 작업지시가 참조하는 레시피는 삭제할 수 없습니다.
Blob Tool 프리셋의 7 개 항목은 VisionSetup Blob 도구의 연동 콤보와 1:1 로 맞춰져 있어, 프리셋으로 추가하면 바로 연동할 수 있습니다.

8.11 파레토 분석

"불량의 대부분은 소수의 원인에서 나온다"는 원리로 개선 우선순위를 찾는 화면입니다. 기간(기본 최근 7 일, 최대 366 일) · 라인 · 상위 N(5~50)을 고르고 [실행] 을 누르면 NG 코드별 건수 · 비중 · 누적이 표로 나오고, 누적선이 80% 에 닿기 전까지의 코드가 개선 우선 대상입니다. 마스터에 없는 코드는 "(미등록 — 불량 코드에 추가 필요)" 로 표시됩니다.

8.12 SPC 관리도

  1. 라인 → 레시피 → 파라미터 코드를 차례로 고릅니다. 규격 상하한이 설정된 파라미터에는 "규격 설정됨" 표시가 붙습니다.
  2. 부분군 크기 n(2~10, 기본 5)을 정하고 [계산] 을 누릅니다. 측정값은 검사 결과와 함께 라인 PC 가 올린 값입니다.
  3. X̄ 관리도와 R 관리도에서 가운데 실선은 중심선(평균), 위아래 점선은 관리 한계선(UCL/LCL)입니다. 점이 한계선을 벗어나면 설비 · 자재 · 조건 변화 같은 특별 원인이 생긴 신호이므로 원인을 확인합니다.
  4. Cp/Cpk 는 규격 상하한(USL/LSL)이 있어야 계산되며 1.67 이상 우수, 1.33 이상 양호, 1.00 미만은 즉시 조치가 필요합니다.

8.13 불량 코드

  • 코드 · 설명 · 분류(패턴 매칭 · 블롭 분석 · 치수 · 표면 · 기계 · 기타) · 심각도(치명 · 중대 · 경미)를 등록합니다.
  • 라인에서 올라온 NG 코드가 마스터에 없으면 화면 위에 미등록 NG 코드 카드가 나타나며, 카드를 누르면 값이 채워진 등록 창이 열립니다(최근 7 · 30 · 90 일).
  • 한 번 만든 코드 값은 바꿀 수 없고, 이력이 참조하면 지울 수 없습니다. 더 쓰지 않을 코드는 "사용 안 함" 으로 바꿉니다.

8.14 교대 리포트

기간 · 라인을 고르고 [실행] 하면 교대별 총 검사 · 합격 · 불량 · 불량률 카드와 일자 × 교대 표가 나옵니다. 교대는 시스템 관리 → 교대 마스터(§8.21)에 정의된 시간대로 자동 배정됩니다.

8.15 PDF 리포트

일간(1 일) · 주간(월~일) · 월간 리포트를 A4 PDF 로 내려받습니다. 전체 KPI, 라인별 OEE 표, 파레토 상위 10 개 불량 코드, 교대조별 집계(교대 데이터가 있을 때)가 들어갑니다. 파일명은 BODA_VMS_Daily_YYYYMMDD.pdf 형식입니다.

8.16 비전 클라이언트 (라인)

  • 라인 PC 가 처음 연결되면 자동으로 등록됩니다. [클라이언트 등록] 으로 미리 만들 수도 있습니다 — 라인 이름 · IP 주소 · 라인 인덱스(0~99). 한 서버에 최대 100 대까지 등록됩니다.
  • 행의 [보기] 를 누르면 오른쪽에 그 라인의 레시피 → 스텝 → 도구 트리가 표시됩니다. 온라인 여부는 라인 PC 의 생존 신호로 실시간 갱신됩니다.
  • 검사 이력이 있는 라인은 삭제할 수 없습니다.

8.17 OEE 설비종합효율

OEE = 가용성 × 성능 × 품질입니다. 가용성 = (가동 + 대기) / 기간, 성능 = 가동 / (가동 + 대기), 품질 = 합격 / 전체. 상태 로그가 없는 시간은 정지로 봅니다. 기간 · 라인을 고르고 [계산] 을 누르면 라인별 카드가 나오며, 85% 이상이 세계적 수준입니다. 라인이 13 대 이상이면 카드 대신 표 모드(정렬 · 목표 미달만 · Excel(CSV) 저장)가 기본입니다.

8.18 설비 신뢰성 (MTBF / MTTR)

설비 상태 로그에서 정지(Down) 전이를 고장으로 세어 MTBF(평균 고장 간격) = Σ가동시간 / 고장 횟수, MTTR(평균 수리 시간) = Σ정지시간 / 고장 횟수, 가용성 = MTBF / (MTBF + MTTR) 을 계산합니다. MTBF 는 길수록, MTTR 은 짧을수록 좋습니다.

8.19 예방 보전

  • PM 일정 — [일정 등록]: 일정 이름 · 설명 · 라인(비우면 전체 공통) · 주기(일) · 예상 소요(분) · 다음 수행 예정. 상태는 지연 · 오늘 예정 · 임박 · 정상으로 표시됩니다.
  • 임박 — 7 일 이내 예정 카드. [수행 기록] 으로 바로 기록합니다.
  • 수행 이력 — 기간 조회. 수행 시각 · 일정 · 라인 · 수행자 · 소요 · 비고. 수행 기록 창에서는 공통 일정일 때 수행 라인을 고르고 실제 소요 시간과 비고를 적습니다.

8.20 불량률 예측

최근 검사 흐름을 학습한 예측 모델이 다음 1 시간의 불량률을 추정합니다. 60 초마다 자동 갱신되며, 예측값은 VMS 헤더의 예측 칩과 안돈 보드의 사전 경보에도 표시됩니다. 모델이 등록되지 않은 서버는 "활성 ML 모델이 등록되지 않았습니다" 배너가 뜨고 예측이 표시되지 않습니다(모델 등록과 재학습은 서버 관리 도구 tools/register_model.py · tools/retrain_pipeline.py 로 합니다).

8.21 교대 마스터 (Admin)

교대 이름 · 시작 시각 · 종료 시각(0~23 시)을 등록합니다. 종료가 시작보다 앞서면 야간 교대로 자정을 넘깁니다. 활성 교대끼리 시간대가 겹칠 수 없고, 검사 이력이 있는 교대는 삭제할 수 없습니다.

8.22 사용자 승인 (Admin)

  • 승인 대기 — 가입 신청 목록. [Guest 승인] · [User 승인] · [Admin 승인] 중 하나로 역할을 정해 승인하거나 [거부] 합니다(거부 시 계정 삭제).
  • 전체 사용자 — 역할 칩을 눌러 역할을 바꾸고, [비밀번호 초기화](임시 비밀번호가 한 번만 표시) · [삭제] 를 할 수 있습니다. 자기 자신과 마지막 Admin 은 강등 · 삭제할 수 없습니다.

8.23 감사 로그 (Admin)

기준 정보(작업지시 · 제품 · 작업자 · 레시피 · 불량 코드 · 교대 · 사용자 · 라인 등)를 누가 언제 만들고 고치고 지웠는지, 로그인 · 로그아웃 · 잠금 같은 인증 사건과 함께 남깁니다. 비밀번호 · PIN 은 마스킹되며 기록은 수정 · 삭제할 수 없습니다.

8.24 SW 라이선스 (Admin)

서버에 설치된 라이선스(상태 · 고객 · 라이선스 ID · 좌석 사용/계약)와 각 라인 PC 가 점유한 좌석(클라이언트 번호 · 호스트 · 지문 · 마지막 갱신)을 30 초마다 갱신해 보여 줍니다. 좌석은 72 시간 동안 갱신이 없으면 자동 해제됩니다. 계약 좌석을 초과하면 경고 배너가 뜹니다(현재는 운전 제한 없음). 서버 지문 코드는 라이선스 발급 요청에 씁니다(§2.6).

8.25 시스템 설정 (Admin)

애플리케이션 버전 · 플랫폼 · DB 종류를 확인하고, VisionServer 연동(사용 여부 · 기본 URL)을 저장합니다. VisionServer 를 쓰지 않는 일반 현장은 "단독 모드: 모든 변경이 로컬 DB 에 직접 저장" 상태로 둡니다.

8.26 라인 PC 와 서버가 맞물리는 방식

단계무슨 일이 일어나는지
작업자 로그인VMS 가 사번 · PIN 을 서버로 보내면 서버가 작업자 명단과 대조해 세션을 만듭니다. 세션은 작업자 → 출근 이력 탭에 즉시 나타납니다.
작업지시 선택VMS 가 이 라인의 작업지시 목록을 받아 옵니다. 선택하면 레시피가 자동 로드되고 열린 Lot 이 채워집니다.
검사 결과 업로드사이클마다 결과(판정 · 측정값 · 추적 4 필드 · 검사 시각)가 올라가고, 서버는 작업지시 · Lot 수량을 올려 응답합니다. 헤더 진행률과 Web 작업 지시 화면이 즉시 갱신됩니다.
오프라인 복구서버에 닿지 못한 결과는 라인 PC 의 업로드 큐에 파일로 보관되었다가 연결이 돌아오면 순서대로 재전송됩니다. 재시작해도 남습니다. 같은 사이클이 두 번 도착해도 수량은 한 번만 오릅니다.
완료계획 수량 도달 시 서버가 완료 처리하고 라인 PC 에 알려 검사가 멈춥니다. Web 에서 수동 완료해도 같습니다.
생존 신호VMS 가 주기적으로 신호를 보냅니다. 15 초 이상 끊기면 라인이 오프라인으로 바뀌고 Offline 알람이 생기며 열린 작업자 세션이 자동 종료됩니다. 복구되면 알람은 자동 해제됩니다.

8.27 여러 라인 · 여러 서버 운영

  • 라인 PC 는 설정 마법사의 라인 번호(0~99)로 구분되며, 같은 서버 안에서 번호가 겹치면 안 됩니다. 작업지시 · 레시피 · 작업자 세션은 라인별로 분리됩니다.
  • 공장 네트워크 사정으로 서버를 여러 대 두고 라인을 나누어 붙일 수도 있습니다. 이때 라인 번호는 십의 자리를 서버 번호로 쓰기를 권장합니다 — 0~9 시험 · 예비, 10~19 1 번 서버, 20~29 2 번 서버 … 90~99 9 번 서버. 나중에 서버를 합치거나 보고서를 모을 때 어느 라인인지 구분됩니다.
  • 서버를 나누면 대시보드 · 작업지시 · 품질 분석 · 백업 · 관리자 계정 · 기준 정보도 서버마다 따로입니다. 네트워크가 허락하면 서버 1 대 구성이 운영이 가장 단순합니다.
  • 한 PC 에 카메라가 여러 대 있으면 VMS 를 인스턴스 이름으로 두 개 띄워 두 라인으로 운용할 수 있습니다(§11.5).
