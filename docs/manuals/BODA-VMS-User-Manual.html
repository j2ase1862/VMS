BODA VMS 사용자 매뉴얼

버전 2.0 · 2026-09-01 · Vision Management System + Web MES 통합 — 앱별 구성 개편판

1. 시스템 개요

BODA VMS 는 두 프로그램으로 구성된 통합 시스템입니다. 현장 PC 의 VMS 클라이언트가 카메라로 제품을 검사하고, 관리 서버인 BODA.VMS.Web 이 검사 결과 · 작업지시 · 작업자 · 알람을 한곳에서 관리합니다. 두 프로그램은 네트워크로 자동 연동되며, 검사 결과와 알람은 실시간으로 서버 화면에 반영됩니다.

1.2 운영 흐름 한눈에

  1. VMS 를 실행하면 카메라가 자동으로 연결되고, Web 서버와의 연결 상태가 헤더에 표시됩니다.
  2. 작업자가 헤더의 [Login...] 버튼을 눌러 사번과 PIN 으로 로그인합니다. 입력한 정보는 Web 서버의 작업자 명단과 대조됩니다.
  3. 로그인하면 이름과 권한 뱃지(Operator / Lead / Supervisor)가 표시되고 [Work Orders] 버튼이 활성화됩니다.
  4. [Work Orders] 를 눌러 오늘 작업할 작업지시를 선택합니다.
  5. 작업지시를 선택하면 검사 레시피가 자동으로 불러와지고 [AUTO RUN] 버튼이 켜집니다.
  6. [AUTO RUN] 을 누르면 검사가 시작됩니다. 진행 수량은 헤더에 실시간으로 표시됩니다 (예: 5/100).
  7. 계획 수량을 다 채우면 완료 알림 창이 뜨고 검사가 자동으로 멈춥니다. 이어서 다음 작업지시를 바로 선택할 수 있습니다.
  8. 검사 결과는 건마다 Web 서버에 자동 저장되고, 불량(NG)이 나오면 관리자 화면에 즉시 알람이 표시됩니다.

2. 설치 / 배포

⚙ 이 장은 설치 담당자/관리자용입니다. 현장에서 검사만 수행하는 작업자는 3장(VMS 클라이언트 매뉴얼)부터 읽으면 됩니다.

2.1 VMS 클라이언트 (MSI)

설치 파일(MSI, 약 850MB) 하나만 실행하면 설치가 끝납니다. 실행에 필요한 구성 요소 (.NET 8 런타임 · Visual C++ 런타임)가 모두 동봉되어 있어, 인터넷이 안 되는 PC 에서도 다른 프로그램을 먼저 설치할 필요가 없습니다. 카메라/IO 보드 벤더 소프트웨어만 예외입니다 (아래 요구사항).

설치

  1. BODA-VMS-1.1.0.msi 더블 클릭.
  2. Welcome → Install Folder (기본 C:\Program Files\BODA VMS\) → Install. 설치 마법사는 BODA 브랜드 화면으로 표시되며, 별도의 라이선스 동의 단계는 없습니다.
  3. 설치 폴더 다음의 "설치 구성 선택" 화면에서 "BODA VMS Web 서버 포함" 체크박스를 선택합니다 (기본: 켬, 권장). 이 PC 를 관리 서버로도 쓸 계획이 없으면 해제해 파일 설치를 생략할 수 있습니다. 포함해서 설치해도 자동 실행되지 않으며(서비스 수동 등록 상태), 관리 서버로 쓸 때만 설치 후 §2.2 의 설정 마법사 방법으로 켭니다. ⚙ 무인 설치에서 제외하려면: msiexec /i VMS-버전.msi INSTALLWEB=0
  4. 완료 시 시작 메뉴 + 데스크톱 바로가기 자동 생성.

제거

  • 제어판 → 프로그램 및 기능 → "BODA VMS" → 제거
  • 또는 시작 메뉴의 "Uninstall BODA VMS" 바로가기

업그레이드 (v1.1 → v1.2)

새 MSI 더블 클릭하면 이전 버전을 자동 제거 후 새 버전 설치 (UpgradeCode 동일 유지). 로컬 설정 파일과 카메라 보정 등은 %LocalAppData% 에 저장되어 보존됩니다.

요구사항: Windows 11 x64. .NET 8 런타임과 Visual C++ 런타임은 MSI 에 동봉되어 별도 설치가 필요 없습니다. 사용하는 장비에 따라 다음만 별도 설치하세요:
  • Basler 카메라 — pylon Camera Software Suite(Runtime). 미설치 시 카메라 검색은 되지만 연결/촬영이 실패합니다.
  • ADLink IO 보드 — DASK x64 드라이버 (32-bit 만 설치된 PC 에서는 보드 인식 불가).
  • PLC(Mitsubishi · Siemens · LS · Omron · Modbus)는 TCP 직접 통신이라 드라이버가 필요 없습니다. Mech-Eye 3D 카메라 구동 파일은 MSI 에 동봉됩니다.

2.2 Web 서버 (설치 / 구성)

Web 서버는 Windows 서비스로 설치되어 부팅 시 자동 시작됩니다. 별도의 웹 서버 프로그램(IIS 등)은 필요 없습니다. 켜는 방법은 두 가지입니다 — VMS 와 같은 PC 에서 운영한다면 설정 마법사 방법이 가장 쉽습니다.

방법 A — 설정 마법사로 켜기 (VMS 와 같은 PC, 권장)

MSI 설치의 "설치 구성 선택" 화면에서 Web 서버를 포함했다면(§2.1 기본값) 명령어 없이 화면에서 바로 구성할 수 있습니다:

  1. System Setup(설정 마법사)을 실행하고 두 번째 페이지로 이동합니다.
  2. "Web 서버 초기 구성 (이 PC)" 카드에서 관리자(admin) 계정으로 쓸 비밀번호를 입력하고 구성 버튼을 누릅니다.
  3. 서버 구성과 서비스 시작이 자동으로 진행되고, 완료되면 카드에 "구성 완료" 상태가 표시됩니다.
  • 구성은 끝났는데 서비스가 멈춰 있으면(Stopped) 카드에 [서비스 시작 (관리자 권한)] 버튼이 나타납니다. 누르면 Windows 권한 확인 창(UAC)이 뜨고, 승인하면 서비스가 부팅 시 자동 시작으로 바뀐 뒤 곧바로 시작되어 응답까지 확인해 줍니다.

방법 B — 배포 스크립트로 설치 (별도 서버 PC)

VMS 와 다른 PC 를 관리 서버로 쓰는 구성입니다. Web 서버 배포 패키지(zip)는 설치 매체(USB)에 MSI 와 함께 제공됩니다 — 없거나 새 버전이 필요하면 공급사(BODA Vision AI)에 요청하세요. 패키지를 서버 PC 의 원하는 폴더에 풀고 관리자 PowerShell 에서 실행합니다:

# 관리자 PowerShell 에서 — 압축을 푼 폴더로 이동
cd <압축 푼 폴더>\deploy
.\Install-Web.ps1

기본값: 설치 폴더 C:\Program Files\BODA VMS Web\, 포트 7144 (HTTPS), 서비스 이름 BODA-VMS-Web, 부팅 시 자동 시작 (실패 시 5초 후 자동 재시작 3회).

옵션 변경:

.\Install-Web.ps1 -Port 8443 -InstallPath "D:\BODA Web"

제거

.\Uninstall-Web.ps1

SQLite DB 는 보존 ($env:LOCALAPPDATA\BODA\VMS). 완전 삭제 시:

Remove-Item "$env:LOCALAPPDATA\BODA\VMS" -Recurse

2.4 첫 실행 전 체크리스트

  1. Web 서버 먼저 시작 → 브라우저로 https://<서버IP>:7144 접속 확인.
  2. 관리자 계정으로 회원가입 → 승인 (현재 첫 사용자가 자동 Admin).
  3. Operators 페이지에서 작업자 마스터 등록 (사번 + PIN + Role).
  4. Products / Recipes / Work Orders 1건 이상 등록.
  5. VMS 클라이언트 설치 후 첫 실행 → AppSetup 마법사에서 WebServerUrl = https://<서버IP>:7144, ClientIndex = 1, 2, 3... 라인별 지정. 입력란 라벨 옆의 파란 물음표(?)에 마우스를 올리면 각 항목의 설명이 표시됩니다.
  6. 마법사 마지막 Security & License 단계에서 현장(운영) PC는 Production을 그대로 두고 [Finish]로 저장합니다. 보안 모드가 저장되어 있지 않으면 VMS가 시작 시 "보안 정책 오류"를 표시하고 실행되지 않습니다. 같은 화면 아래의 SW 라이선스 카드 사용법은 §2.6을 참고하세요.
  7. VMS 실행 → 시작 화면 헤더에 Heartbeat 정상 표시 확인.

2.6 SW 라이선스 설치·활성화

⚙ 이 절은 설치 담당자/관리자용입니다. 라이선스는 설치할 때 한 번만 넣으면 되고, 일반 작업자는 신경 쓸 일이 없습니다.

SW 라이선스는 "이 PC에서 BODA VMS를 사용해도 된다"는 사용권 파일 (license.lic)입니다. 인터넷 연결 없이 파일 하나로 동작하므로, 공장 내부망(폐쇄망)에서도 추가 설정이 필요 없습니다.

지금은 라이선스가 없어도 사용에 제한이 없습니다 (도입 전환기). 라이선스가 없으면 상태 표시와 기록에 "미설치" 경고만 남습니다. 향후 버전부터 라이선스가 필수가 될 예정이니, 신규 설치 시 함께 활성화해 두는 것을 권장합니다.

라이선스는 어떻게 받나요 — 지문 코드

라이선스는 PC마다 발급됩니다. 발급에 필요한 것은 그 PC의 지문 코드 하나뿐입니다 — 0X0Y9-MMS36-7540K 처럼 생긴 15자 코드로, 전화로 불러줄 수 있을 만큼 짧습니다. 지문 코드는 System Setup(설정 마법사) 마지막 페이지의 "SW 라이선스" 카드에서 확인하고 [복사]할 수 있습니다.

활성화 절차 (한 PC에서 쓰는 경우)

  1. System Setup(설정 마법사)을 실행하고 마지막 페이지(Security & License)로 이동합니다.
  2. "SW 라이선스" 카드의 지문 코드를 [복사] 버튼으로 복사해 본사 담당자에게 전달합니다 (전화·메신저·이메일 모두 가능).
  3. 본사에서 발급한 license.lic 파일을 받아 USB 등으로 이 PC에 옮깁니다. 라이선스 파일은 이 PC에서만 유효하므로, 옮기는 경로는 자유롭게 선택해도 됩니다.
  4. [라이선스 파일 가져오기...] 버튼을 누르고 받은 파일을 선택합니다. 파일 검사 후 자동으로 설치되며, 권한이 필요한 경우 Windows 권한 확인 창(UAC)이 뜨면 [예]를 누릅니다.
  5. 카드의 현재 상태가 정상 으로 바뀌면 완료입니다.

서버 1대 + 여러 클라이언트로 쓰는 경우

Web 서버가 있는 구성이라면 라이선스는 서버 PC에만 설치하면 됩니다. 각 라인의 VMS 클라이언트는 서버에서 자동으로 사용권(좌석)을 받아 가므로 별도 작업이 없고, 클라이언트 PC를 교체해도 라이선스를 다시 받을 필요가 없습니다. 좌석이 몇 개 사용 중인지는 Web 관리 화면에서 확인합니다 (§7.18).

서버가 꺼져 있어도 클라이언트는 마지막으로 좌석을 받은 시점부터 72시간(3일) 동안 정상 동작합니다 — 서버 점검이나 일시 장애로 생산이 멈추지 않도록 한 여유 시간입니다.

이런 경우에는 재발급이 필요합니다

  • "지문 불일치"가 표시되는 경우 — 라이선스가 다른 PC용으로 발급되었거나, PC 부품 교체·Windows 재설치로 지문이 크게 바뀐 경우입니다. 화면의 지문 코드를 본사에 전달하고 재발급을 요청하세요.
  • "만료 임박" / "유지보수 만료"가 표시되는 경우 — 계약 갱신 후 새 라이선스 파일을 받아 같은 방법으로 가져오기 하면 됩니다 (덮어쓰기 설치).

3. 시스템 구성 (VMS.AppSetup)

⚙ 이 장은 설치 담당자/관리자용입니다. System Setup(설정 마법사)은 카메라 · PLC · IO 보드 · Web 연동 · 보안 · 라이선스 등 시스템 전체 구성을 저장하는 프로그램입니다. 일반 작업자는 사용할 일이 없습니다.

3.1 실행 방법과 저장 동작

System Setup 은 다음 세 가지 경로로 실행합니다:

  • 최초 실행 자동 — VMS 를 설치 후 처음 실행하면(설정 파일이 없으면) 마법사가 자동으로 열립니다. 저장을 마친 뒤 VMS 를 다시 실행하세요.
  • VMS 에서 실행 — 사이드 패널 External Tools 의 [System Setup] 버튼 (Supervisor · Admin 전용, §4.3).
  • 다중 인스턴스 — 한 PC 에서 두 라인을 운용할 때는 VMS.AppSetup.exe --instance 이름 으로 실행합니다 (§8.5).

마법사는 총 7단계이며, 마지막 단계에서 [Finish] 를 누르면 설정 파일 (system_config.json)에 저장됩니다. 저장한 설정은 VMS 를 다시 시작할 때 반영됩니다 — 운전 중이라면 검사를 멈추고 VMS 를 재시작하세요. 각 입력란 라벨 옆의 파란 물음표(?) 아이콘에 마우스를 올리면 그 항목의 설명이 표시됩니다.

Web 서버 없이 쓰는 현장: 2단계 Web Server Integration 카드의 "Web 서버 미사용 — 단독(Standalone) 모드" 를 체크하면 작업자 로그인 · 작업지시 없이 검사를 운전할 수 있습니다 (§4.5).
"고급 설정" 은 해당 현장만 펼칩니다: 2단계 Web Server Integration 카드 아래의 고급 설정 — Web Client API Key · MLOps 모델 레지스트리 는 두 종류 현장에서만 씁니다. Web Client API Key 는 Web 서버 관리자가 API 키 강제를 켠 경우(값을 틀리게 넣으면 Web 연동이 끊깁니다), MLOps 서버 주소 · MLOps 라인 토큰 은 MLOps 서버를 운영해 모델을 레지스트리에서 내려받거나(§5.10) 불량 사진을 학습 데이터로 모으는(§4.3 Image Saving) 현장입니다. 라인 토큰(ln_…)은 MLOps 관리 화면에서 라인마다 발급해 그대로 붙여 넣습니다. 그 밖의 현장은 접힌 채로 두세요.
3단계에서 노출·게인·3D 옵션은 설정하지 않습니다: 3단계 카메라 카드는 이름 · IP · 카메라 타입 · 제조사(와 라인 스캔 · 프레임 그래버 항목)만 다룹니다. 노출(Exposure) · 게인(Gain)과 3D 취득 옵션(점군 후처리 필터, 깊이 Z 범위)은 VMS 메인의 카메라 스텝 설정 또는 VisionSetup 레시피 스텝(§5.3)에서 조정하며, 기본은 카메라에 저장된 현재 값을 그대로 씁니다. 카드 아래에 같은 내용의 안내 문구가 표시됩니다.

4. 검사 운전 (VMS 메인)

빠른 시작 — 검사를 시작하는 가장 짧은 길
  1. 헤더의 Operator [Login...] 버튼을 누르고 사번과 PIN 을 입력합니다.
  2. [Work Orders] 버튼을 눌러 오늘 작업할 작업지시를 더블 클릭으로 선택합니다.
  3. 레시피가 자동으로 불러와지고 [AUTO RUN] 버튼이 켜집니다.
  4. [AUTO RUN] 을 누르면 검사가 시작됩니다. 멈추려면 같은 자리의 빨간 [STOP] 을 누릅니다.
  5. 진행 상황은 헤더의 WO 칩(예: 5/100)과 사이드 패널의 Recent Inspections 에서 확인합니다.
각 버튼과 화면 요소의 자세한 설명은 아래 4.1 ~ 4.3 을 참고하세요.

4.1 첫 실행 화면

VMS 를 실행하면 다음 순서로 화면이 나타납니다:

  1. 시작 화면(Splash)이 표시되는 동안 카메라를 자동으로 찾아 연결합니다.
  2. 시스템 사용자 로그인 창이 표시됩니다 (엔지니어·관리자용). 선택
  3. 메인 화면이 표시됩니다: 헤더 + KPI 스트립(생산 현황 요약) + 카메라 화면 + 시스템 로그 + 사이드 패널(접힘).

KPI 스트립 — TACT TIME 카드 읽는 법

KPI 스트립의 TACT TIME 카드는 [AUTO RUN] 으로 연속 검사가 도는 동안 "한 검사가 끝나고 다음 검사가 시작되기까지의 간격"을 보여줍니다. 수동으로 한 건씩 검사할 때는 갱신되지 않습니다 — 사람이 기다린 시간이 섞여 설비 속도로 오해할 수 있기 때문입니다. 카드에는 PROC N ms 가 함께 표시되는데, 이것은 마지막 검사 1건을 처리하는 데 걸린 순수 시간입니다.

4.2 헤더 — 운영 흐름

헤더의 버튼과 표시는 왼쪽에서 오른쪽으로 실제 작업 순서대로 배치되어 있습니다: 작업자 로그인 → 작업지시 선택 → 검사 시작(AUTO RUN).

4.2.1 Operator 로그인

로그인 전에는 [Login...] 버튼만 표시됩니다.

  1. [Login...] 을 클릭하면 로그인 창이 열립니다 (사번 + PIN).
  2. 입력한 사번과 PIN 을 Web 서버의 작업자 명단과 대조합니다.
  3. 성공하면 칩이 "김기동 (1003) Lead [Logout]" 형태로 바뀝니다.

4.2.2 Work Orders 버튼

작업자 로그인 후 사용할 수 있습니다. 클릭하면 Web 서버에서 작업지시 목록을 불러와 창으로 보여줍니다.

  • 상태 필터 — 활성(Planned + InProgress) / 전체 / Planned / InProgress / Completed 로 추려 볼 수 있습니다.
  • 목록 항목 — 작업지시 번호, 제품, 레시피, 진행(예: 5/100), 상태, 계획 시작 시각.
  • 원하는 작업지시를 더블 클릭하거나 [Select] 버튼으로 선택합니다.

4.2.3 WO 칩 (진행률 표시)

선택한 작업지시가 헤더에 표시되고, 검사 1건이 끝날 때마다 진행 수량이 실시간으로 올라갑니다.

WO: WO-20260522-001 · A001 (5/100)  [▰▰▱▱▱▱▱▱]
  • 진행 수량은 작업지시의 완료 기준(§7.7)을 따릅니다 — 총 생산 기준이면 검사한 개수가, 양품 기준이면 "양품 80 / 100" 처럼 합격 수량이 표시됩니다.
  • 혼합 레시피 작업지시(§7.7)는 칩에 마우스를 올리면 레시피별 진행이 줄 단위로 표시됩니다 (예: "R-A: 30/60 (NG 2)").
  • 계획 수량이 0 인 작업지시는 진행률 막대가 표시되지 않습니다.
  • 작업지시가 완료되면 선택이 자동으로 해제되고, 다음 작업지시 선택 창이 열립니다.

4.2.4 Recipe 칩

현재 사용 중인 레시피 이름이 표시됩니다. 작업지시를 선택하면 그 작업지시에 지정된 레시피가 자동으로 불러와지고, 카메라 설정과 Web 파라미터도 함께 맞춰집니다. PC 에 없는 레시피는 Web 서버에서 받아 온 뒤 다시 시도합니다.

검사(AUTO RUN)가 도는 중에 비전 설정(VMS.VisionSetup)에서 이 레시피를 고쳐 저장하면, 레시피 칩에 주황 변경 대기 배지가 나타납니다 — 검사를 멈추면 자동으로 다시 불러와 적용되고, 멈추기 전까지는 이전 설정으로 계속 검사합니다 (§4.3).

4.2.5 Ctx (Inspection Context)

검사 결과와 함께 서버에 기록되는 추적 정보 4가지입니다. 대부분 자동으로 채워집니다:

필드채움 방식비고

4.2.6 AUTO RUN

검사를 시작하는 메인 버튼입니다. 시작 조건(§4.5)을 모두 만족하면 청록색으로 활성화되고, 검사가 실행되는 동안에는 같은 자리가 빨간 [STOP] 버튼으로 바뀝니다.

4.2.7 Role 뱃지

Operator 칩 안에 작업자의 권한이 뱃지로 표시됩니다:

  • Operator — 기본, 뱃지 없음
  • Lead — 반장. 파란 뱃지.
  • Supervisor — 관리자. 주황 뱃지.

4.2.8 하단 상태바 — 설비 연결 상태

화면 맨 아래 상태바에는 시스템 상태(Running/정지)와 설비 연결 상태가 왼쪽부터 순서대로 표시됩니다: 시스템 상태 → CAM n/m(카메라) → PLC → IO 보드 → Web.

  • CAM n/m — 등록된 카메라 중 연결된 대수입니다. 전부 정상이면 초록, 일부만 연결되면 주황, 전부 끊기면 빨강 점으로 표시됩니다.
  • IO n/m — IO 보드를 등록해서 쓰는 구성(§4.8)에서만 표시됩니다. 예: IO 1/2 는 보드 2대 중 1대 연결. 하나라도 연결에 실패하면 빨간 점 + 빨간 글씨로 바뀌며, 실패 사유는 System Log 의 [IoBoard] 항목에서 확인합니다 (§10.1). 보드 상태는 자동 운전을 시작하는 시점에 갱신됩니다.
  • 운전을 시작했는데 작업지시 수량이 집계되지 않는 상태면 시스템 상태가 "Running — 경고: Web 미연동 (작업지시 수량 미집계)" 로 표시됩니다 (§10.1).

4.2.9 불량률 예측 칩 — "다음 1시간: …"

헤더에 다음 1시간 예상 불량률 칩이 상시 표시됩니다. Web 서버의 예측 모델이 최근 생산 이력을 바탕으로 계산한 값으로, 불량률이 올라가는 추세를 검사 중에 미리 알아차리는 용도입니다.

  • 예측 모델이 등록되어 있지 않으면 칩에 "모델 미등록" 으로 표시됩니다 — 고장이 아니며, 예측 기능을 쓰지 않는 현장에서는 무시해도 됩니다.
  • 예측의 근거 데이터와 상세 분석은 Web 의 Reports 화면에서 확인합니다 (§7.16).

4.3 사이드 패널 (Settings)

헤더 오른쪽 끝의 톱니바퀴(⚙) 아이콘으로 열고 닫습니다. 열 때 시스템 사용자 로그인이 필요합니다. 각 섹션 제목 옆의 파란 물음표(?) 아이콘에 마우스를 올리면 그 섹션이 무엇을 하는 곳인지 설명 창이 열립니다. 설명이 길면 창을 클릭해 크게 볼 수 있고, X 를 누르면 닫힙니다.

카메라 촬영 조작 — 카메라 화면의 설정(톱니바퀴) 창

사진 촬영(Grab)과 실시간 영상(Live)은 각 카메라 화면의 설정(톱니바퀴) 창에서 조작합니다 — 카메라 단위 조작은 그 카메라 화면 옆에서 하는 방식입니다:

  • [Grab] — 사진을 한 장 촬영합니다. 검사(AUTO RUN)가 멈춰 있을 때만 사용할 수 있고, 라이브 영상이 도는 중에는 눌리지 않습니다. 촬영해도 지금 보고 있던 화면 탭(2D / Depth Map / Point Cloud)은 그대로 유지됩니다.
  • [Live] — 카메라 영상을 실시간으로 계속 표시하거나 멈춥니다 (시작/정지 토글).
  • [Grab] / [Live] 버튼이 눌리지 않을 때는 마우스를 올리면 이유가 말풍선으로 표시됩니다 — 예: 검사 시작/정지 권한이 없음, 작업자 로그인이 필요함, 카메라가 연결되지 않음. [Grab] 도 [Live] 와 같은 권한 기준을 따릅니다.
  • 연결 끊김 감지 · 자동 재연결 — 운전이나 대기 중에 카메라 케이블이 빠지면 몇 초 안에 감지되어 카메라 화면의 연결 점이 빨간색(Disconnected)으로 바뀌고, 하단 상태바의 CAM 수도 함께 줄어듭니다. 케이블을 다시 꽂으면 별도 조작 없이 다음 촬영(Grab / Live / 검사)에서 자동으로 다시 연결됩니다. Live 표시는 연결이 끊기거나 촬영이 연속으로 실패하면 스스로 멈춥니다 — 예전처럼 마지막 화면이 그대로 멈춰 있는 무증상 정지가 생기지 않습니다.

노출 · 게인 설정 — 같은 설정 창에서 촬영 밝기를 조절합니다:

  • 카메라 설정 유지 체크박스 (기본: 체크) — 체크되어 있으면 카메라에 저장된 노출/게인을 그대로 사용합니다. 카메라 제조사 프로그램(예: Mech-Eye Viewer, pylon Viewer)에서 튜닝해 둔 값이 보존됩니다. 해제하면 아래에 입력한 값을 촬영 전에 카메라에 적용합니다.
  • Exposure — 노출 시간을 숫자로 직접 입력합니다. 단위는 ms(밀리초)로, 카메라 제조사 프로그램과 같은 단위입니다 (예: 200 = 200ms).
  • Gain — 게인(dB)을 숫자로 직접 입력합니다.
  • 설정 창에서도 [Live] 로 실시간 영상을 보면서 값을 맞출 수 있고, 스텝별 노출/게인 설정을 저장할 수 있습니다.
  • [Save Parameter] — 입력한 값을 저장합니다. 저장이 끝나면 완료/실패 결과 메시지가 표시되고, 카메라가 아직 등록되어 있지 않으면 System Setup(설정 마법사)을 먼저 실행하라는 안내가 표시됩니다.
  • Basler 카메라도 여기서 설정한 스텝별 노출/게인이 그대로 적용됩니다. 연결할 때 카메라의 자동 노출/자동 게인이 꺼져서, 촬영할 때마다 밝기가 달라지는 현상이 생기지 않습니다. 제조사 프로그램(pylon Viewer)에서 맞춰 둔 값을 쓰려면 "카메라 설정 유지" 체크를 그대로 두면 됩니다.

비전 설정에서 저장하면 자동으로 반영됩니다: 비전 설정(VMS.VisionSetup)에서 지금 사용 중인 레시피를 고쳐 저장하면, 실행 중인 VMS 가 자동으로 다시 불러옵니다 — 상태바에 "외부 변경 반영 완료"가 표시되며 따로 할 일이 없습니다. 검사(AUTO RUN)가 도는 중이라면 안전을 위해 바로 바꾸지 않고, 헤더 레시피 칩에 주황 변경 대기 배지가 표시됩니다 — 검사를 멈추면 자동으로 다시 불러와 적용됩니다 (§4.2.4).

Image Saving 섹션 Admin 전용

검사 판정 이미지(양품/불량)의 저장과 Web 전송을 설정합니다. [Image Save Settings] 버튼을 누르면 설정 창이 열립니다:

  • 저장 — 양품(OK) / 불량(NG) 이미지 저장 여부, 저장 경로, 보존 기간(일)을 정합니다. 저장 경로 아래에 날짜별 {연월일}\OK / {연월일}\NG 폴더가 자동으로 만들어지고, 보존 기간보다 오래된 폴더는 시작 시 자동 삭제됩니다 (0 = 무제한).
  • Web 연동 (생산 이력) — Web 의 생산 이력 상세 창(§7.6)에서 검사 사진을 보려면 여기서 전송을 켜야 합니다:
    • 전달 모드 — Auto(권장)를 그대로 두세요. Auto/Upload 는 아래 전송 옵션에 따라 Web 으로 업로드합니다 — VMS 와 Web 서버가 같은 PC 여도 업로드합니다. SharedPath 는 전송하지 않는 모드라 생산 이력에 이미지가 표시되지 않으므로 선택하지 마세요.
    • OK 이미지 Web 전송 / NG 이미지 Web 전송 — 판정별 전송 여부입니다. 로컬 저장 체크와는 별개입니다 — NG 사진을 Web 에서 보려면 "NG 이미지 Web 전송"을 켜야 합니다.
    • 전송 화질 — 기본 Thumbnail(썸네일)은 대역폭과 서버 용량을 아낍니다. 원본이 필요하면 Full 로 바꿉니다.
  • MLOps 학습 데이터 수집 — 불량으로 판정된 사진을 원본 해상도 그대로 MLOps 데이터 풀에 올려, 웹에서 라벨링해 다음 모델을 학습하는 재료로 씁니다. 위의 Web 전송(사람이 보는 썸네일)과는 별개의 스위치이며 검사 속도에는 영향이 없습니다:
    • NG 이미지 MLOps 전송 — 기본은 꺼짐입니다. 켜면 NG 사진이 MLOps 의 데이터 관리 화면에 출처 "라인 NG" 로 쌓입니다.
    • 양품 샘플 비율 — 양품 N 장에 1 장을 함께 보냅니다(기본 200). 모델이 "정상" 도 배우려면 정상 사진이 조금은 있어야 합니다. 0 이면 양품은 보내지 않습니다.
    • 카드 아래 안내 문구를 확인하세요 — MLOps 서버 주소와 라인 토큰이 설정 마법사 2단계 고급 설정(§3)에 없으면 체크해도 전송되지 않으며, 화면이 그 사실을 먼저 알려 줍니다.
    • 서버가 꺼져 있으면 사진은 이 PC 에 쌓였다가(재시작해도 유지) 서버가 켜지면 순서대로 올라갑니다. 서버가 파일을 받지 않은 사진은 다시 보내지 않고 %LocalAppData%\BODA VISION AI\mlops_line_ng_queue ejected 에 사유 파일과 함께 남습니다.

Recent Inspections 섹션

최근 검사 결과를 VMS 안에 최대 200건까지 보관해 보여줍니다. Web 연결이 끊겨 있어도 작업자가 바로 확인할 수 있습니다.

  • 요약 통계 — Total / Pass / NG 건수와 합격률(Pass rate).
  • 최근 목록 — 시각, OK / NG 판정, 시리얼 · 작업지시 · 레시피, NG 코드.
  • [전체 이력] 버튼 — 이 PC 에 저장된 검사 이력 전체를 조회하는 창을 엽니다 (아래 설명).
  • [Clear] 버튼으로 목록을 비웁니다 (저장된 이력은 지워지지 않습니다).
VMS 를 다시 시작하면 이 목록은 비워집니다. 재시작 후에도 남는 전체 이력은 [전체 이력] 버튼으로 여는 생산 이력 조회 창에서, Web 연동 현장이라면 Web 의 Production History(§7.6) 화면에서도 조회할 수 있습니다.

생산 이력 조회 창 — [전체 이력]

검사 결과는 사이클(AUTO RUN) 또는 수동 검사 1건마다 이 PC 의 검사 이력 파일 (%LocalAppData%\BODA VISION AI\inspection_history.db)에 자동으로 저장됩니다. Web 서버 없이 운전하는 단독 모드(§4.5)에서도 남는 영구 이력이며, Web 연동 현장에서는 오프라인 백업 역할을 합니다. 저장은 백그라운드에서 이루어져 검사 속도에 영향이 없습니다.

  1. Recent Inspections 섹션의 [전체 이력] 버튼을 누릅니다. (버튼이 비활성이면 관리자 Retention Settings 에서 검사 이력 저장이 꺼진 상태입니다 — §9.4)
  2. 필터를 고르고 [조회]를 누릅니다 — From / To 날짜(기본 최근 7일), 판정(전체 / PASS / NG), 레시피(기간 안에 검사한 레시피 목록), NG 코드(NG 코드 또는 실패한 도구 이름 포함 검색). [필터 초기화]로 되돌립니다.
  3. 탭에서 원하는 보기를 고릅니다.
    • 이력 목록 — 검사 시각, 판정, 레시피, NG 코드/실패 도구, 구분(사이클/수동), 소요 ms, 추적(시리얼 · 작업지시 · Lot), IMG(이미지 있음). 행을 클릭하면 오른쪽 상세에 도구별 결과 표(도구 · 종류 · 결과 · ms · 메시지)와 저장된 검사 사진이 표시되고 [폴더 열기]로 파일 위치를 열 수 있습니다.
    • 일별 집계 — 기간 전체의 총 검사 · PASS · NG · 수율 카드와 날짜별 표.
    • NG 파레토 — NG 원인(NG 코드 또는 도구 이름)별 건수 · 비율 · 누적 비율 순위.
  4. 목록이 200건을 넘으면 하단의 [◀ 이전] / [다음 ▶] 으로 페이지를 넘깁니다.
  5. [CSV 내보내기] — 현재 필터의 전체 결과(화면에 보이는 페이지만이 아님)를 CSV 로 저장합니다. Excel 에서 바로 열리며 한글이 깨지지 않습니다.
검사 사진이 함께 보이려면 사이드 패널의 Image Saving(OK/NG 이미지 저장)이 켜져 있어야 합니다. 저장 옵션이 꺼져 있던 기간의 이력은 "저장된 이미지 없음"으로 표시됩니다. NG 사이클은 그 사이클에서 찍힌 NG 사진을 우선해서 연결합니다. 이미지 파일이 보존 정리로 삭제된 뒤에는 경로만 남습니다.
보존 기간은 기본 90일이며 VMS 를 시작할 때 오래된 이력이 자동으로 정리됩니다. 기간 변경과 저장 켜기/끄기는 관리자 → Admin Tools → Retention Settings 의 "검사 이력" 행에서 합니다(§9.4). 이 파일은 Backup / Restore 에 포함됩니다.

4.5 AUTO RUN 활성화 조건

[AUTO RUN] 버튼은 다음 조건을 모두 만족해야 켜집니다:

  1. 카메라가 1대 이상 연결되어 있어야 합니다.
  2. 시스템 사용자에게 검사 시작/정지 권한이 있어야 합니다 (시스템 사용자 미로그인 시 기본 허용).
  3. (Web 연동 환경) 작업자가 로그인되어 있어야 합니다.
  4. (Web 연동 환경) 작업지시가 선택되어 있고, 상태가 Planned 또는 InProgress 여야 합니다.

버튼이 꺼져 있을 때 마우스를 올리면 이유가 말풍선으로 표시됩니다.

Web 없이 단독으로 운전하기 (Standalone 모드)

생산 이력 관리 없이 검사만 필요한 현장은 Web 서버 없이 VMS 를 단독으로 쓸 수 있습니다:

  1. System Setup(설정 마법사)의 Web Server Integration 카드에서 "Web 서버 미사용 — 단독(Standalone) 모드" 를 체크하고 저장합니다.
  2. VMS 를 다시 시작하면 헤더의 작업자 로그인 칩과 [Work Orders] 버튼이 사라지고, 위 3 · 4번 조건(작업자 로그인 · 작업지시 선택) 없이 AUTO RUN 을 시작할 수 있습니다.
  3. 하단 상태바의 Web 칩은 "단독 모드 (Web 미사용)" 으로 표시됩니다 — 고장이 아닙니다.
단독 모드의 검사 이력: 검사 결과는 Web 에 업로드되지 않는 대신 이 PC 의 검사 이력 파일에 사이클마다 자동 저장됩니다(기본 90일 보존). 최근 결과는 VMS 화면의 Recent Inspections(최대 200건, 프로그램 재시작 시 비워짐)와 대시보드의 NG 이력에서, 재시작 후에도 남는 전체 이력은 같은 섹션의 [전체 이력] 버튼으로 여는 생산 이력 조회 창(§4.3)에서 기간 · 판정 · 레시피별 조회, 일별 집계, NG 파레토, CSV 내보내기를 할 수 있습니다. NG 행에는 실패한 도구 이름이 NG 코드 대신 표시됩니다. 검사 사진까지 함께 보려면 사이드 패널의 Image Saving(OK/NG 이미지 저장, §4.3)을 켜 두세요. 작업지시 · Lot 단위 생산 관리와 여러 PC 의 이력 통합이 필요해지면 언제든 설정 마법사에서 체크를 해제하고 Web 서버 주소를 입력해 연동 모드로 전환할 수 있습니다.
운전 중 이미지 획득에 실패하면 그 사이클은 NG 입니다: 케이블 분리 등으로 카메라에서 이미지를 받지 못한 사이클은 검사 없이 불합격(NG)으로 집계됩니다 — 카메라 카드의 판정 배지가 NG 로 표시됩니다. 예전처럼 직전 화면의 이미지로 검사를 계속하지 않으므로, NG 가 연속으로 나오면 카메라 연결부터 확인하세요 (§10.1).

4.8 시퀀스 운전 — PLC · IO 보드

⚙ 이 절은 설비를 연동하는 엔지니어/설치 담당자용입니다. 현장에서 검사만 수행하는 작업자는 읽지 않아도 됩니다.

자동 운전(AUTO RUN)의 "트리거 대기 → 검사 → 결과 출력 → 반복" 흐름은 시퀀스로 정의합니다. 트리거와 결과 신호는 PLC 로 주고받는 것이 기본이지만, PLC 없이 디지털 IO 보드만으로도 같은 운전이 가능합니다.

시퀀스 편집기 열기

비전 설정(VMS.VisionSetup) 상단 메뉴의 [Sequence] 를 클릭하면 Sequence Editor 창이 열립니다. 왼쪽의 노드 팔레트에서 노드를 놓고 연결해 흐름을 만들고, 오른쪽 노드 속성 패널에서 각 노드의 장치 · 주소 · 조건을 입력합니다. 저장한 시퀀스는 VMS 를 다시 시작할 필요 없이, 다음번 자동 운전을 시작할 때 자동으로 다시 읽어 반영됩니다.

IO 보드 등록 (System Setup)

System Setup(설정 마법사)의 IO Board Configuration 페이지에서 보드를 등록합니다 — 제조사(ADLink / Advantech), 모델, 디바이스 ID(시퀀스에서 이 보드를 부르는 이름), Board ID(같은 모델이 여러 장일 때 몇 번째인지), 입력/출력 채널 수를 입력합니다. 각 입력란의 파란 물음표(?)에 설명이 있습니다.

지원하는 IO 보드와 필요한 드라이버는 다음과 같습니다:

제조사지원 모델드라이버
ADLinkPCI-7432 (입력 32 + 출력 32) · PCI-7433 (입력 64) · PCI-7434 (출력 64) · PCI-7396DASK x64 드라이버 별도 설치
AdvantechPCI-1730 / 1733 / 1734 / 1735 / 1736 · PCI-1750 / 1751 / 1752 / 1753 / 1754 / 1756 / 1758 계열 DAQNavi 별도 설치 (미설치 시 시뮬레이션 보드로 대체 동작)
  • 채널 번호는 0 부터 셉니다 (예: PCI-7433/7434 는 채널 0~63).
  • 보드 드라이버는 64비트(x64)용을 설치해야 합니다 — VMS 가 64비트 프로그램이기 때문입니다 (§10.1).

시퀀스에서 IO 보드 쓰기

  • 노드 속성에서 디바이스로 IO 보드를 고르면 주소 입력란이 "채널 번호 (0 ~ N-1)" 로 바뀝니다 — PLC 주소(X0, M100 등) 대신 채널 번호 정수를 입력합니다 (예: 0, 5, 15).
  • IO 보드는 ON/OFF(Bit) 신호 전용입니다 — 숫자(Word) 읽기/쓰기가 필요한 노드는 PLC 를 사용하세요.

트리거는 BitRisingEdge 로 (스위치 · 센서)

트리거 대기 노드(InputCheck)의 체크 모드는 다음 중에서 고릅니다:

  • BitOn / BitOff — "지금 신호가 켜져(꺼져) 있는가"를 봅니다. 스위치를 누르고 있는 동안 매 사이클 트리거가 반복 성립하므로, 버튼 · 센서 트리거에는 적합하지 않습니다.
  • BitRisingEdge (권장) — 신호가 꺼짐→켜짐으로 바뀌는 순간에만 성립합니다. 스위치를 길게 눌러도 1회 누름 = 1회 검사가 보장됩니다. BitFallingEdge 는 반대 방향(켜짐→꺼짐)입니다.
  • 디바운스 (ms) — 에지 모드에서 전환을 감지한 뒤 입력한 시간만큼 기다렸다가 신호가 유지되는지 한 번 더 확인합니다. 기계식 스위치의 떨림(채터링)으로 인한 오탐을 막습니다 (0 = 사용 안 함).

무부하 테스트 · 모니터 — 라인을 세우지 않고 점검

Sequence Editor 툴바의 버튼으로 만든 시퀀스를 실제 설비 신호와 함께 미리 검증할 수 있습니다. PLC 가 없는 구성이라도 등록된 IO 보드만으로 동작합니다:

  • [PLC 연결] — PLC 와 등록된 IO 보드를 함께 연결합니다. 연결 결과가 상태 문구로 표시됩니다 (예: "장치 연결 성공: IO 보드 2대").
  • [▶ 무부하 테스트] — 시퀀스를 실제로 돌리되 카메라 검사만 항상 합격으로 시뮬레이션합니다. 트리거 · 분기 · 출력 신호가 설비와 실제로 오가므로 배선과 흐름을 라인 가동 없이 확인할 수 있습니다. 캔버스의 노드가 진행 상태에 따라 초록/빨강으로 표시됩니다.
  • [PLC Monitor] — 하단 모니터 패널을 열어 신호 값을 실시간으로 봅니다. IO Board Monitor 표에는 시퀀스가 참조하는 보드 채널별 현재값이 표시됩니다.

운전 중 오류가 나면

  • 시퀀스 노드에서 오류가 나면 System Log 에 [AutoProcess] 출처로 "시퀀스 '노드명' 노드 오류 — 사유"가 기록되고, 5초 후 자동으로 재시도합니다.
  • IO 보드 연결 실패는 하단 상태바의 IO 칩(§4.2.8)이 빨갛게 바뀌고, System Log 의 [IoBoard] 항목에 사유가 남습니다 (§10.1).

⚙ 이 장은 검사 레시피를 만드는 엔지니어용입니다. 현장에서 검사만 수행하는 작업자는 읽지 않아도 됩니다.

5.2 3D 검사 — 객체 검출 · 점군 측정

3D 객체 검출 — 딥러닝으로 찾고, 점군으로 잰다

3D 카메라로 찍은 점군(Point Cloud)에서 원하는 객체만 골라내어 개수를 세고 크기를 재는 검사입니다. 원리는 간단합니다 — "어디에 있는지"는 2D 사진에서 딥러닝으로 찾고, "얼마나 큰지"는 3D 점군에서 잽니다.

  1. 모델 준비 (AI 학습 도구 — 별책, §6) — 3D 카메라가 함께 찍는 2D 사진을 모아 Segmentation 유형으로 라벨링하고 학습합니다. SAM 을 쓰면 클릭만으로 윤곽이 그려집니다. 실제 검사와 같은 위치 · 조명에서 찍은 사진으로 학습해야 정확합니다.
  2. 윤곽 검출 (YOLO Seg 도구) — 학습한 모델 파일을 지정하면, 촬영된 2D 사진에서 객체마다 정확한 윤곽(마스크)을 찾아냅니다.
  3. 점군 잘라내기 (Point Cloud Mask Crop 도구) — 찾은 윤곽 안쪽에 해당하는 점들만 점군에서 잘라냅니다. 배경 · 바닥은 사라지고 객체의 점만 남습니다.
  4. 개수 · 치수 측정 (Point Cloud Cluster 도구) — 남은 점들을 덩어리(클러스터)로 나눠 객체 개수를 세고, 덩어리마다 가로 · 세로 · 높이 치수를 잽니다. 덩어리 사이의 거리도 잴 수 있습니다.
빠른 시작: 위 구성은 예제 템플릿 "DL 세그 기반 3D 객체 검출" 을 선택하면 한 번에 만들어집니다. 모델 파일 지정과 값 조정만 하면 됩니다.
  • mm 단위 환산 (XY 캘리브레이션) — 점군의 가로 · 세로 값을 mm 로 바꿔 줍니다. 3D 카메라의 내부 정보로 자동 환산하는 것이 기본이고, 수동으로 환산 값을 입력할 수도 있습니다.
  • 여러 갈래로 나눠 검사 — 마스크 크롭을 여러 갈래(브랜치)로 나눠 각각 다른 대상을 잘라낸 뒤 합쳐서(Union) 볼 수 있고, 크롭 · 클러스터 결과는 2D 화면 위에도 겹쳐(오버레이) 표시됩니다.

점군 화면에서 바로 재기 (측정 툴바)

Point Cloud 화면 상단 가운데에 측정 툴바가 있습니다. 도구를 만들지 않아도 화면에서 바로 거리와 각도를 확인할 수 있습니다:

  • [Distance] — 점 2개를 클릭하면 두 점 사이 거리를 표시합니다.
  • [Angle] — 점 3개를 클릭하면 각도를 표시합니다 (두 번째 점이 꼭짓점).
  • [Clear] — 측정 결과를 모두 지웁니다.

점군 화면 조작 — 표시 밀도 · 회전 · 줌

  • 표시 밀도 — 고해상도 3D 카메라의 점군(수백만 점)도 기본으로 전부 표시됩니다. 화면이 무겁게 느껴지면 뷰 툴바의 밀도 버튼을 눌러 자동 → 전체 → 1/2 → 1/4 순서로 표시 밀도를 바꿀 수 있습니다.
  • 회전 — 마우스 드래그로 회전하면 점군의 중심을 축으로 턴테이블처럼 돌아갑니다. 수평이 유지되어 화면이 뒤집히지 않습니다.
  • 줌 — 마우스 휠 한 칸에 조금씩(2%) 확대/축소됩니다. Ctrl 을 누른 채 휠을 돌리면 절반(1%)씩 움직여 더 정밀하게 맞출 수 있습니다. Depth Map 화면도 같은 방식으로 동작합니다.

5.3 스텝 관리와 카메라 설정

스텝별 카메라 설정 (Camera Settings 패널)

비전 설정에서 스텝을 선택하면 그 스텝이 사용할 카메라 파라미터(노출 등)를 바로 편집할 수 있습니다. 2D 이미지 보존, Depth 표시 색상(컬러/그레이) 등 카메라 종류에 맞는 항목이 표시됩니다. 노출 · 게인과 3D 취득 옵션(점군 후처리 프리셋, 깊이 범위)은 스텝이 소유합니다 — System Setup 3단계(§3)에는 이 항목이 없으며, "카메라 설정 유지"(기본 켬)를 끈 스텝에서만 여기 값이 촬영 직전에 카메라에 적용됩니다.

패널의 "스텝 정보" 그룹에서는 스텝에 붙일 정보를 입력합니다:

  • 별칭 — 스텝을 알아보기 쉽게 붙이는 자유 이름입니다 (예: "Node 3"). 입력하면 스텝 목록과 트리에 "1-3 — Node 3" 처럼 이름 옆에 함께 표시됩니다.
  • 로봇 노드 번호 — 로봇이 촬영 위치마다 보내는 번호와 이 스텝을 짝지을 때 입력합니다. 비워 두면 스텝 순서대로 짝지어집니다.

스텝 관리 — 이름 · 별칭 · Steps 그리드

  • 스텝 이름은 자동으로 매겨집니다 — "1-1", "1-2" 같은 이름은 이 PC 에 등록된 카메라 순서를 기준으로 레시피를 불러올 때마다 자동 계산됩니다. 직접 바꿀 수 없으며, 부르기 쉬운 이름이 필요하면 위의 별칭을 쓰세요.
  • 다른 PC 에서 만든 레시피 — 카메라 재연결 창 — 이 PC 에 등록되지 않은 카메라를 쓰는 레시피를 열면 카메라 재연결 창이 먼저 뜹니다. 스텝별로 이 PC 의 카메라를 콤보에서 골라 짝지은 뒤 [적용 및 저장] 을 누르면, 스텝의 도구 · 학습 데이터를 그대로 두고 카메라만 바꿔 바로 사용할 수 있습니다. 창을 건너뛰면 해당 스텝 이름이 "?-1" 처럼 물음표로 표시되며, 나중에 레시피를 다시 열어 재연결하거나 System Setup 에서 같은 카메라를 등록하면 됩니다.
  • Steps 그리드는 선택한 카메라의 스텝만 보여줍니다 — 그리드 제목에 현재 카메라 이름이 표시됩니다 (예: "Steps — Cam1"). 스텝이 안 보이면 카메라를 선택하지 않았거나 그 카메라에 스텝이 없는 것이며, 빈 화면에 어떤 경우인지 안내 문구가 표시됩니다. 레시피를 불러오면 레시피가 쓰는 카메라가 자동으로 선택됩니다.
  • Recipe Manager 의 Step Alias 입력란 — 레시피 관리 창에서도 스텝의 별칭을 고칠 수 있습니다. 자동으로 매겨지는 이름("1-1")은 여기서도 편집할 수 없습니다.

5.4 레시피 · 스텝 · 도구 복사와 이름 변경

비슷한 제품의 검사를 만들 때 처음부터 다시 만들지 않고 세 단위 모두 복사할 수 있습니다:

  • 레시피 복사 — Recipe Manager 에서 레시피를 선택하고 [Duplicate] 를 누르면 스텝 · 도구 · 학습 데이터까지 통째로 복사되어 "이름 - 복사본"으로 만들어집니다 (Web 원장에는 새 이름으로 별도 등록).
  • 스텝 복사 — Steps 패널의 복사 버튼(보라색 아이콘)을 누르면 카메라/조명 설정과 도구 파이프라인(연결 포함)이 복사되어 원본 바로 뒤에 추가됩니다.
  • 도구 복사 — 작업 공간의 도구 탭을 우클릭 → [Duplicate Tool]. 파라미터 · ROI · 학습 데이터까지 복사됩니다. 도구 사이 연결선만 복사되지 않으니 필요하면 새로 이어 주세요.
  • 레시피 이름 변경 — Recipe Manager 의 [Rename] 버튼으로 이름을 바꿉니다. Web 과 연동된 레시피는 Web 쪽 이름이 함께 바뀌지 않으니, 필요하면 Web 검사항목 화면에서도 바꿔 주세요 (§7.9).

5.5 촬영 — Grab · Live · VMS 연동

화면 위 툴바에 카메라 버튼(▶/■ 배지)이 있어, Camera 메뉴에 들어가지 않아도 사진 한 장 촬영(Grab)과 실시간 보기(Live) 시작/정지를 바로 할 수 있습니다. 앱을 켜면 첫 번째 카메라가 자동으로 선택되므로, 카메라 패널을 만지지 않아도 툴바 버튼이 곧바로 동작합니다. 실시간 보기는 장시간 켜 두어도 느려지거나 멈추지 않도록 개선되었습니다.

  • VMS 실행 중에도 바로 촬영 — VMS(운전 프로그램)가 카메라를 잡고 있을 때 비전 설정의 [Acquire] 를 누르면, VMS 에 촬영을 요청해 이미지를 곧바로 받아옵니다 — 예전처럼 VMS 창으로 가서 촬영하고 돌아올 필요가 없습니다. VMS 가 검사(AUTO RUN)나 라이브 중이면 요청이 거절되고 사유가 상태바에 표시됩니다. 요청한 카메라와 다른 카메라의 이미지가 오면 경고가 표시됩니다.
  • 카메라 연결 토글 버튼 — 툴바의 연결 버튼으로 현재 카메라의 연결 상태를 바로 보고(연결 시 초록) 연결/해제할 수 있습니다. VMS 가 실행 중이면 카메라 소유권이 VMS 에 있어 버튼이 비활성화되며, 마우스를 올리면 사유가 표시됩니다.

5.6 측정과 판정

측정값 판정 (Judgment) — 기준값 ± 공차

엣지 간 거리 같은 측정 도구(Geometry)에 Judgment 설정이 있습니다. 기준값과 공차(+/−)를 입력하면 측정값이 범위 안이면 OK, 벗어나면 NG 로 판정되고 결과가 화면 위에 겹쳐 표시됩니다. 단위는 mm 또는 픽셀(px) 중에서 고를 수 있습니다.

  • 캘리브레이션 없이 mm 로 재기 — 카메라 캘리브레이션을 하지 않았다면, 스텝 그리드의 Resolution (mm/px) 값을 입력해 두세요. 측정 도구가 이 값으로 픽셀을 mm 로 환산합니다.
  • 템플릿은 판정까지 연결되어 만들어집니다 — 예제 템플릿의 엣지 간 거리 측정 · Blob 검출 · 컬러 객체 검출은 마지막 Result 판정까지 연결된 상태로 생성되어, 값만 조정하면 OK/NG 판정이 바로 동작합니다.

판정 규칙 — 검출 0건 · 판정 불능은 NG

검사 도구의 판정은 다음 공통 규칙을 따릅니다. "찾아야 할 것을 하나도 찾지 못한 검사"는 합격이 아니라 불합격(NG)으로 처리됩니다:

도구NG 로 처리되는 경우
Blob 검출덩어리가 하나도 검출되지 않은 경우 (면적 0 으로 판정 — 기대 면적 범위를 벗어나 NG). 판정 기준을 따로 넣지 않았어도 검출 유무 자체로 판정
패턴 매칭패턴을 찾지 못했거나 커버리지 판정(§5.7)으로 기각된 경우
딥러닝 객체 검출각도 판정을 켰는데 각도를 계산할 수 없는 경우
딥러닝 세그먼테이션객체가 0건 검출된 경우
코드 판독품질 등급 판정을 켰는데 등급을 산출할 수 없는 경우
운전 공통이미지 획득에 실패한 사이클 (§4.5)

NG 가 예상과 다르게 나오면 결과 화면에서 "무엇이 검출되지 않았는지"를 먼저 확인하세요 — 검출 0건 NG 는 설비 이상이 아니라 판정 규칙에 따른 정상 동작일 수 있습니다.

5.7 패턴 매칭 (Feature Match)

패턴 학습 — 학습 영역 · 마스크 · 기준 이미지

Feature Match 는 제품의 윤곽(엣지)을 학습해 두었다가 검사 이미지에서 같은 패턴의 위치 · 각도 · 크기를 찾는 도구입니다. 좋은 학습이 좋은 검출의 전부이므로, 학습 단계의 보조 기능을 알아 두면 현장 문제 대부분을 예방할 수 있습니다:

  • 학습 영역(ROI) — 제품이 화면에서 기울어 놓였다면 회전 사각형 ROI 로 제품에 맞춰 그리세요. 학습(Train) 시 ROI 각도를 존중해 회전 정렬된 패턴으로 학습됩니다 (Blob 도구도 회전 ROI 가 그린 영역 그대로 분석합니다). 회전 ROI 크기를 조절할 때는 잡은 꼭짓점만 움직이고 반대편 꼭짓점은 고정됩니다. 회전 ROI 로 학습하면 같은 자리의 부품은 ROI 각도만큼 회전한 것으로 검출되는데, Match Align 은 이 학습 ROI 각도를 기준 각도로 쓰므로 같은 장면에서 Δθ 는 0 이 됩니다.
  • 기준 이미지 자동 저장 — [Train] 이 성공하면 학습에 쓴 전체 화면 이미지가 자동 저장됩니다. 설정 화면의 [기준 이미지 불러오기] 버튼으로 그 장면을 다시 띄워 ROI 조정 · 재학습을 할 수 있습니다 — 레시피에는 잘라낸 템플릿만 남기 때문에, 이 버튼이 없던 시절에는 학습 당시 화면을 따로 보관해야 했습니다. 재학습하면 같은 파일에 덮어씁니다 (재학습 원점을 KeepReference 로 두면 덮어쓰지 않습니다 — 아래).
  • 학습 마스크 (Train Mask) — 그림자 · 날짜각인 · 반사처럼 이미지마다 달라지는 영역을 학습에서 제외합니다. [Edit Mask...] 편집기에서 도구(브러시 / 사각형 / 다각형) × 동작(마스크 / 해제 UnMask)을 골라 칠하며, 다각형은 좌클릭으로 꼭지점을 찍고 우클릭(또는 더블클릭)으로 완성합니다 (Esc 취소). Ctrl+휠 또는 [+]/[−] 로 1~8배 확대해 정밀하게 칠할 수 있습니다. 편집기의 엣지 미리보기에서 초록 = 학습에 남는 엣지, 주황 = 제외되는 엣지 입니다 — 제품 자신의 윤곽(그림자와 맞닿은 경계 포함)이 주황으로 바뀌었다면 과하게 칠한 것이니 해제(UnMask)로 되돌리세요. 저장하면 즉시 재학습되어 특징 이미지의 반투명 빨간 영역으로 확인할 수 있습니다.
  • 안정 특징 정제 (자동 마스크) — 현장 샘플 이미지 여러 장(2장 이상 권장)을 선택하면, 이미지마다 흔들리는 엣지(그림자 외곽 · 반사 · 가변 각인)를 자동으로 찾아 학습 마스크에 반영하고 재학습합니다 — 수작업 마스킹을 대신하는 기능입니다.
  • 학습 특징점 수와 Auto Tune — 학습 직후 특징 이미지의 초록 점이 제품 윤곽을 따라 촘촘해야 정상입니다. Auto Tune 을 켜 두면 특징점 상한(Max Model Points)이 검출된 엣지 양에 맞춰 자동 설정됩니다(100~500). 특징점이 60개 미만이면 상태바에 경고가 표시됩니다 — Canny 임계를 낮추거나 학습 영역을 넓히세요. 프로그램을 업데이트한 뒤에는 [Train] 재학습을 해야 새 자동값이 적용됩니다.
  • 360° 전 방향 검색 — 제품이 아무 방향으로나 놓인다면 Angle Start = -180, Angle Extent = 360 으로 설정하세요.

패턴 여러 개 찾기 (Max Instances) · 반쪽 매칭 차단 (Min Coverage)

  • Max Instances — 같은 제품이 화면에 여러 개 있으면(트레이 부품 등) 이 값을 개수 이상으로 올리세요. 점수 순으로 여러 개를 찾아 결과 화면에 #1, #2… 번호와 점수가 표시되고, 결과값에는 찾은 개수(MatchCount)와 인스턴스별 좌표(Match0_…, Match1_…)가 나옵니다. 기본값 1이면 지금까지처럼 1개만 찾으며, ROI 자동 이동 · 얼라인 연결은 1순위 매칭을 그대로 사용하므로 바꿀 것이 없습니다. 붙어 있는 부품이 하나로 합쳐지면 전문가 설정의 NMS Distance 를 낮춰 보세요.
  • Min Coverage — 학습 특징점이 적을 때 패턴이 반쯤 겹친 위치에서 매칭되어 중심 좌표가 어긋나는 일이 생길 수 있습니다. Min Coverage 를 켜면(권장 0.6~0.75) 특징점 일치 비율이 낮은 매칭을 걸러내고, 결과 메시지에 "커버리지 부족으로 기각: Score=…, Coverage=…" 로 사유가 표시됩니다. 기본값 0(끔)이라 기존 레시피 동작은 바뀌지 않습니다. 부품이 자주 일부 가려지는 공정이면 값을 낮춰 조정하세요.

재학습 원점 — 기준 이미지 유지 / 현재 이미지

학습 원점(패턴 중심 좌표와 학습 ROI 각도)은 Match Align 의 기준 포즈이자 Feature Match 결과의 TrainedCenter 값입니다. 이미 학습된 모델을 [Train Selected] 로 다시 학습할 때 이 원점을 어떻게 할지 Models 영역의 재학습 원점 콤보에서 고릅니다:

  • UseCurrentImage (기본) — 원점을 현재 ROI 의 위치 · 각도로 다시 계산하고 기준 이미지도 현재 장면으로 바꿉니다. 부품을 옮겨 놓고 그 위치를 새 기준으로 삼을 때 씁니다. 옮긴 자리에서 다시 Run 하면 Δ 는 0 이 됩니다.
  • KeepReference — 원점 · 기준 각도 · 기준 이미지는 그대로 두고 템플릿 특징만 새로 학습합니다. Match Align 마스터 포즈를 유지한 채 다른 장면(조명 · 로트 차이)으로 특징을 보강할 때 씁니다. ROI 크기를 바꾸면 템플릿 중심 정의가 달라져 미세 오프셋이 생길 수 있으니 크기는 유지하세요.
  • [Add Model] 로 만드는 새 모델은 항상 현재 이미지 기준입니다.

재학습을 마치면 연결된 Match Align 에 대한 안내가 나옵니다 — Match Align 이 학습 기준을 쓰면 상태바에 "기준 원점이 현재 이미지 학습 위치로 갱신됨" 또는 "기준 이미지 그대로 유지됨"이 표시되고, 수동 기준(학습 기준 사용 해제 + Ref X/Y/θ 직접 등록)을 쓰고 있으면 [현재 매칭을 기준으로 등록] 으로 원점을 다시 등록하라는 경고 창이 뜹니다. 수동 기준은 이전 템플릿으로 매칭한 포즈를 기록한 값이라 템플릿이 바뀌면 맞지 않을 수 있기 때문입니다.

학습 원점은 레시피에 함께 저장되어 다시 열어도 그대로 복원됩니다. 이전 버전에서 저장한 레시피는 열 때 ROI 기준으로 자동 재계산되며, 한 번 저장하면 새 형식으로 고정됩니다.

패턴 매칭의 각도 · 크기 판정 (Pose Judgment)

패턴 매칭 도구(Feature Match / Shape Match) 설정에 Pose Judgment 섹션이 있습니다. 패턴을 찾긴 했는데 기울어져 있거나 크기가 다른 경우를 불량으로 걸러낼 때 사용합니다:

  • Use Angle Judgment 를 켜고 각도 하한/상한(Angle Lower/Upper Limit)을 입력하면, 찾은 패턴의 각도가 범위를 벗어날 때 NG 가 됩니다 — 결과에 "각도 판정 NG: 47.30° (허용 -45.00~45.00°)" 처럼 사유가 표시됩니다.
  • Use Scale Judgment 도 같은 방식으로 크기(배율) 범위를 판정합니다.
  • 패턴을 여러 개 찾는 모드에서는 1순위 매칭을 기준으로 판정합니다.
  • 두 판정 모두 기본은 꺼짐입니다 — 기존 레시피의 판정 결과는 바뀌지 않습니다.
  • 한계값 4개는 모두 Web 파라미터 연동 콤보를 지원합니다 — Web 패턴 프리셋의 Angle / Scale Lower · Upper Limit 항목과 짝이 맞습니다.

5.8 검사 기준값을 Web 에서 관리하기 (파라미터 연동)

도구 설정의 판정 기준 입력란 옆에는 Web 파라미터 연동 콤보가 있습니다. 콤보에서 파라미터 코드를 고르면, 검사할 때 그 코드의 Web 기준값을 사용합니다 — 이후 기준값을 바꿀 일이 있으면 현장에서 도구 설정을 다시 열 필요 없이 Web 화면(§7.9)에서 값만 고치면 됩니다.

  • 연동할 수 있는 곳 (Blob 도구) — 판정(Judgment)의 기대 면적(Expected Area)과 면적 공차(+/−), 그리고 개수 판정의 기준 개수와 개수 공차(상/하)입니다. 영역 필터(Min/Max Area)는 연동 대상이 아닙니다 — 레시피에서 직접 설정하는 값입니다. 예전 레시피에 Min/Max Area 연동이 걸려 있었다면 불러올 때 자동으로 해제됩니다.
  • 개수 판정의 Tolerance 모드 (Blob 도구) — Count Mode 에서 Tolerance 를 고르면 "기준 개수 ± 공차"로 판정합니다 (Web 연동에 권장). 기존 Equal / 이상 / 이하 / Range 모드는 그대로 쓸 수 있습니다. 하한 공차에 음수를 넣어도 크기로 알아서 해석합니다.
  • 측정 도구 (Geometry) — Judgment 의 기준값(Expected Value)과 공차(+/−)를 연동할 수 있습니다. Web 의 Dimension Tool 프리셋 (Reference Value / Upper·Lower Tolerance)과 항목이 1:1 로 맞습니다. mm/px 해석은 Judgment 의 단위 설정을 따릅니다.
  • 콤보 목록은 자동으로 최신 상태 — Web 에서 파라미터를 추가/수정/삭제하면 열려 있는 연동 콤보에 곧바로(약 1초) 반영됩니다. 네트워크가 잠시 끊겨도 60초 안에 자동으로 따라잡습니다. 프로그램을 다시 시작할 필요가 없습니다. 콤보에는 지금 편집 중인 레시피의 파라미터 목록이 표시되며, 레시피를 전환하면 목록도 그 레시피 기준으로 바로 바뀝니다.
  • 연동 상태는 배지로 확인 — 연동을 걸어 둔 입력란 아래에는 "Web 연동 중 (#코드: 값) — 운전 값은 Web에서 변경" 배지가 항상 표시됩니다. 화면에 입력해 둔 로컬 값이 Web 값과 다르면 배지가 주황 경고 "⚠ 로컬 값 ≠ Web 값 — 운전(AUTO RUN)은 Web 값을 사용합니다"로 바뀝니다 — 여기서 바꾼 값은 이 화면의 테스트 실행에만 쓰이고, 운전 판정 기준을 바꾸려면 Web 에서 수정해야 한다는 뜻입니다.
  • 레시피를 불러오면 상태바에 연동 진단이 표시됩니다 — 정상이면 "Web 파라미터: '레시피명' 코드 N개" 형태의 요약이, Web 레시피와 연결되지 않았거나 등록된 코드가 0개면 무엇을 확인해야 하는지 안내가 표시됩니다. 연동 콤보에 기대한 코드가 안 보일 때는 이 상태바 메시지를 먼저 확인하세요.
  • 레시피는 Web 에 자동 등록 — 비전 설정에서 만든 레시피는 같은 이름으로 Web 원장에 자동 등록됩니다 (이미 같은 이름이 있으면 그 항목에 자동 연결). 관리자는 Web 에서 파라미터만 추가하면 연동 준비가 끝납니다. 오프라인 상태였다면 연결이 돌아올 때 자동으로 다시 등록됩니다. 레시피를 불러오면 연동 콤보에는 그 레시피의 파라미터 코드 목록이 표시됩니다. 반대로 Web 에서 만든 레시피도 Recipe Manager 창이 열려 있는 동안 목록에 자동으로 나타납니다 — 창을 닫았다 다시 열 필요가 없습니다.

5.9 검사 통계를 PLC 로 보내기 (Result 도구)

Result 도구 설정에 PLC Output 항목이 있습니다. 합격 수(PassCount) · 불량 수(FailCount) · 전체 수(TotalCount) 통계를 PLC 주소에 실어 보낼 수 있습니다. 검사 1건의 최종 OK/NG 신호는 지금까지처럼 시퀀스 에디터의 분기(Branch) → 출력(Output) 단계가 담당합니다 — 도구 설정의 도움말에도 같은 안내가 있습니다.

5.10 딥러닝 도구 — 모델 파일과 레지스트리

Deep Learning 카테고리의 도구(Detection · Classify · Anomaly · Segmentation · YOLO Segmentation · RF-DETR-seg 등)는 Model Path 에 모델 파일(ONNX)을 지정해 씁니다. 파일은 AI 학습 도구(별책)로 만들거나 MLOps 모델 레지스트리에서 받습니다.

  • 파일 직접 지정 — 폴더 아이콘으로 이 PC 의 .onnx 파일을 고릅니다. 모델을 바꾸려면 파일을 PC 마다 복사해야 합니다.
  • [레지스트리…] 로 참조 지정 — MLOps 모델 레지스트리에서 모델 계열과 단계(운영 · 스테이징 · 특정 버전)를 고르면 Model Path 에 model://… 참조가 들어갑니다. 레시피는 "이 모델의 운영 버전" 이라고만 적고, 실제 파일은 레시피를 열 때 이 PC 가 레지스트리에서 받아 캐시에 둡니다. MLOps 쪽에서 새 버전을 승격하거나 되돌리면 라인 PC 는 다음 레시피 로드 때 따라옵니다 — 파일을 복사할 일이 없습니다. 검사 중에는 네트워크를 쓰지 않으며, 서버에 닿지 못해도 캐시에 있는 파일로 계속 검사합니다. 설정 마법사 2단계 고급 설정의 MLOps 서버 주소 · 라인 토큰(§3)이 필요합니다.
  • Detection 도구 — D-FINE(기본 학습 백본) 과 YOLO 모델 파일을 열 때 자동으로 판별합니다. 파라미터와 조작은 두 형식이 같습니다.
  • RF-DETR-seg 도구 — 인스턴스 분할 도구로, YOLO Segmentation 과 같은 일을 하지만 Ultralytics(AGPL-3.0) 의존이 없는 대안입니다. Input Size 는 모델을 열면 ONNX 가 정한 값으로 자동 설정되고 칸이 잠깁니다 (모델마다 배수가 달라 손으로 맞추면 안 됩니다). Confidence Threshold 와 Max Instances(점수 순 상한)만 조정하며, IoU · 마스크 임계는 없습니다(집합 예측이라 NMS 를 쓰지 않음). 결과는 인스턴스별 클래스 · 점수 · 박스 · 마스크 픽셀 수이고, 0 건 검출은 NG 입니다(§5.6 판정 규칙과 동일). 학습은 별책 §2 의 train_rfdetr_seg.py 로 합니다.
모델 참조와 검사 이력: 참조로 지정한 모델은 검사 결과와 함께 "어느 모델 버전이 판정했는지" 가 Web 생산 이력에 기록되어, MLOps 라인 모니터링이 모델 버전별 불량률을 집계합니다.

6. AI 학습 도구 (별책 · 선택 구성 요소)

딥러닝 검사 도구(§5 의 Deep Learning 카테고리)에 쓰는 모델 파일(ONNX)은 AI 학습 도구 (VMS.DeepLearning)로 만듭니다. 제품 사진을 모아 정답을 표시(라벨링)하고 학습을 실행해 모델 파일을 만드는 별도 프로그램으로, 설치 파일의 "설치 구성 선택" 화면에서 AI 학습 도구 포함을 체크한 PC(파이썬과 NVIDIA GPU 가 있는 학습용 PC)에만 설치됩니다. 검사만 수행하는 PC 에는 필요하지 않으며, 설치되지 않은 PC 에서는 비전 설정 Tools 메뉴에 Deep Learning 항목이 표시되지 않습니다.

사용 방법(데이터셋 만들기 → 라벨링 → 학습 → 모델 파일 내보내기)과 학습 환경 준비는 별책 「BODA VMS AI 학습 도구 매뉴얼」(BODA-VMS-AI-Tools-Manual.html)을 참고하세요. 만들어진 모델 파일을 비전 설정의 Detection / Classify / Anomaly / YOLO-seg / OCR 도구에 지정하는 방법은 §5 에 있습니다.

참고: 모델 파일은 AI 학습 도구 외의 방법으로 만든 ONNX 도 쓸 수 있습니다. 도구별 입력 규약은 §5 각 도구의 도움말(?) 에 적혀 있습니다.

7. 생산 관리 웹 (BODA.VMS.Web)

⚙ 이 장은 관리 화면(Web)을 사용하는 관리자·반장용입니다. 현장에서 검사만 수행하는 작업자는 읽지 않아도 됩니다.

BODA.VMS.Web 은 별도 프로그램 설치 없이 브라우저로 접속해서 사용합니다. 주소창에 https://<서버IP>:7144 를 입력하세요. 화면 왼쪽에는 메뉴 목록이, 위쪽 막대에는 언어 전환 · 알림 종 · 로그인 사용자 표시가 있습니다.

7.1 로그인 / 회원가입

  1. 접속하면 로그인 화면이 표시됩니다. 사용자 이름과 비밀번호를 입력합니다.
  2. 계정이 없으면 회원가입을 먼저 합니다. 가장 처음 가입한 사용자는 자동으로 관리자(Admin)가 되고, 그 이후에 가입한 사용자는 "승인 대기" 상태가 되어 기존 관리자가 승인해 주어야 로그인할 수 있습니다.
  3. 로그인 유지 체크박스를 켜면 브라우저를 닫아도 로그인이 유지됩니다 (자동 연장, 처음 로그인한 날로부터 최대 30일). 체크하지 않으면 브라우저를 닫거나 8시간이 지나면 다시 로그인합니다. 여러 사람이 쓰는 PC 에서는 체크하지 마세요. 로그아웃은 우측 상단 사용자 메뉴에서 합니다.

가입 승인과 사용자 관리 (관리자)

  • 새 가입 신청이 들어오면 관리자 화면의 알림 종에 알림이 표시되어 놓치지 않습니다.
  • 승인하려면 사이드 메뉴 System 그룹의 사용자 승인 페이지를 열어 "승인 대기" 목록에서 승인 또는 거절합니다.
  • 같은 페이지에서 기존 사용자의 역할 변경(예: User → Admin)과 사용자 삭제도 할 수 있습니다. 삭제는 되돌릴 수 없으니 확인 창에서 한 번 더 확인합니다.

검사 항목(Inspection Items)은 Quality 그룹에 있습니다. 검사 기준값은 품질 기준 정보이므로 일반 사용자(User)도 조회할 수 있고, 추가/수정/삭제는 관리자(Admin)만 할 수 있습니다. 로그인하지 않은 사용자에게는 보이지 않습니다.

7.3 Dashboard

공장 전체 현황을 한 화면에 보여주는 상황판입니다. 전체 라인 수, 합격률(Pass Rate), 불량(NG) 비율, 진행 중인 작업지시, 최근 알람이 카드로 표시됩니다. 검사 결과가 들어올 때마다 새로 고침 없이 자동으로 갱신됩니다.

7.4 Andon Board

모든 라인의 실시간 상태를 카드로 나란히 보여주는 현황판입니다. 각 라인 카드에는 라인 이름, 현재 로그인한 작업자, 작업지시 진행률, 알람 개수가 표시됩니다. 알람 개수를 클릭하면 해당 라인으로 추려진 Alarms 페이지로 이동합니다.

7.5 Alarms

발생한 알람을 모아 보고 처리하는 화면입니다. 라인, 처리 상태(New / Ack / Resolved), 심각도, 기간으로 추려 볼 수 있고, 새 알람은 새로 고침 없이 목록에 즉시 나타납니다.

처리 방법

  • Acknowledge(확인) — "알람을 봤다"는 표시입니다. 확인하면 알림 종의 미확인 개수에서 빠집니다.
  • Resolve(해제) — 원인을 조치한 뒤 사유를 입력하고 알람을 종결합니다.

7.6 Production History

모든 검사 이력을 조회하는 화면입니다. 라인, 작업지시, LOT, 기간, 판정(Pass/NG)으로 추려 볼 수 있습니다.

  • 작업지시 · LOT 필터 — 작업지시를 먼저 고르면 LOT 콤보에 그 작업지시에서 발행된 Lot 만 나타납니다. Lot 하나를 고르면 그 묶음의 검사만 볼 수 있습니다. 필터를 비우면 전체가 표시됩니다.
  • 하루치 조회 — 시작일과 종료일을 같은 날짜로 골라 그날 하루의 검사만 볼 수 있습니다. 위의 요약 카드(총 검사 / 양품 / NG / 불량률)도 함께 그 기간으로 집계됩니다.
  • 목록의 WO / LOT 열에서 각 검사가 어느 작업지시 · Lot 에 속하는지 확인할 수 있습니다. 예전 버전에서 올라온 이력은 이 정보가 없어 — 로 표시되며, 작업지시/LOT 필터를 걸면 목록에서 빠집니다.
  • 행을 클릭하면 상세 창이 열려 측정값, 검사 사진, 불량(NG) 코드를 확인할 수 있습니다.
  • [Excel 내보내기] 버튼으로 현재 목록을 엑셀 파일로 저장할 수 있습니다 — Work Order / Lot 열도 함께 저장됩니다.
  • 검사 이력은 읽기 전용입니다 — 품질 기록의 신뢰성을 위해 수정하거나 지울 수 없습니다.
Web 서버 없이 운전하는 단독 모드(§4.5)에서는 이 화면 대신 VMS 메인의 생산 이력 조회 창([전체 이력] 버튼, §4.3)을 사용합니다. Web 연동 현장에서도 그 창으로 해당 PC 에 남은 로컬 이력을 볼 수 있지만, 작업지시 · Lot 기준의 전체 이력은 이 화면이 기준입니다.

7.7 Work Orders

작업지시를 만들고 관리하는 화면입니다. 작업지시는 Planned(예정) → InProgress(진행 중) → Completed(완료) → Closed(마감) 순서로 진행됩니다.

  • [+] 버튼으로 새 작업지시를 만듭니다 — 제품, 라인, 레시피, 계획 수량, 계획 시작 시각과 완료 기준(아래 참고)을 입력합니다.
  • 작업지시 번호는 자동으로 매겨집니다 (예: WO-20260522-001).
  • [Start] — 예정 상태를 진행 중으로 바꿉니다. VMS 에서 첫 검사 결과가 도착하면 자동으로도 바뀝니다.
  • [Complete] — 수량이 계획 수량에 도달하면 자동으로 완료되며, 필요하면 수동으로도 완료할 수 있습니다. 수동으로 완료하면 그 라인의 VMS 도 즉시 검사를 멈추고 완료 알림 창을 표시합니다 — 현장에 따로 알릴 필요가 없습니다.
  • [Close] — 완료된 작업지시를 영구 마감합니다. 마감한 뒤에는 검사 결과를 더 받지 않습니다.
  • [LOT] — 이 작업지시의 생산 묶음(Lot)을 발행하고 마감합니다. 사용 방법은 §7.11 을 참고하세요.
  • 실시간 갱신 — 이 화면을 열어 두면 VMS 가 검사할 때마다 생산 / 합격 / 불량 수량과 진척률이 새로 고침 없이 바로 올라가고, 계획 수량에 도달하면 상태가 즉시 "완료됨" 으로 바뀝니다.

완료 기준 — 총 생산 / 양품

작업지시를 만들 때 "계획 수량을 무엇으로 채울 것인지"를 고를 수 있습니다:

  • 총 생산 (기본) — 판정과 무관하게 검사한 개수가 계획 수량에 도달하면 완료됩니다. "투입분을 다 검사하면 끝"인 일반적인 운영에 맞습니다.
  • 양품 — 합격(OK) 수량이 계획 수량에 도달해야 완료됩니다. 불량이 나온 만큼 더 생산해서 양품 수를 채우는 운영에 씁니다. 필요할 때만 명시적으로 선택하세요.

VMS 헤더의 진행률도 선택한 기준에 맞는 수량으로 표시됩니다 — 양품 기준이면 "양품 80 / 100" 처럼 접두어가 붙습니다 (§4.2.3). 이전 버전에서 만든 작업지시는 총 생산 기준으로 동작합니다.

혼합 레시피 작업지시 (한 작업지시에 여러 레시피)

여러 제품(레시피)이 섞여 흐르는 혼류 라인을 위해, 작업지시 하나에 레시피별 계획 수량을 여러 줄로 등록할 수 있습니다:

  • 작업지시 생성 창에서 레시피 + 계획 수량 줄을 필요한 만큼 추가합니다.
  • VMS 의 검사 결과는 그때 사용 중인 레시피의 줄에 자동으로 집계됩니다 — 작업자가 따로 지정할 것이 없습니다.
  • 모든 줄이 각자의 계획 수량에 도달하면 작업지시가 완료됩니다.
  • 작업지시에 등록되지 않은 레시피로 검사하면 그 결과는 수량에 집계되지 않고 VMS 시스템 로그에 경고가 남습니다 — 레시피를 잘못 불러온 경우를 바로 알 수 있습니다.

7.8 Products

제품 기준 정보를 관리하는 화면입니다 — 제품 코드, 이름, 분류, 사용 여부를 등록합니다. 작업지시를 만들 때 여기에 등록된 제품 중에서 선택하게 됩니다.

7.9 Inspection Items (Recipes + Parameters)

검사 레시피와 그 안의 파라미터(검사 기준값)를 관리하는 화면입니다. 사이드 메뉴의 Quality 그룹에 있으며, 조회는 일반 사용자(User)도 할 수 있고 추가/수정/삭제는 관리자(Admin)만 할 수 있습니다. 여기서 수정한 값은 VMS 가 1분 안에 자동으로 내려받아 사용하고, 비전 설정(VMS.VisionSetup)의 파라미터 연동 목록에는 곧바로(약 1초) 반영됩니다 (§5).

  • 화면 위에서 라인을 먼저 고릅니다 — 레시피는 라인별로 관리됩니다.
  • 레시피는 Pattern / Blob / Dimension 세 갈래로 나뉘어 트리로 표시됩니다.
  • 파라미터마다 코드 번호(ParamCode), 기준값(ParamValue), 설명, 단위, 상한/하한, 사용 여부를 지정합니다.
  • VMS 는 검사할 때 기준값(ParamValue)을 사용합니다. 상한/하한은 앞으로 제공될 통계 기반 판정(SPC)에 쓰일 예정입니다.

레시피 만들기 · 복사 · 이름 변경 · 지우기

  • 레시피를 만들 때 다이얼로그에 "대상 라인: ○○ — 이 레시피는 해당 라인의 VMS 에만 내려갑니다" 안내가 표시됩니다. 다른 라인용 레시피라면 취소하고 화면 위에서 라인을 먼저 바꾼 뒤 다시 만드세요.
  • 레시피 복사 Admin — 툴바의 [레시피 복사] 버튼은 선택한 레시피를 검사 기준값 파라미터까지 통째로 복사해 "이름 - 복사본"으로 만듭니다. 비슷한 제품의 기준값 세트를 빠르게 만들 때 사용합니다.
  • 이름 변경 Admin — 툴바의 [이름 변경] 버튼으로 레시피 이름을 바꿉니다. 같은 이름이 이미 있으면 안내가 표시됩니다. VisionServer 연동 모드에서는 이름 변경이 지원되지 않는다는 안내가 표시됩니다.
  • 비전 설정(VMS.VisionSetup)에서 만든 레시피는 이 화면에 자동으로 등록됩니다 — 관리자는 그 레시피에 파라미터만 추가하면 됩니다 (§5 파라미터 연동).
  • 삭제 보호 — 작업지시가 참조하고 있는 레시피는 지울 수 없습니다. 삭제를 시도하면 "레시피를 참조하는 작업지시가 있어 삭제할 수 없습니다" 안내가 표시됩니다. 해당 작업지시를 먼저 정리한 뒤 지우세요.

파라미터 프리셋으로 한 번에 추가

파라미터를 하나씩 만들지 않고, 도구 유형별 프리셋으로 관련 파라미터를 한 번에 만들 수 있습니다:

  1. 레시피를 선택하고 [프리셋 일괄 추가] 메뉴를 엽니다.
  2. 도구 유형을 고릅니다 — Pattern Tool(점수·각도·배율·위치 등 7개) / Blob Tool(임계값·면적 기준과 공차·개수 기준과 공차 7개) / Dimension Tool(기준값·공차 3개).
  3. 미리보기 창에 만들어질 파라미터 목록(코드 · 설명 · 단위)이 표시됩니다. 확인하고 [추가] 를 누릅니다.
  4. 값은 0 으로 만들어지므로, 추가한 뒤 각 행에서 실제 기준값을 입력합니다.
Blob Tool 프리셋의 7개 항목은 비전 설정 Blob 도구의 연동 콤보(면적 기준/공차, 개수 기준/공차, 임계값)와 1:1 로 맞춰져 있어, 프리셋으로 추가하면 바로 연동해 쓸 수 있습니다 (§5).

7.10 Operators

현장 작업자를 관리하는 화면으로, 탭 3개로 나뉩니다:

  • Operator Master — 작업자 명단입니다. 사번, 이름, 부서, 권한(Role), 사용 여부를 등록하고 로그인용 PIN 을 지정합니다. PIN 은 암호화되어 저장됩니다.
  • Sessions — 작업자의 로그인/로그아웃 이력입니다. 작업자가 VMS 에서 로그인하면 새로 고침 없이 이 화면에 바로 나타납니다.
  • Kiosk Links — 각 라인의 키오스크 페이지 주소 모음입니다.

7.11 Lots (생산 묶음)

하나의 작업지시 안에서 생산을 묶음(Lot) 단위로 나누어 추적하는 기능입니다. 자재 투입분이 바뀌거나, 교대가 바뀌거나, 시간대를 나누어 관리하고 싶을 때 Lot 을 나눕니다 — 몇 개로 나눌지는 현장이 정하며 시스템 제한은 없습니다. 나중에 "이 불량이 어느 묶음에서 나왔는지"를 Lot 단위로 역추적할 수 있습니다 (§7.6).

  • Lot 번호는 날짜 · 작업지시 번호 · 순번으로 자동으로 매겨집니다 (예: 20260821-WO-…-001).
  • Lot 은 Open(사용 중) → Closed(마감) 두 상태뿐입니다. 마감은 "이 묶음의 생산이 끝났다"는 선언이며, 작업지시의 완료와는 별개입니다.

Lot 발행하고 마감하기 (Web)

  1. Work Orders 화면(§7.7)에서 작업지시 행의 [LOT] 버튼을 누릅니다.
  2. [발행] 을 누르면 새 Lot 이 Open 상태로 만들어집니다 — 한 작업지시에 여러 Lot 을 동시에 Open 해 둘 수 있습니다.
  3. 묶음 생산이 끝나면 해당 Lot 의 [마감] 을 누릅니다. 마감한 Lot 은 VMS 의 선택 목록에서 수 초 안에 사라집니다.

VMS 에서 Lot 고르기 (현장)

VMS 헤더의 Ctx: 영역 Lot 콤보에 지금 선택된 작업지시의 사용 중(Open) Lot 목록이 표시됩니다. Web 에서 발행/마감하면 이 목록은 자동으로 따라옵니다(수 초, 늦어도 1분).

  • 사용 중 Lot 이 1개면 자동으로 선택됩니다 — 작업자가 할 일이 없습니다.
  • 사용 중 Lot 이 여러 개면 지금 생산하는 물량이 어느 묶음인지 현장만 알 수 있으므로, 작업자가 콤보에서 직접 골라야 합니다. 묶음이 바뀔 때마다 콤보에서 바꿔 주세요 — 이후 검사가 그 Lot 으로 집계됩니다.
  • 선택해 둔 Lot 이 마감되면 자동으로 목록에서 빠지고, 남은 Lot 이 1개면 그쪽으로 자동 전환됩니다.
Lot 을 고르지 않고 검사하면? 검사와 작업지시 수량 집계는 정상 진행되지만, 그 검사들은 어느 Lot 에도 귀속되지 않습니다 — 생산 이력의 WO / LOT 열이 비고, Lot 단위 품질 추적이 불가능해집니다. 사용 중 Lot 이 여러 개일 때는 반드시 콤보에서 골라 주세요. (사용 중 Lot 이 하나도 없으면 Lot 없이 검사해도 됩니다.)

7.12 Maintenance

설비 예방정비(PM) 일정을 관리하는 화면입니다. 정비 항목이 기한 초과(Overdue), 오늘 예정(Due Today), 예정(Upcoming)으로 구분되어 표시되고, [Perform] 버튼으로 수행 결과를 기록합니다.

7.13 Defect Codes

불량(NG) 코드 기준 정보를 관리하는 화면입니다 — 코드, 설명, 분류, 심각도(Critical / Major / Minor)를 등록합니다.

7.14 Shifts

교대 근무를 정의하는 화면입니다 (시작 시각과 근무 시간). 검사 결과는 검사한 시각에 따라 해당 교대에 자동으로 배정되어, 교대별 통계를 볼 수 있습니다.

7.15 Audit Logs

기준 정보(작업지시 · 제품 · 작업자 등)를 누가 언제 만들고, 고치고, 지웠는지 기록한 화면입니다. 사용자, 접속 주소(IP), 시각이 함께 남으며, 기록은 읽기 전용이라 수정할 수 없습니다.

7.16 Reports / Quality Analysis

생산 · 품질 통계를 보는 화면입니다. 설비종합효율(OEE) 지표, 라인별 · 작업자별 · 작업지시별 통계, 공정 관리도(SPC 차트)를 제공합니다.

불량률 예측 — 최근 생산 이력을 학습한 예측 모델이 다음 1시간의 예상 불량률을 계산합니다. 예측값은 VMS 헤더의 예측 칩(§4.2.9)에 상시 표시되어, 검사 중에도 불량률 상승 추세를 미리 볼 수 있습니다. 모델이 등록되지 않은 현장에서는 "모델 미등록"으로 표시되며 다른 기능에는 영향이 없습니다.

7.17 알림 (종 아이콘)

화면 위쪽 막대의 오른쪽에 있는 종 모양 아이콘입니다. 아직 확인하지 않은 알람 수가 숫자 배지로 표시됩니다 (100건이 넘으면 "99+"로 표시).

사용 방법

  • 종 아이콘을 클릭하면 최근 알람 10건과 미확인 건수가 표시됩니다.
  • 알람 하나를 클릭하면 Alarms 페이지로 이동합니다.
  • 알람 오른쪽의 ✕ 를 누르면 그 알람만 확인 처리됩니다.
  • [모두 확인] 버튼을 누르면 새 알람 전체가 한 번에 확인 처리됩니다.
확인 처리는 알람을 지우는 것이 아닙니다 — 품질 기록 보존을 위해 알람 이력은 삭제되지 않고 영구 보존됩니다.

7.18 SW 라이선스 (좌석 현황)

System 그룹의 SW 라이선스 메뉴입니다 관리자 전용. 서버에 설치된 SW 라이선스와, 각 라인의 VMS 클라이언트가 사용 중인 좌석을 한눈에 봅니다. 화면은 30초마다 자동으로 새로고침됩니다.

  • 라이선스 정보 — 상태(정상 / 미설치 / 만료 등), 고객명, 라이선스 ID, 좌석 사용/계약 수. 상태가 초록이면 정상입니다.
  • 서버 — 이 서버 PC의 지문 코드입니다. 라이선스 발급·재발급을 요청할 때 이 코드를 그대로 본사에 전달하면 됩니다 (§2.6).
  • 점유 좌석 — 클라이언트 번호별로 호스트 이름 · 지문 코드 · 마지막 갱신 시각이 표시됩니다. 좌석은 클라이언트가 주기적으로 갱신하며, 72시간 동안 갱신이 없으면 (PC 철거 등) 자동으로 목록에서 사라집니다.
좌석 사용 수가 계약 좌석 수를 넘으면 화면 위에 경고 배너가 표시됩니다. 지금은 경고만 표시되고 운전은 제한되지 않지만, 계약 좌석 확인 또는 라이선스 변경(좌석 추가)이 필요한 상태입니다.

2단계

8.3 업로드 큐 (오프라인 복구)

네트워크가 끊기거나 Web 서버가 꺼져 있어도 검사 결과를 잃어버리지 않습니다:

  • 업로드에 실패한 결과는 VMS 가 PC 디스크에 파일로 보관합니다.
  • 몇 초 간격으로 서버 연결을 다시 시도해서, 연결이 돌아오면 보관한 결과를 순서대로 다시 보냅니다.
  • 재전송 중 한 건이 실패하면 잠시 멈췄다가 다시 시도합니다 — 결과 순서가 뒤섞이지 않습니다.
  • VMS 를 껐다 켜도 보관된 결과는 그대로 남아 있다가 자동으로 전송됩니다.
보관 위치와 확인 방법은 §10.1 의 "검사 결과가 서버로 안 올라가고 계속 쌓임" 항목을 참고하세요.

8.4 실시간 반영

검사 결과 · 알람 · 작업지시 변경은 새로 고침 없이 관련된 모든 화면에 즉시 반영됩니다. VMS 가 검사 결과 한 건을 올리면:

  1. VMS 는 서버 응답에서 진행 수량을 즉시 돌려받아 헤더 진행률에 반영합니다.
  2. 동시에 서버가 접속 중인 모든 화면에 변경 사실을 알립니다.
  3. 같은 라인의 다른 VMS 와 관리자의 Dashboard / Andon Board / Alarms / Work Orders 화면이 모두 새로 고침 없이 즉시 갱신됩니다.
  4. Web 에서 Lot 을 발행/마감하면 VMS 헤더의 Lot 콤보도 수 초 안에 따라옵니다 (§7.11).

이 실시간 반영에 쓰이는 기술 이벤트 목록은 부록 §11.2 에 정리되어 있습니다.

8.5 다중 라인 운영

VMS 여러 대(여러 라인)를 하나의 Web 서버에 연결할 수 있습니다. 각 VMS 는 설치할 때 지정한 라인 번호(ClientIndex)로 구분됩니다 (1, 2, 3...).

  • 작업지시 목록은 라인 번호별로 분리되어, 각 라인은 자기 라인의 작업지시만 봅니다.
  • 작업자 로그인 세션도 라인별로 독립적입니다.
  • 관리자는 Andon Board 에서 모든 라인을 한 화면에서 모니터링할 수 있습니다.
라인 번호는 겹치면 안 됩니다: 같은 라인 번호(ClientIndex)로 VMS 두 대를 동시에 실행하지 마세요. 설치할 때 라인마다 번호를 미리 정해서 배정해 두는 것을 권장합니다.

한 PC 에서 두 라인 운용하기

PC 한 대에 카메라가 여러 대 연결되어 있으면, VMS 를 두 개 띄워 각각 다른 라인으로 운용할 수 있습니다. 실행할 때 인스턴스 이름을 붙이는 방식입니다:

  1. 바탕화면에 VMS 바로가기를 하나 더 만들고, 대상 끝에 --instance line2 를 붙입니다 (이름은 영문/숫자로 자유롭게).
  2. 설정 마법사(System Setup)도 같은 이름으로 실행합니다: VMS.AppSetup.exe --instance line2. 화면 위쪽에 인스턴스: line2 배지가 보이면 올바르게 실행된 것입니다.
  3. 마법사에서 2번 라인이 쓸 카메라와 라인 번호(ClientIndex)를 등록하고 저장합니다. 같은 카메라를 두 인스턴스에 겹쳐 등록하면 안 됩니다 — 카메라는 한 번에 한 프로그램만 연결할 수 있습니다.
  4. 이제 두 바로가기로 VMS 를 각각 실행하면, 서로 다른 카메라로 검사하고 Web 화면에는 두 개의 라인으로 표시됩니다.

인스턴스마다 설정 · 레시피 · 작업자 계정 · 검사 기록이 완전히 분리되어 보관됩니다. 이름 없이 실행하면 지금까지와 똑같은 기본 인스턴스로 동작합니다.

9.5 버전 업그레이드

VMS — 인앱 업데이트 (권장)

새 버전이 나오면 VMS 가 알림 창으로 알려 줍니다. 창에서 업데이트를 진행하면 다운로드부터 설치, 재실행까지 자동으로 이어집니다 — 설치 파일을 따로 내려받을 필요가 없습니다:

  1. "업데이트 가능" 알림 창에서 [확인] 을 누릅니다. (수동으로 확인하려면 사이드 패널 Updates 섹션의 [Check for updates] 버튼)
  2. 앱 안에서 설치 파일이 다운로드됩니다 — 사이드 패널 Updates 섹션에 진행률이 표시되고, [다운로드 취소] 로 중간에 멈출 수도 있습니다. 내려받은 파일은 손상 여부를 자동으로 검증합니다.

  4. 설치가 끝나면 VMS 가 자동으로 다시 실행됩니다. 이 PC 에서 Web 서비스를 운영 중이었다면 서비스도 자동으로 다시 시작됩니다.
  • 자동 검사(AUTO RUN)가 도는 동안에는 업데이트를 시작할 수 없습니다 — 검사를 멈춘 뒤 진행하세요.
  • 다운로드나 설치가 실패하면 기존처럼 브라우저에서 설치 파일을 직접 내려받는 방법이 안내됩니다.
  • ⚙ 설치 과정 로그: C:\ProgramData\BODA\VMS\update-bootstrap.log

  1. 새 버전 설치 파일(예: BODA-VMS-1.2.0.msi)을 더블 클릭합니다.
  2. 이전 버전이 자동으로 제거되고 새 버전이 설치됩니다.
  3. 로컬 설정과 카메라 보정 데이터는 그대로 보존됩니다.

Web

  1. 관리자 PowerShell 에서 .\Install-Web.ps1 을 다시 실행합니다.
  2. 서비스 중지 → 새 파일 배포 → 서비스 재시작이 자동으로 진행됩니다.
  3. 데이터베이스는 그대로 유지됩니다. 새 버전에서 데이터 구조가 바뀌는 경우에도 서버가 시작하면서 자동으로 반영합니다.

10. 트러블슈팅

자주 겪는 문제와 해결 방법입니다. 증상을 찾아 순서대로 확인해 보세요. PowerShell 명령이 나오는 항목은 ⚙ 관리자(또는 설치 담당자)용입니다.

10.1 VMS 측

실행하자마자 DLL 오류가 뜸

.NET 8 런타임과 Visual C++ 런타임은 설치 패키지에 동봉되므로 정상 설치본에서는 이 오류가 나지 않습니다. 오류가 난다면:

  1. 구버전(v1.24.0 미만) 설치본인지 확인하세요 — 구버전은 vc_redist / .NET 8 런타임을 별도 설치해야 했습니다. 최신 MSI 로 업그레이드하면 해결됩니다.
  2. 백신/보안 프로그램이 설치 폴더의 DLL 을 격리하지 않았는지 확인하세요.
  3. 계속되면 MSI 를 다시 실행해 복구 설치를 진행하세요.

NG 가 연속으로 나옴 (검사 사진이 비어 있음)

운전 중 카메라에서 이미지를 받지 못하면 그 사이클은 검사 없이 NG 로 집계됩니다 (§4.5). NG 가 연속으로 나오면서 카메라 화면의 연결 점이 빨간색이면 카메라 케이블 · 전원 · 네트워크를 확인하세요. 케이블을 다시 꽂으면 다음 검사부터 자동으로 재연결됩니다 (§4.3).

카메라 영상이 실제 제품과 다르게 보임 (시뮬레이션 영상)

설치된 빌드에 해당 카메라 제조사의 SDK 가 들어 있지 않으면 카메라가 시뮬레이션 모드로 동작합니다 — 비전 설정(VMS.VisionSetup)에서 카메라를 연결할 때 "SDK 미탑재 — 시뮬레이션 모드" 경고 창이 표시됩니다. 화면의 영상은 실제 카메라 영상이 아니므로, 카메라 SDK 가 포함된 정식 설치본인지 설치 담당자에게 확인하세요.

카메라가 자동으로 연결되지 않음

  1. System Setup(설정 마법사)에서 카메라 IP 주소와 제조사가 맞게 입력되어 있는지 확인합니다.
  2. ⚙ 방화벽이 카메라 통신(GigE Vision — UDP 3956 포트)을 막고 있지 않은지 확인합니다.
  3. ⚙ 네트워크 카드가 여러 개인 PC 라면, 카메라가 연결된 네트워크 카드가 우선되도록 네트워크 설정을 확인합니다.

⚙ IO 보드가 연결되지 않음 (상태바 IO 칩이 빨간색)

System Log 의 [IoBoard] 항목에 실패 사유가 남습니다 — 시도한 드라이버 파일 이름, 오류 번호, 설정된 모델 · 보드 번호까지 함께 기록되므로 이 로그부터 확인하세요:

  1. "라이브러리를 찾을 수 없습니다" — 보드 드라이버(ADLink DASK)가 설치되지 않은 것입니다. 64비트(x64)용 드라이버를 설치하세요. 32비트용만 설치된 PC 에서는 VMS(64비트)가 드라이버를 읽을 수 없습니다.
  2. "Register_Card 실패 (에러 번호)" — System Setup 에 입력한 모델과 Board ID 가 실제 장착된 카드와 일치하는지 확인하세요.
  3. "연결 시간 초과(5초)" — 드라이버가 응답하지 않는 상태입니다. 카드 장착과 드라이버 설치 상태를 확인하고 PC 를 재부팅해 보세요.

보드 연결이 실패한 상태에서도 검사 자체는 가능하지만, 그 보드를 쓰는 시퀀스 노드는 동작하지 않습니다.

스위치를 한 번 눌렀는데 검사가 여러 번 반복됨

트리거 노드의 체크 모드가 BitOn(레벨 검사)이면 스위치를 누르고 있는 동안 트리거가 계속 성립합니다. 시퀀스 편집기에서 트리거 노드의 체크 모드를 BitRisingEdge 로 바꾸세요 — 1회 누름 = 1회 검사가 보장됩니다 (§4.8).

검사 결과가 서버로 안 올라가고 계속 쌓임

Web 서버와의 연결이 끊긴 상태입니다. 검사 결과는 잃어버리지 않고 %LocalAppData%\BODA VISION AI\upload_queue\ 폴더에 파일로 보관되며, Web 서버가 다시 켜지면 몇 초 안에 자동으로 전송됩니다. 이 폴더의 파일 수가 줄어드는지를 보면 전송 여부를 확인할 수 있습니다.

검사는 되는데 작업지시 수량이 올라가지 않음

  1. 화면 아래 상태바를 확인하세요. "Running — 경고: Web 미연동 (작업지시 수량 미집계)" 로 표시되어 있으면 검사 결과가 서버 수량으로 집계되지 않는 상태입니다. 시스템 로그에도 같은 경고가 남습니다.
  2. 사용 중인 레시피가 Web 에 등록된(연동된) 레시피인지 확인하세요. PC 에만 있는 레시피로 검사하면 수량이 집계되지 않습니다 (§7.9).
  3. 혼합 레시피 작업지시(§7.7)라면, 지금 사용 중인 레시피가 그 작업지시에 등록된 레시피인지 확인하세요. 등록되지 않은 레시피의 검사는 집계되지 않고 시스템 로그에 경고가 남습니다.
  4. 작업지시가 이미 완료/마감 상태가 아닌지 확인하세요 — 완료된 작업지시로 올라온 검사는 수량에 집계되지 않습니다.

[AUTO RUN] 버튼이 켜지지 않음

버튼 위에 마우스를 올리면 어떤 조건이 빠졌는지 말풍선으로 알려 줍니다. 다음을 차례로 확인하세요:

  1. 카메라가 연결되어 있는지 (헤더에 연결 표시).
  2. 작업자가 로그인되어 있는지 (헤더 Operator 칩에 이름 표시).
  3. 작업지시가 선택되어 있는지 (헤더에 WO 칩 표시).
  4. 작업지시 상태가 예정(Planned) 또는 진행 중(InProgress)인지 — 완료된 작업지시로는 검사를 시작할 수 없습니다.

10.2 비전 설정(레시피 편집) 측

레시피 새로고침을 눌러도 "Web 레시피 0개"

  1. 레시피가 이 라인 번호(ClientIndex) 로 만들어졌는지 Web 검사항목 화면에서 확인하세요 — 레시피는 라인별로 분리됩니다 (§7.9).
  2. 단독 모드(§4.5)로 저장된 PC 라면 Web 동기화 자체가 꺼져 있습니다 — System Setup 에서 단독 모드 체크를 해제하고 Web 주소를 입력하세요.
  3. 상태바의 동기화 요약 메시지에 원인 힌트가 함께 표시됩니다.

도구 설정의 파라미터 연동 콤보에 코드가 안 보임

레시피를 불러오면 상태바에 연동 진단이 표시됩니다 — "코드 N개" 가 아니라 안내 문구가 보이면 그 지시를 따르세요. 흔한 원인은 ① Web 레시피와 이름이 연결되지 않음 ② 그 레시피에 파라미터가 등록되지 않음 (§5.8, §7.9) 입니다.

학습한 패턴을 현장에서 못 찾거나 중심이 어긋남 (Feature Match)

  1. 특징 이미지의 초록 점이 제품 윤곽을 따라 촘촘한지 확인하고, 듬성하면 [Train] 재학습 또는 Max Model Points 를 올리세요 (§5.7).
  2. 중심이 어긋난 반쪽 매칭이 의심되면 Min Coverage(0.6~0.75)를 켜세요 — 기각 사유가 결과 메시지에 표시됩니다.
  3. 그림자 · 반사가 함께 학습된 경우 학습 마스크 또는 [안정 특징 정제] 를 사용하세요.

10.3 Web 측

⚙ 이 절은 관리자용입니다. 서버 로그 확인과 PowerShell 명령을 다룹니다.

Web 서비스가 시작되지 않음

  1. Windows 이벤트 뷰어에서 오류 로그를 확인합니다: Event Viewer → Windows Logs → Application → "BODA-VMS-Web".
  2. 가장 흔한 원인은 포트 충돌입니다. 다른 프로그램이 7144 포트를 쓰고 있는지 확인합니다: netstat -ano | findstr 7144
  3. HTTPS 인증서 문제라면 인증서를 신뢰 목록에 등록합니다: dotnet dev-certs https --trust

로그아웃한 작업자가 계속 "작업 중"으로 표시됨

VMS 가 비정상 종료되면 작업자 세션이 서버에 열린 채로 남을 수 있습니다. 보통은 다음처럼 자동으로 정리됩니다:

  • VMS 를 정상 종료하면 세션도 함께 종료됩니다.
  • 생존 신호(Heartbeat)가 5분 이상 끊긴 클라이언트의 세션은 Web 서버가 시작할 때 자동으로 정리합니다.
  • 바로 정리해야 한다면 Web 서비스를 재시작하세요.

Operators 의 Sessions 탭이 갱신되지 않음

이 화면은 원래 새로 고침 없이 자동으로 갱신됩니다. 갱신되지 않으면:

  • 로그인이 만료되었을 수 있습니다. 로그아웃했다가 다시 로그인해 보세요.
  • 페이지를 새로 고침(F5)해서 실시간 연결을 다시 맺어 보세요.

알림 종 배지가 보이지 않음

브라우저에 이전 버전 화면이 저장(캐시)되어 있는 경우입니다. 강력 새로 고침(Ctrl+Shift+R)으로 캐시를 지우면 해결됩니다.

10.4 통합 / 네트워크

⚙ 이 절은 관리자용입니다.

VMS 가 Web 서버에 연결하지 못함

  1. VMS 의 System Setup 에서 서버 주소(WebServerUrl)가 맞는지 확인합니다 (예: https://192.168.0.10:7144).
  2. Web 서버 PC 의 방화벽 규칙이 살아 있는지 확인합니다: Get-NetFirewallRule -DisplayName "BODA VMS Web*"
  3. 운영 환경에서는 신뢰할 수 있는 인증서(사설 CA) 사용을 권장합니다. 자체 서명(self-signed) 인증서는 개발 · 테스트용입니다.

다른 VMS 의 검사가 내 화면에 반영되지 않음

실시간 연결이 잠시 끊긴 경우입니다. 연결은 몇 초 간격으로 자동 재시도되므로 보통 스스로 복구됩니다. 오래 지속되면 네트워크 상태와 Web 서버가 켜져 있는지 확인하세요.

검사 결과가 Web 에 보이지 않음

  1. VMS 의 업로드 보관 폴더(%LocalAppData%\BODA VISION AI\upload_queue\)에 파일이 쌓여 있는지 확인합니다 — 쌓여 있다면 네트워크가 끊긴 것입니다 (§10.1 참고).
  2. Web 서버의 이벤트 뷰어 로그에서 검사 결과 수신 기록이 있는지 확인합니다.
  3. 레시피와 라인 번호(ClientIndex)가 VMS 와 Web 양쪽에서 일치하는지 확인합니다.

Web 생산 이력의 NG 상세에 검사 사진이 안 보임

  1. VMS 사이드 패널 → Image Saving → [Image Save Settings] 창에서 "NG 이미지 Web 전송" 이 켜져 있는지 확인하세요 — 로컬 저장 체크와 별개의 항목입니다 (§4.3).
  2. 같은 창의 전달 모드가 SharedPath 로 되어 있으면 이미지가 전송되지 않습니다 — Auto 로 바꾸세요. VMS 와 Web 서버가 같은 PC 인 구성에서도 Auto 로 두면 정상 전송됩니다.

Web 에서 만든 레시피가 VMS 에 보이지 않음

  1. VMS 사이드 패널 Recipe 섹션의 새로고침(⟳) 버튼을 누르고, 상태바의 요약 메시지를 확인합니다 — "Web 레시피 N개 — 새 항목 M, 이름 연결 K" 형태로 방금 가져온 결과를 알려 줍니다 (§4.3).
  2. 요약이 0개로 나오면 레시피가 다른 라인으로 만들어진 경우가 대부분입니다. Web 의 검사 항목 화면에서 레시피의 대상 라인과 이 VMS 의 라인 번호(ClientIndex)가 같은지 확인하세요 (§7.9).
  3. VMS 나 비전 설정을 시작할 때 "Web 연동 비활성" 경고 창이 떴다면, 운영(Production) 보안 모드에서 서버 주소가 안전하지 않은 원격 http 주소로 설정되어 Web 연동이 꺼진 것입니다. System Setup 에서 서버 주소를 https://... 로 바꾸세요 (같은 PC 를 가리키는 localhost 주소는 http 여도 됩니다).
