BODA VMS 사용자 매뉴얼

버전 1.1.0 · 2026-08-11 · Vision Management System + Web MES 통합

1. 시스템 개요

BODA VMS 는 두 프로그램으로 구성된 통합 시스템입니다. 현장 PC 의 VMS 클라이언트가 카메라로 제품을 검사하고, 관리 서버인 BODA.VMS.Web 이 검사 결과 · 작업지시 · 작업자 · 알람을 한곳에서 관리합니다. 두 프로그램은 네트워크로 자동 연동되며, 검사 결과와 알람은 실시간으로 서버 화면에 반영됩니다.

1.2 운영 흐름 한눈에

  1. VMS 를 실행하면 카메라가 자동으로 연결되고, Web 서버와의 연결 상태가 헤더에 표시됩니다.
  2. 작업자가 헤더의 [Login...] 버튼을 눌러 사번과 PIN 으로 로그인합니다. 입력한 정보는 Web 서버의 작업자 명단과 대조됩니다.
  3. 로그인하면 이름과 권한 뱃지(Operator / Lead / Supervisor)가 표시되고 [Work Orders] 버튼이 활성화됩니다.
  4. [Work Orders] 를 눌러 오늘 작업할 작업지시를 선택합니다.
  5. 작업지시를 선택하면 검사 레시피가 자동으로 불러와지고 [AUTO RUN] 버튼이 켜집니다.
  6. [AUTO RUN] 을 누르면 검사가 시작됩니다. 진행 수량은 헤더에 실시간으로 표시됩니다 (예: 5/100).
  7. 계획 수량을 다 채우면 완료 알림 창이 뜨고 검사가 자동으로 멈춥니다. 이어서 다음 작업지시를 바로 선택할 수 있습니다.
  8. 검사 결과는 건마다 Web 서버에 자동 저장되고, 불량(NG)이 나오면 관리자 화면에 즉시 알람이 표시됩니다.

2. 설치 / 배포

⚙ 이 장은 설치 담당자/관리자용입니다. 현장에서 검사만 수행하는 작업자는 3장(VMS 클라이언트 매뉴얼)부터 읽으면 됩니다.

2.1 VMS 클라이언트 (MSI)

설치 파일(MSI, 약 220MB) 하나만 실행하면 설치가 끝납니다. 실행에 필요한 구성 요소(.NET 8)가 모두 포함되어 있어 다른 프로그램을 먼저 설치할 필요가 없습니다.

설치

  1. BODA-VMS-1.1.0.msi 더블 클릭.
  2. Welcome → License 동의 → Install Folder (기본 C:\Program Files\BODA VMS\) → Install.
  3. 설치 구성 선택 화면에 "BODA VMS Web 서버" 항목이 있습니다 (기본 포함). 이 PC 를 관리 서버로도 쓸 계획이 없으면 빼도 됩니다 — 포함해서 설치했다면 설치 후 §2.2 의 설정 마법사 방법으로 서버를 켤 수 있습니다.
  4. 완료 시 시작 메뉴 + 데스크톱 바로가기 자동 생성.

제거

  • 제어판 → 프로그램 및 기능 → "BODA VMS" → 제거
  • 또는 시작 메뉴의 "Uninstall BODA VMS" 바로가기

업그레이드 (v1.1 → v1.2)

새 MSI 더블 클릭하면 이전 버전을 자동 제거 후 새 버전 설치 (UpgradeCode 동일 유지). 로컬 설정 파일과 카메라 보정 등은 %LocalAppData% 에 저장되어 보존됩니다.

요구사항: Windows 10/11 x64. Visual C++ Redistributable (OpenCvSharp 네이티브 DLL 의존). 일반 Windows 에 보통 설치되어 있으나 누락 시 Microsoft 공식 사이트에서 vc_redist.x64.exe 다운로드 후 설치.

2.2 Web 서버 (설치 / 구성)

Web 서버는 Windows 서비스로 설치되어 부팅 시 자동 시작됩니다. 별도의 웹 서버 프로그램(IIS 등)은 필요 없습니다. 켜는 방법은 두 가지입니다 — VMS 와 같은 PC 에서 운영한다면 설정 마법사 방법이 가장 쉽습니다.

방법 A — 설정 마법사로 켜기 (VMS 와 같은 PC, 권장)

MSI 설치 때 "BODA VMS Web 서버"를 포함했다면(§2.1 기본값) 명령어 없이 화면에서 바로 구성할 수 있습니다:

  1. System Setup(설정 마법사)을 실행하고 두 번째 페이지로 이동합니다.
  2. "Web 서버 초기 구성 (이 PC)" 카드에서 관리자(admin) 계정으로 쓸 비밀번호를 입력하고 구성 버튼을 누릅니다.
  3. 서버 구성과 서비스 시작이 자동으로 진행되고, 완료되면 카드에 "구성 완료" 상태가 표시됩니다.
  • 구성은 끝났는데 서비스가 멈춰 있으면(Stopped) 카드에 [서비스 시작 (관리자 권한)] 버튼이 나타납니다. 누르면 Windows 권한 확인 창(UAC)이 뜨고, 승인하면 서비스가 부팅 시 자동 시작으로 바뀐 뒤 곧바로 시작되어 응답까지 확인해 줍니다.

방법 B — 배포 스크립트로 설치 (별도 서버 PC)

# 관리자 PowerShell 에서
cd D:\Project\BODA.VMS.Web\deploy
.\Install-Web.ps1

기본값: 설치 폴더 C:\Program Files\BODA VMS Web\, 포트 7144 (HTTPS), 서비스 이름 BODA-VMS-Web, 부팅 시 자동 시작 (실패 시 5초 후 자동 재시작 3회).

옵션 변경:

.\Install-Web.ps1 -Port 8443 -InstallPath "D:\BODA Web"

제거

.\Uninstall-Web.ps1

SQLite DB 는 보존 ($env:LOCALAPPDATA\BODA\VMS). 완전 삭제 시:

Remove-Item "$env:LOCALAPPDATA\BODA\VMS" -Recurse

2.4 첫 실행 전 체크리스트

  1. Web 서버 먼저 시작 → 브라우저로 https://<서버IP>:7144 접속 확인.
  2. 관리자 계정으로 회원가입 → 승인 (현재 첫 사용자가 자동 Admin).
  3. Operators 페이지에서 작업자 마스터 등록 (사번 + PIN + Role).
  4. Products / Recipes / Work Orders 1건 이상 등록.
  5. VMS 클라이언트 설치 후 첫 실행 → AppSetup 마법사에서 WebServerUrl = https://<서버IP>:7144, ClientIndex = 1, 2, 3... 라인별 지정. 입력란 라벨 옆의 파란 물음표(?)에 마우스를 올리면 각 항목의 설명이 표시됩니다.
  6. 마법사 마지막 Security Mode 단계에서 현장(운영) PC는 Production을 그대로 두고 [Finish]로 저장합니다. 보안 모드가 저장되어 있지 않으면 VMS가 시작 시 "보안 정책 오류"를 표시하고 실행되지 않습니다.
  7. VMS 실행 → 시작 화면 헤더에 Heartbeat 정상 표시 확인.

3. VMS 클라이언트 매뉴얼

빠른 시작 — 검사를 시작하는 가장 짧은 길
  1. 헤더의 Operator [Login...] 버튼을 누르고 사번과 PIN 을 입력합니다.
  2. [Work Orders] 버튼을 눌러 오늘 작업할 작업지시를 더블 클릭으로 선택합니다.
  3. 레시피가 자동으로 불러와지고 [AUTO RUN] 버튼이 켜집니다.
  4. [AUTO RUN] 을 누르면 검사가 시작됩니다. 멈추려면 같은 자리의 빨간 [STOP] 을 누릅니다.
  5. 진행 상황은 헤더의 WO 칩(예: 5/100)과 사이드 패널의 Recent Inspections 에서 확인합니다.
각 버튼과 화면 요소의 자세한 설명은 아래 3.1 ~ 3.3 을 참고하세요.

3.1 첫 실행 화면

VMS 를 실행하면 다음 순서로 화면이 나타납니다:

  1. 시작 화면(Splash)이 표시되는 동안 카메라를 자동으로 찾아 연결합니다.
  2. 시스템 사용자 로그인 창이 표시됩니다 (엔지니어·관리자용). 선택
  3. 메인 화면이 표시됩니다: 헤더 + KPI 스트립(생산 현황 요약) + 카메라 화면 + 시스템 로그 + 사이드 패널(접힘).

KPI 스트립 — TACT TIME 카드 읽는 법

KPI 스트립의 TACT TIME 카드는 [AUTO RUN] 으로 연속 검사가 도는 동안 "한 검사가 끝나고 다음 검사가 시작되기까지의 간격"을 보여줍니다. 수동으로 한 건씩 검사할 때는 갱신되지 않습니다 — 사람이 기다린 시간이 섞여 설비 속도로 오해할 수 있기 때문입니다. 카드에는 PROC N ms 가 함께 표시되는데, 이것은 마지막 검사 1건을 처리하는 데 걸린 순수 시간입니다.

3.2 헤더 — 운영 흐름

헤더의 버튼과 표시는 왼쪽에서 오른쪽으로 실제 작업 순서대로 배치되어 있습니다: 작업자 로그인 → 작업지시 선택 → 검사 시작(AUTO RUN).

3.2.1 Operator 로그인

로그인 전에는 [Login...] 버튼만 표시됩니다.

  1. [Login...] 을 클릭하면 로그인 창이 열립니다 (사번 + PIN).
  2. 입력한 사번과 PIN 을 Web 서버의 작업자 명단과 대조합니다.
  3. 성공하면 칩이 "김기동 (1003) Lead [Logout]" 형태로 바뀝니다.

3.2.2 Work Orders 버튼

작업자 로그인 후 사용할 수 있습니다. 클릭하면 Web 서버에서 작업지시 목록을 불러와 창으로 보여줍니다.

  • 상태 필터 — 활성(Planned + InProgress) / 전체 / Planned / InProgress / Completed 로 추려 볼 수 있습니다.
  • 목록 항목 — 작업지시 번호, 제품, 레시피, 진행(예: 5/100), 상태, 계획 시작 시각.
  • 원하는 작업지시를 더블 클릭하거나 [Select] 버튼으로 선택합니다.

3.2.3 WO 칩 (진행률 표시)

선택한 작업지시가 헤더에 표시되고, 검사 1건이 끝날 때마다 진행 수량이 실시간으로 올라갑니다.

WO: WO-20260522-001 · A001 (5/100)  [▰▰▱▱▱▱▱▱]
  • 계획 수량이 0 인 작업지시는 진행률 막대가 표시되지 않습니다.
  • 작업지시가 완료되면 선택이 자동으로 해제되고, 다음 작업지시 선택 창이 열립니다.

3.2.4 Recipe 칩

현재 사용 중인 레시피 이름이 표시됩니다. 작업지시를 선택하면 그 작업지시에 지정된 레시피가 자동으로 불러와지고, 카메라 설정과 Web 파라미터도 함께 맞춰집니다. PC 에 없는 레시피는 Web 서버에서 받아 온 뒤 다시 시도합니다.

3.2.5 Ctx (Inspection Context)

Camera Control 섹션

  • [Grab] — 사진을 한 장 촬영합니다. 검사(AUTO RUN)가 멈춰 있을 때만 사용할 수 있습니다. 촬영해도 지금 보고 있던 화면 탭(2D / Depth Map / Point Cloud)은 그대로 유지됩니다.
  • [Live Start] / [Live Stop] — 카메라 영상을 실시간으로 계속 표시하거나 멈춥니다.
  • [Roller] — 롤러 검사 모드를 켜고 끕니다 (지원 카메라에서만).
  • [Grab] / [Live] 버튼이 눌리지 않을 때는 마우스를 올리면 이유가 말풍선으로 표시됩니다 — 예: 검사 시작/정지 권한이 없음, 작업자 로그인이 필요함, 카메라가 연결되지 않음. [Grab] 도 [Live] 와 같은 권한 기준을 따릅니다.

노출 · 게인 설정 (카메라 설정 창) — 카메라 화면의 설정 창에서 촬영 밝기를 조절합니다:

  • 카메라 설정 유지 체크박스 (기본: 체크) — 체크되어 있으면 카메라에 저장된 노출/게인을 그대로 사용합니다. 카메라 제조사 프로그램(예: Mech-Eye Viewer, pylon Viewer)에서 튜닝해 둔 값이 보존됩니다. 해제하면 아래에 입력한 값을 촬영 전에 카메라에 적용합니다.
  • Exposure — 노출 시간을 숫자로 직접 입력합니다. 단위는 ms(밀리초)로, 카메라 제조사 프로그램과 같은 단위입니다 (예: 200 = 200ms).
  • Gain — 게인(dB)을 숫자로 직접 입력합니다.
  • 설정 창에서도 [Live] 로 실시간 영상을 보면서 값을 맞출 수 있고, 스텝별 노출/게인 설정을 저장할 수 있습니다.
  • [Save Parameter] — 입력한 값을 저장합니다. 저장이 끝나면 완료/실패 결과 메시지가 표시되고, 카메라가 아직 등록되어 있지 않으면 System Setup(설정 마법사)을 먼저 실행하라는 안내가 표시됩니다.
  • Basler 카메라도 여기서 설정한 스텝별 노출/게인이 그대로 적용됩니다. 연결할 때 카메라의 자동 노출/자동 게인이 꺼져서, 촬영할 때마다 밝기가 달라지는 현상이 생기지 않습니다. 제조사 프로그램(pylon Viewer)에서 맞춰 둔 값을 쓰려면 "카메라 설정 유지" 체크를 그대로 두면 됩니다.

3.8 딥러닝 라벨링·학습 (VMS.DeepLearning)

⚙ 이 절은 검사 레시피를 만드는 엔지니어용입니다. 현장에서 검사만 수행하는 작업자는 읽지 않아도 됩니다.

딥러닝 검사 도구(비전 설정의 Deep Learning 카테고리, §3.3)를 쓰려면 먼저 우리 제품의 사진으로 학습한 모델 파일이 있어야 합니다. VMS.DeepLearning 은 그 모델을 만드는 프로그램입니다 — 제품 사진을 모아 정답을 표시(라벨링)하고, 학습을 실행해서, 검사에 쓸 모델 파일(ONNX)을 만드는 과정을 한 화면에서 처리합니다.

비전 설정(VMS.VisionSetup) 화면 상단의 [Deep Learning] 버튼으로 실행합니다.

화면 구성

화면은 세 부분으로 나뉩니다 — 왼쪽은 데이터셋과 이미지 목록, 가운데는 사진 위에 정답을 그리는 캔버스, 오른쪽은 클래스 · 라벨 · 내보내기 · 학습 패널입니다. 각 섹션 제목과 입력란 라벨 옆의 파란 물음표(?) 아이콘에 마우스를 올리면 쉬운 설명 창이 열립니다.

작업 유형 — 데이터셋을 만들 때 선택

무엇을 검사할지에 따라 다섯 가지 작업 유형 중 하나를 고릅니다. 유형마다 정답을 표시하는 방법이 다릅니다:

작업 유형용도정답 표시 방법
Detection (객체 검출)결함이 어디 있는지 찾기 마우스 드래그로 결함 둘레에 상자를 그립니다
Classification (분류)이미지 전체를 종류별로 구분 이미지마다 해당하는 클래스 버튼을 누릅니다
Anomaly (이상 탐지)정상/불량 구분 — 불량 사진이 적을 때 유리 [GOOD (정상)] / [DEFECT (불량)] 버튼으로 분류합니다
OCR (문자 인식)각인 · 라벨의 문자 읽기 문자 영역에 상자를 그리고 정답 텍스트를 입력합니다
Segmentation (분할)객체의 정확한 윤곽까지 필요할 때 SAM 모델을 불러온 뒤 객체를 클릭하면 윤곽이 자동으로 생깁니다

라벨링에서 학습까지 — 기본 절차

  1. 왼쪽 Dataset 섹션에서 이름을 입력하고 작업 유형을 고른 뒤 [+] 버튼으로 데이터셋을 만듭니다.
  2. 위쪽 [Add Images] 버튼으로 검사 대상 사진들을 불러옵니다.
  3. 사진마다 정답을 표시합니다 (방법은 위 표 참고). 키보드 ←/→ 로 이미지를 이동하며, 라벨이 완료된 이미지는 목록에 초록 점으로 표시됩니다.
  4. [Auto Split] — 학습용/검증용 이미지를 자동으로 나눕니다.
  5. [Export] — 학습에 필요한 형식으로 내보냅니다. 작업 유형에 맞는 형식이 자동으로 선택됩니다.
  6. 오른쪽 Training 섹션에서 [Start Training] 을 누르면 학습이 시작됩니다. 진행률과 Loss(오차) · 정확도가 실시간으로 표시되고, [Stop] 으로 중단할 수 있습니다.
  7. 학습이 끝나면 모델 파일(ONNX)이 만들어집니다. 이 파일을 비전 설정의 딥러닝 도구(Detection / Classify / Anomaly 등)에 지정하면 검사에 사용됩니다.
학습 환경: 학습 기능은 Python 이 설치된 PC 에서 동작하며, NVIDIA GPU 가 있으면 훨씬 빠릅니다 (라벨링과 추론 확인은 GPU 없이도 가능). Python 경로는 Training 섹션에 표시되며, 학습 스크립트는 작업 유형에 맞게 자동으로 선택됩니다. 환경 준비는 설치 담당자에게 문의하세요.

학습 결과 바로 확인 (Inference Mode)

왼쪽의 Inference Mode 를 켜면 학습된 모델이 이미지를 넘길 때마다 자동으로 검사해서 결과 상자를 화면에 겹쳐 보여줍니다 — 학습이 잘 됐는지 그 자리에서 확인할 수 있습니다. 두 개의 슬라이더로 민감도를 조절합니다:

  • Conf (신뢰도 기준) — 이 값보다 확신이 낮은 검출은 표시하지 않습니다. 갓 학습한 모델은 낮게(0.05~0.15) 시작하는 것을 권장합니다.
  • IoU (중복 제거 기준) — 같은 결함에 상자가 여러 개 겹칠 때 정리하는 강도입니다.

부족한 데이터 보강 (Active Learning)

모델을 효율적으로 키우는 기능입니다. 학습에 쓰지 않은 사진 폴더를 지정하고 [일괄 추론 실행] 을 누르면, 모델이 잘 못 맞히는 사진일수록 위에 오도록 골라 줍니다. 고른 사진을 [데이터셋에 추가] 로 가져와 라벨링하고 다시 학습하면, 모델이 약한 부분부터 보강됩니다. "모델 예측을 초기 라벨로 사용" 을 켜면 모델의 검출 결과가 라벨로 미리 채워져 검토만 하면 됩니다.

클릭 한 번으로 윤곽 라벨링 (SAM)

Segmentation 데이터셋에서는 오른쪽 SAM Model 섹션에서 모델 파일 두 개 (Encoder/Decoder)를 지정하고 [Load SAM Model] 을 누릅니다. 그 다음 이미지에서 객체를 클릭만 하면 윤곽 마스크가 자동으로 만들어집니다:

  • 왼쪽 클릭 — 포함할 부분 지정 / 오른쪽 클릭 — 제외할 부분 지정
  • Enter — 미리보기 마스크를 라벨로 확정 / Esc — 취소
3D 검사에도 이 모델을 씁니다: Segmentation 으로 학습한 모델은 3D 객체 검출 (§3.9)의 첫 단계에서 그대로 사용됩니다. 3D 카메라를 쓰는 경우에도 학습은 언제나 2D 사진으로 합니다 — 그 3D 카메라가 함께 찍는 2D 이미지를 모아 라벨링하세요.

3.9 비전 설정 (VMS.VisionSetup) — 예제 템플릿 · 3D · 스텝 관리

예제 템플릿 갤러리

  4. 만들어진 각 도구를 선택해 우리 제품에 맞게 값(임계값, 모델 파일 등)을 조정합니다.

3D 객체 검출 — 딥러닝으로 찾고, 점군으로 잰다

3D 카메라로 찍은 점군(Point Cloud)에서 원하는 객체만 골라내어 개수를 세고 크기를 재는 검사입니다. 원리는 간단합니다 — "어디에 있는지"는 2D 사진에서 딥러닝으로 찾고, "얼마나 큰지"는 3D 점군에서 잽니다.

  1. 모델 준비 (VMS.DeepLearning, §3.8) — 3D 카메라가 함께 찍는 2D 사진을 모아 Segmentation 유형으로 라벨링하고 학습합니다. SAM 을 쓰면 클릭만으로 윤곽이 그려집니다. 실제 검사와 같은 위치 · 조명에서 찍은 사진으로 학습해야 정확합니다.
  2. 윤곽 검출 (YOLO Seg 도구) — 학습한 모델 파일을 지정하면, 촬영된 2D 사진에서 객체마다 정확한 윤곽(마스크)을 찾아냅니다.
  3. 점군 잘라내기 (Point Cloud Mask Crop 도구) — 찾은 윤곽 안쪽에 해당하는 점들만 점군에서 잘라냅니다. 배경 · 바닥은 사라지고 객체의 점만 남습니다.
  4. 개수 · 치수 측정 (Point Cloud Cluster 도구) — 남은 점들을 덩어리(클러스터)로 나눠 객체 개수를 세고, 덩어리마다 가로 · 세로 · 높이 치수를 잽니다. 덩어리 사이의 거리도 잴 수 있습니다.
빠른 시작: 위 구성은 예제 템플릿 "DL 세그 기반 3D 객체 검출" 을 선택하면 한 번에 만들어집니다. 모델 파일 지정과 값 조정만 하면 됩니다.
  • mm 단위 환산 (XY 캘리브레이션) — 점군의 가로 · 세로 값을 mm 로 바꿔 줍니다. 3D 카메라의 내부 정보로 자동 환산하는 것이 기본이고, 수동으로 환산 값을 입력할 수도 있습니다.
  • 여러 갈래로 나눠 검사 — 마스크 크롭을 여러 갈래(브랜치)로 나눠 각각 다른 대상을 잘라낸 뒤 합쳐서(Union) 볼 수 있고, 크롭 · 클러스터 결과는 2D 화면 위에도 겹쳐(오버레이) 표시됩니다.

점군 화면에서 바로 재기 (측정 툴바)

Point Cloud 화면 상단 가운데에 측정 툴바가 있습니다. 도구를 만들지 않아도 화면에서 바로 거리와 각도를 확인할 수 있습니다:

  • [Distance] — 점 2개를 클릭하면 두 점 사이 거리를 표시합니다.
  • [Angle] — 점 3개를 클릭하면 각도를 표시합니다 (두 번째 점이 꼭짓점).
  • [Clear] — 측정 결과를 모두 지웁니다.

점군 화면 조작 — 표시 밀도 · 회전 · 줌

  • 표시 밀도 — 고해상도 3D 카메라의 점군(수백만 점)도 기본으로 전부 표시됩니다. 화면이 무겁게 느껴지면 뷰 툴바의 밀도 버튼을 눌러 자동 → 전체 → 1/2 → 1/4 순서로 표시 밀도를 바꿀 수 있습니다.
  • 회전 — 마우스 드래그로 회전하면 점군의 중심을 축으로 턴테이블처럼 돌아갑니다. 수평이 유지되어 화면이 뒤집히지 않습니다.
  • 줌 — 마우스 휠 한 칸에 조금씩(2%) 확대/축소됩니다. Ctrl 을 누른 채 휠을 돌리면 절반(1%)씩 움직여 더 정밀하게 맞출 수 있습니다. Depth Map 화면도 같은 방식으로 동작합니다.

스텝별 카메라 설정 (Camera Settings 패널)

비전 설정에서 스텝을 선택하면 그 스텝이 사용할 카메라 파라미터(노출 등)를 바로 편집할 수 있습니다. 2D 이미지 보존, Depth 표시 색상(컬러/그레이) 등 카메라 종류에 맞는 항목이 표시됩니다.

패널의 "스텝 정보" 그룹에서는 스텝에 붙일 정보를 입력합니다:

  • 별칭 — 스텝을 알아보기 쉽게 붙이는 자유 이름입니다 (예: "Node 3"). 입력하면 스텝 목록과 트리에 "1-3 — Node 3" 처럼 이름 옆에 함께 표시됩니다.
  • 로봇 노드 번호 — 로봇이 촬영 위치마다 보내는 번호와 이 스텝을 짝지을 때 입력합니다. 비워 두면 스텝 순서대로 짝지어집니다.

스텝 관리 — 이름 · 별칭 · Steps 그리드

  • 스텝 이름은 자동으로 매겨집니다 — "1-1", "1-2" 같은 이름은 이 PC 에 등록된 카메라 순서를 기준으로 레시피를 불러올 때마다 자동 계산됩니다. 직접 바꿀 수 없으며, 부르기 쉬운 이름이 필요하면 위의 별칭을 쓰세요.
  • 다른 PC 에서 만든 레시피 — 이 PC 에 등록되지 않은 카메라를 쓰는 스텝은 이름이 "?-1" 처럼 물음표로 표시되고, 레시피를 불러올 때 등록되지 않은 카메라가 있다는 경고 창이 뜹니다. 이 PC 의 카메라로 쓰려면 System Setup 에서 해당 카메라를 등록하세요.
  • Steps 그리드는 선택한 카메라의 스텝만 보여줍니다 — 그리드 제목에 현재 카메라 이름이 표시됩니다 (예: "Steps — Cam1"). 스텝이 안 보이면 카메라를 선택하지 않았거나 그 카메라에 스텝이 없는 것이며, 빈 화면에 어떤 경우인지 안내 문구가 표시됩니다. 레시피를 불러오면 레시피가 쓰는 카메라가 자동으로 선택됩니다.
  • Recipe Manager 의 Step Alias 입력란 — 레시피 관리 창에서도 스텝의 별칭을 고칠 수 있습니다. 자동으로 매겨지는 이름("1-1")은 여기서도 편집할 수 없습니다.

툴바에서 바로 촬영 (Grab · Live)

화면 위 툴바에 카메라 버튼(▶/■ 배지)이 있어, Camera 메뉴에 들어가지 않아도 사진 한 장 촬영(Grab)과 실시간 보기(Live) 시작/정지를 바로 할 수 있습니다. 앱을 켜면 첫 번째 카메라가 자동으로 선택되므로, 카메라 패널을 만지지 않아도 툴바 버튼이 곧바로 동작합니다.

측정값 판정 (Judgment) — 기준값 ± 공차

엣지 간 거리 같은 측정 도구(Geometry)에 Judgment 설정이 있습니다. 기준값과 공차(+/−)를 입력하면 측정값이 범위 안이면 OK, 벗어나면 NG 로 판정되고 결과가 화면 위에 겹쳐 표시됩니다. 단위는 mm 또는 픽셀(px) 중에서 고를 수 있습니다.

  • 캘리브레이션 없이 mm 로 재기 — 카메라 캘리브레이션을 하지 않았다면, 스텝 그리드의 Resolution (mm/px) 값을 입력해 두세요. 측정 도구가 이 값으로 픽셀을 mm 로 환산합니다.
  • 템플릿은 판정까지 연결되어 만들어집니다 — 예제 템플릿의 엣지 간 거리 측정 · Blob 검출 · 컬러 객체 검출은 마지막 Result 판정까지 연결된 상태로 생성되어, 값만 조정하면 OK/NG 판정이 바로 동작합니다.

검사 기준값을 Web 에서 관리하기 (파라미터 연동)

도구 설정의 판정 기준 입력란 옆에는 Web 파라미터 연동 콤보가 있습니다. 콤보에서 파라미터 코드를 고르면, 검사할 때 그 코드의 Web 기준값을 사용합니다 — 이후 기준값을 바꿀 일이 있으면 현장에서 도구 설정을 다시 열 필요 없이 Web 화면(§4.9)에서 값만 고치면 됩니다.

  • 연동할 수 있는 곳 (Blob 도구) — 판정(Judgment)의 기대 면적(Expected Area)과 면적 공차(+/−), 그리고 개수 판정의 기준 개수와 개수 공차(상/하)입니다. 영역 필터(Min/Max Area)는 연동 대상이 아닙니다 — 레시피에서 직접 설정하는 값입니다. 예전 레시피에 Min/Max Area 연동이 걸려 있었다면 불러올 때 자동으로 해제됩니다.
  • 개수 판정의 Tolerance 모드 (Blob 도구) — Count Mode 에서 Tolerance 를 고르면 "기준 개수 ± 공차"로 판정합니다 (Web 연동에 권장). 기존 Equal / 이상 / 이하 / Range 모드는 그대로 쓸 수 있습니다. 하한 공차에 음수를 넣어도 크기로 알아서 해석합니다.
  • 측정 도구 (Geometry) — Judgment 의 기준값(Expected Value)과 공차(+/−)를 연동할 수 있습니다. Web 의 Dimension Tool 프리셋 (Reference Value / Upper·Lower Tolerance)과 항목이 1:1 로 맞습니다. mm/px 해석은 Judgment 의 단위 설정을 따릅니다.
  • 콤보 목록은 자동으로 최신 상태 — Web 에서 파라미터를 추가/수정/삭제하면 열려 있는 연동 콤보에 곧바로(약 1초) 반영됩니다. 네트워크가 잠시 끊겨도 60초 안에 자동으로 따라잡습니다. 프로그램을 다시 시작할 필요가 없습니다.
  • 레시피는 Web 에 자동 등록 — 비전 설정에서 만든 레시피는 같은 이름으로 Web 원장에 자동 등록됩니다 (이미 같은 이름이 있으면 그 항목에 자동 연결). 관리자는 Web 에서 파라미터만 추가하면 연동 준비가 끝납니다. 오프라인 상태였다면 연결이 돌아올 때 자동으로 다시 등록됩니다. 레시피를 불러오면 연동 콤보에는 그 레시피의 파라미터 코드 목록이 표시됩니다. 반대로 Web 에서 만든 레시피도 Recipe Manager 창이 열려 있는 동안 목록에 자동으로 나타납니다 — 창을 닫았다 다시 열 필요가 없습니다.

검사 통계를 PLC 로 보내기 (Result 도구)

Result 도구 설정에 PLC Output 항목이 있습니다. 합격 수(PassCount) · 불량 수(FailCount) · 전체 수(TotalCount) 통계를 PLC 주소에 실어 보낼 수 있습니다. 검사 1건의 최종 OK/NG 신호는 지금까지처럼 시퀀스 에디터의 분기(Branch) → 출력(Output) 단계가 담당합니다 — 도구 설정의 도움말에도 같은 안내가 있습니다.

4. BODA.VMS.Web (관리자 / MES)

⚙ 이 장은 관리 화면(Web)을 사용하는 관리자·반장용입니다. 현장에서 검사만 수행하는 작업자는 읽지 않아도 됩니다.

BODA.VMS.Web 은 별도 프로그램 설치 없이 브라우저로 접속해서 사용합니다. 주소창에 https://<서버IP>:7144 를 입력하세요. 화면 왼쪽에는 메뉴 목록이, 위쪽 막대에는 언어 전환 · 알림 종 · 로그인 사용자 표시가 있습니다.

4.1 로그인 / 회원가입

  1. 접속하면 로그인 화면이 표시됩니다. 사용자 이름과 비밀번호를 입력합니다.
  2. 계정이 없으면 회원가입을 먼저 합니다. 가장 처음 가입한 사용자는 자동으로 관리자(Admin)가 되고, 그 이후에 가입한 사용자는 "승인 대기" 상태가 되어 기존 관리자가 승인해 주어야 로그인할 수 있습니다.
  3. 한 번 로그인하면 브라우저가 로그인 상태를 기억하므로, 로그인이 만료되기 전까지는 다시 입력할 필요가 없습니다.

가입 승인과 사용자 관리 (관리자)

  • 새 가입 신청이 들어오면 관리자 화면의 알림 종에 알림이 표시되어 놓치지 않습니다.
  • 승인하려면 사이드 메뉴 System 그룹의 사용자 승인 페이지를 열어 "승인 대기" 목록에서 승인 또는 거절합니다.
  • 같은 페이지에서 기존 사용자의 역할 변경(예: User → Admin)과 사용자 삭제도 할 수 있습니다. 삭제는 되돌릴 수 없으니 확인 창에서 한 번 더 확인합니다.

4.2 사이드 메뉴 구조

왼쪽 사이드 메뉴는 업무 성격별로 다음과 같이 묶여 있습니다:

검사 항목(Inspection Items)은 Quality 그룹에 있습니다. 검사 기준값은 품질 기준 정보이므로 일반 사용자(User)도 조회할 수 있고, 추가/수정/삭제는 관리자(Admin)만 할 수 있습니다. 로그인하지 않은 사용자에게는 보이지 않습니다.

4.3 Dashboard

공장 전체 현황을 한 화면에 보여주는 상황판입니다. 전체 라인 수, 합격률(Pass Rate), 불량(NG) 비율, 진행 중인 작업지시, 최근 알람이 카드로 표시됩니다. 검사 결과가 들어올 때마다 새로 고침 없이 자동으로 갱신됩니다.

4.4 Andon Board

모든 라인의 실시간 상태를 카드로 나란히 보여주는 현황판입니다. 각 라인 카드에는 라인 이름, 현재 로그인한 작업자, 작업지시 진행률, 알람 개수가 표시됩니다. 알람 개수를 클릭하면 해당 라인으로 추려진 Alarms 페이지로 이동합니다.

4.5 Alarms

발생한 알람을 모아 보고 처리하는 화면입니다. 라인, 처리 상태(New / Ack / Resolved), 심각도, 기간으로 추려 볼 수 있고, 새 알람은 새로 고침 없이 목록에 즉시 나타납니다.

처리 방법

  • Acknowledge(확인) — "알람을 봤다"는 표시입니다. 확인하면 알림 종의 미확인 개수에서 빠집니다.
  • Resolve(해제) — 원인을 조치한 뒤 사유를 입력하고 알람을 종결합니다.

4.6 Production History

모든 검사 이력을 조회하는 화면입니다. 라인, 작업지시, LOT, 기간, 판정(Pass/NG)으로 추려 볼 수 있습니다.

  • 작업지시 · LOT 필터 — 작업지시를 먼저 고르면 LOT 콤보에 그 작업지시에서 발행된 Lot 만 나타납니다. Lot 하나를 고르면 그 묶음의 검사만 볼 수 있습니다. 필터를 비우면 전체가 표시됩니다.
  • 하루치 조회 — 시작일과 종료일을 같은 날짜로 골라 그날 하루의 검사만 볼 수 있습니다. 위의 요약 카드(총 검사 / 양품 / NG / 불량률)도 함께 그 기간으로 집계됩니다.
  • 목록의 WO / LOT 열에서 각 검사가 어느 작업지시 · Lot 에 속하는지 확인할 수 있습니다. 예전 버전에서 올라온 이력은 이 정보가 없어 — 로 표시되며, 작업지시/LOT 필터를 걸면 목록에서 빠집니다.
  • 행을 클릭하면 상세 창이 열려 측정값, 검사 사진, 불량(NG) 코드를 확인할 수 있습니다.
  • [Excel 내보내기] 버튼으로 현재 목록을 엑셀 파일로 저장할 수 있습니다 — Work Order / Lot 열도 함께 저장됩니다.
  • 검사 이력은 읽기 전용입니다 — 품질 기록의 신뢰성을 위해 수정하거나 지울 수 없습니다.

4.7 Work Orders

작업지시를 만들고 관리하는 화면입니다. 작업지시는 Planned(예정) → InProgress(진행 중) → Completed(완료) → Closed(마감) 순서로 진행됩니다.

  • [+] 버튼으로 새 작업지시를 만듭니다 — 제품, 라인, 레시피, 계획 수량, 계획 시작 시각을 입력합니다.
  • 작업지시 번호는 자동으로 매겨집니다 (예: WO-20260522-001).
  • [Start] — 예정 상태를 진행 중으로 바꿉니다. VMS 에서 첫 검사 결과가 도착하면 자동으로도 바뀝니다.
  • [Complete] — 생산 수량이 계획 수량에 도달하면 자동으로 완료되며, 필요하면 수동으로도 완료할 수 있습니다.
  • [Close] — 완료된 작업지시를 영구 마감합니다. 마감한 뒤에는 검사 결과를 더 받지 않습니다.
  • [LOT] — 이 작업지시의 생산 묶음(Lot)을 발행하고 마감합니다. 사용 방법은 §4.11 을 참고하세요.
  • 실시간 갱신 — 이 화면을 열어 두면 VMS 가 검사할 때마다 생산 / 합격 / 불량 수량과 진척률이 새로 고침 없이 바로 올라가고, 계획 수량에 도달하면 상태가 즉시 "완료됨" 으로 바뀝니다.

4.8 Products

제품 기준 정보를 관리하는 화면입니다 — 제품 코드, 이름, 분류, 사용 여부를 등록합니다. 작업지시를 만들 때 여기에 등록된 제품 중에서 선택하게 됩니다.

4.9 Inspection Items (Recipes + Parameters)

검사 레시피와 그 안의 파라미터(검사 기준값)를 관리하는 화면입니다. 사이드 메뉴의 Quality 그룹에 있으며, 조회는 일반 사용자(User)도 할 수 있고 추가/수정/삭제는 관리자(Admin)만 할 수 있습니다. 여기서 수정한 값은 VMS 가 1분 안에 자동으로 내려받아 사용하고, 비전 설정(VMS.VisionSetup)의 파라미터 연동 목록에는 곧바로(약 1초) 반영됩니다 (§3.9).

  • 화면 위에서 라인을 먼저 고릅니다 — 레시피는 라인별로 관리됩니다.
  • 레시피는 Pattern / Blob / Dimension 세 갈래로 나뉘어 트리로 표시됩니다.
  • 파라미터마다 코드 번호(ParamCode), 기준값(ParamValue), 설명, 단위, 상한/하한, 사용 여부를 지정합니다.
  • VMS 는 검사할 때 기준값(ParamValue)을 사용합니다. 상한/하한은 앞으로 제공될 통계 기반 판정(SPC)에 쓰일 예정입니다.

레시피 만들기 · 지우기

  • 레시피를 만들 때 다이얼로그에 "대상 라인: ○○ — 이 레시피는 해당 라인의 VMS 에만 내려갑니다" 안내가 표시됩니다. 다른 라인용 레시피라면 취소하고 화면 위에서 라인을 먼저 바꾼 뒤 다시 만드세요.
  • 비전 설정(VMS.VisionSetup)에서 만든 레시피는 이 화면에 자동으로 등록됩니다 — 관리자는 그 레시피에 파라미터만 추가하면 됩니다 (§3.9 파라미터 연동).
  • 삭제 보호 — 작업지시가 참조하고 있는 레시피는 지울 수 없습니다. 삭제를 시도하면 "레시피를 참조하는 작업지시가 있어 삭제할 수 없습니다" 안내가 표시됩니다. 해당 작업지시를 먼저 정리한 뒤 지우세요.

파라미터 프리셋으로 한 번에 추가

파라미터를 하나씩 만들지 않고, 도구 유형별 프리셋으로 관련 파라미터를 한 번에 만들 수 있습니다:

  1. 레시피를 선택하고 [프리셋 일괄 추가] 메뉴를 엽니다.
  2. 도구 유형을 고릅니다 — Pattern Tool(점수·각도·배율·위치 등 7개) / Blob Tool(임계값·면적 기준과 공차·개수 기준과 공차 7개) / Dimension Tool(기준값·공차 3개).
  3. 미리보기 창에 만들어질 파라미터 목록(코드 · 설명 · 단위)이 표시됩니다. 확인하고 [추가] 를 누릅니다.
  4. 값은 0 으로 만들어지므로, 추가한 뒤 각 행에서 실제 기준값을 입력합니다.
Blob Tool 프리셋의 7개 항목은 비전 설정 Blob 도구의 연동 콤보(면적 기준/공차, 개수 기준/공차, 임계값)와 1:1 로 맞춰져 있어, 프리셋으로 추가하면 바로 연동해 쓸 수 있습니다 (§3.9).

4.10 Operators

현장 작업자를 관리하는 화면으로, 탭 3개로 나뉩니다:

  • Operator Master — 작업자 명단입니다. 사번, 이름, 부서, 권한(Role), 사용 여부를 등록하고 로그인용 PIN 을 지정합니다. PIN 은 암호화되어 저장됩니다.
  • Sessions — 작업자의 로그인/로그아웃 이력입니다. 작업자가 VMS 에서 로그인하면 새로 고침 없이 이 화면에 바로 나타납니다.
  • Kiosk Links — 각 라인의 키오스크 페이지 주소 모음입니다.

4.11 Lots (생산 묶음)

하나의 작업지시 안에서 생산을 묶음(Lot) 단위로 나누어 추적하는 기능입니다. 자재 투입분이 바뀌거나, 교대가 바뀌거나, 시간대를 나누어 관리하고 싶을 때 Lot 을 나눕니다 — 몇 개로 나눌지는 현장이 정하며 시스템 제한은 없습니다. 나중에 "이 불량이 어느 묶음에서 나왔는지"를 Lot 단위로 역추적할 수 있습니다 (§4.6).

  • Lot 번호는 날짜 · 작업지시 번호 · 순번으로 자동으로 매겨집니다 (예: 20260821-WO-…-001).
  • Lot 은 Open(사용 중) → Closed(마감) 두 상태뿐입니다. 마감은 "이 묶음의 생산이 끝났다"는 선언이며, 작업지시의 완료와는 별개입니다.

Lot 발행하고 마감하기 (Web)

  1. Work Orders 화면(§4.7)에서 작업지시 행의 [LOT] 버튼을 누릅니다.
  2. [발행] 을 누르면 새 Lot 이 Open 상태로 만들어집니다 — 한 작업지시에 여러 Lot 을 동시에 Open 해 둘 수 있습니다.
  3. 묶음 생산이 끝나면 해당 Lot 의 [마감] 을 누릅니다. 마감한 Lot 은 VMS 의 선택 목록에서 수 초 안에 사라집니다.

VMS 에서 Lot 고르기 (현장)

VMS 헤더의 Ctx: 영역 Lot 콤보에 지금 선택된 작업지시의 사용 중(Open) Lot 목록이 표시됩니다. Web 에서 발행/마감하면 이 목록은 자동으로 따라옵니다(수 초, 늦어도 1분).

  • 사용 중 Lot 이 1개면 자동으로 선택됩니다 — 작업자가 할 일이 없습니다.
  • 사용 중 Lot 이 여러 개면 지금 생산하는 물량이 어느 묶음인지 현장만 알 수 있으므로, 작업자가 콤보에서 직접 골라야 합니다. 묶음이 바뀔 때마다 콤보에서 바꿔 주세요 — 이후 검사가 그 Lot 으로 집계됩니다.
  • 선택해 둔 Lot 이 마감되면 자동으로 목록에서 빠지고, 남은 Lot 이 1개면 그쪽으로 자동 전환됩니다.
Lot 을 고르지 않고 검사하면? 검사와 작업지시 수량 집계는 정상 진행되지만, 그 검사들은 어느 Lot 에도 귀속되지 않습니다 — 생산 이력의 WO / LOT 열이 비고, Lot 단위 품질 추적이 불가능해집니다. 사용 중 Lot 이 여러 개일 때는 반드시 콤보에서 골라 주세요. (사용 중 Lot 이 하나도 없으면 Lot 없이 검사해도 됩니다.)

4.12 Maintenance

설비 예방정비(PM) 일정을 관리하는 화면입니다. 정비 항목이 기한 초과(Overdue), 오늘 예정(Due Today), 예정(Upcoming)으로 구분되어 표시되고, [Perform] 버튼으로 수행 결과를 기록합니다.

4.13 Defect Codes

불량(NG) 코드 기준 정보를 관리하는 화면입니다 — 코드, 설명, 분류, 심각도(Critical / Major / Minor)를 등록합니다.

4.14 Shifts

교대 근무를 정의하는 화면입니다 (시작 시각과 근무 시간). 검사 결과는 검사한 시각에 따라 해당 교대에 자동으로 배정되어, 교대별 통계를 볼 수 있습니다.

4.15 Audit Logs

기준 정보(작업지시 · 제품 · 작업자 등)를 누가 언제 만들고, 고치고, 지웠는지 기록한 화면입니다. 사용자, 접속 주소(IP), 시각이 함께 남으며, 기록은 읽기 전용이라 수정할 수 없습니다.

4.16 Reports / Quality Analysis

생산 · 품질 통계를 보는 화면입니다. 설비종합효율(OEE) 지표, 라인별 · 작업자별 · 작업지시별 통계, 공정 관리도(SPC 차트)를 제공합니다.

4.17 알림 (종 아이콘)

화면 위쪽 막대의 오른쪽에 있는 종 모양 아이콘입니다. 아직 확인하지 않은 알람 수가 숫자 배지로 표시됩니다 (100건이 넘으면 "99+"로 표시).

사용 방법

  • 종 아이콘을 클릭하면 최근 알람 10건과 미확인 건수가 표시됩니다.
  • 알람 하나를 클릭하면 Alarms 페이지로 이동합니다.
  • 알람 오른쪽의 ✕ 를 누르면 그 알람만 확인 처리됩니다.
  • [모두 확인] 버튼을 누르면 새 알람 전체가 한 번에 확인 처리됩니다.
확인 처리는 알람을 지우는 것이 아닙니다 — 품질 기록 보존을 위해 알람 이력은 삭제되지 않고 영구 보존됩니다.

5. 통합 워크플로

이 장은 VMS 클라이언트와 Web 서버가 뒤에서 어떻게 맞물려 동작하는지 설명합니다. 평소 운영에 꼭 필요한 내용은 아니지만, 시스템을 이해하거나 문제 원인을 찾을 때 도움이 됩니다.

5.1 운영 3단계 — 로그인 · 작업지시 · 진행/완료

3장에서 본 운영 흐름은 두 프로그램이 다음처럼 역할을 나누어 처리합니다:

단계무슨 일이 일어나는지
1단계
작업자 로그인		 VMS 가 입력받은 사번과 PIN 을 Web 서버로 보내면, 서버가 작업자 명단과 대조해 로그인 세션을 만들어 줍니다. 성공하면 VMS 헤더에 작업자 이름과 권한 뱃지가 표시됩니다.
2단계
작업지시 선택		 VMS 가 Web 서버에서 이 라인의 작업지시 목록을 받아 와 창으로 보여줍니다. 하나를 선택하면 그 작업지시에 지정된 레시피가 자동으로 불러와지고, 사용 중인 Lot 이 채워지며, [AUTO RUN] 버튼이 켜집니다.
3단계

5.3 업로드 큐 (오프라인 복구)

네트워크가 끊기거나 Web 서버가 꺼져 있어도 검사 결과를 잃어버리지 않습니다:

  • 업로드에 실패한 결과는 VMS 가 PC 디스크에 파일로 보관합니다.
  • 몇 초 간격으로 서버 연결을 다시 시도해서, 연결이 돌아오면 보관한 결과를 순서대로 다시 보냅니다.
  • 재전송 중 한 건이 실패하면 잠시 멈췄다가 다시 시도합니다 — 결과 순서가 뒤섞이지 않습니다.
  • VMS 를 껐다 켜도 보관된 결과는 그대로 남아 있다가 자동으로 전송됩니다.
보관 위치와 확인 방법은 §7.1 의 "검사 결과가 서버로 안 올라가고 계속 쌓임" 항목을 참고하세요.

5.4 실시간 반영

검사 결과 · 알람 · 작업지시 변경은 새로 고침 없이 관련된 모든 화면에 즉시 반영됩니다. VMS 가 검사 결과 한 건을 올리면:

  1. VMS 는 서버 응답에서 진행 수량을 즉시 돌려받아 헤더 진행률에 반영합니다.
  2. 동시에 서버가 접속 중인 모든 화면에 변경 사실을 알립니다.
  3. 같은 라인의 다른 VMS 와 관리자의 Dashboard / Andon Board / Alarms / Work Orders 화면이 모두 새로 고침 없이 즉시 갱신됩니다.
  4. Web 에서 Lot 을 발행/마감하면 VMS 헤더의 Lot 콤보도 수 초 안에 따라옵니다 (§4.11).

이 실시간 반영에 쓰이는 기술 이벤트 목록은 부록 §8.2 에 정리되어 있습니다.

5.5 다중 라인 운영

VMS 여러 대(여러 라인)를 하나의 Web 서버에 연결할 수 있습니다. 각 VMS 는 설치할 때 지정한 라인 번호(ClientIndex)로 구분됩니다 (1, 2, 3...).

  • 작업지시 목록은 라인 번호별로 분리되어, 각 라인은 자기 라인의 작업지시만 봅니다.
  • 작업자 로그인 세션도 라인별로 독립적입니다.
  • 관리자는 Andon Board 에서 모든 라인을 한 화면에서 모니터링할 수 있습니다.
라인 번호는 겹치면 안 됩니다: 같은 라인 번호(ClientIndex)로 VMS 두 대를 동시에 실행하지 마세요. 설치할 때 라인마다 번호를 미리 정해서 배정해 두는 것을 권장합니다.

한 PC 에서 두 라인 운용하기

PC 한 대에 카메라가 여러 대 연결되어 있으면, VMS 를 두 개 띄워 각각 다른 라인으로 운용할 수 있습니다. 실행할 때 인스턴스 이름을 붙이는 방식입니다:

  1. 바탕화면에 VMS 바로가기를 하나 더 만들고, 대상 끝에 --instance line2 를 붙입니다 (이름은 영문/숫자로 자유롭게).
  2. 설정 마법사(System Setup)도 같은 이름으로 실행합니다: VMS.AppSetup.exe --instance line2. 화면 위쪽에 인스턴스: line2 배지가 보이면 올바르게 실행된 것입니다.
  3. 마법사에서 2번 라인이 쓸 카메라와 라인 번호(ClientIndex)를 등록하고 저장합니다. 같은 카메라를 두 인스턴스에 겹쳐 등록하면 안 됩니다 — 카메라는 한 번에 한 프로그램만 연결할 수 있습니다.
  4. 이제 두 바로가기로 VMS 를 각각 실행하면, 서로 다른 카메라로 검사하고 Web 화면에는 두 개의 라인으로 표시됩니다.

인스턴스마다 설정 · 레시피 · 작업자 계정 · 검사 기록이 완전히 분리되어 보관됩니다. 이름 없이 실행하면 지금까지와 똑같은 기본 인스턴스로 동작합니다.

7. 트러블슈팅

자주 겪는 문제와 해결 방법입니다. 증상을 찾아 순서대로 확인해 보세요. PowerShell 명령이 나오는 항목은 ⚙ 관리자(또는 설치 담당자)용입니다.

7.1 VMS 측

실행하자마자 DLL 오류가 뜸

Windows 구성 요소(Visual C++ 재배포 패키지)가 없어서 생기는 문제입니다. Microsoft 공식 사이트에서 vc_redist.x64.exe 를 내려받아 설치하면 해결됩니다 (§2.1 요구사항 참고).

카메라가 자동으로 연결되지 않음

  1. System Setup(설정 마법사)에서 카메라 IP 주소와 제조사가 맞게 입력되어 있는지 확인합니다.
  2. ⚙ 방화벽이 카메라 통신(GigE Vision — UDP 3956 포트)을 막고 있지 않은지 확인합니다.
  3. ⚙ 네트워크 카드가 여러 개인 PC 라면, 카메라가 연결된 네트워크 카드가 우선되도록 네트워크 설정을 확인합니다.

검사 결과가 서버로 안 올라가고 계속 쌓임

Web 서버와의 연결이 끊긴 상태입니다. 검사 결과는 잃어버리지 않고 %LocalAppData%\BODA VISION AI\upload_queue\ 폴더에 파일로 보관되며, Web 서버가 다시 켜지면 몇 초 안에 자동으로 전송됩니다. 이 폴더의 파일 수가 줄어드는지를 보면 전송 여부를 확인할 수 있습니다.

[AUTO RUN] 버튼이 켜지지 않음

버튼 위에 마우스를 올리면 어떤 조건이 빠졌는지 말풍선으로 알려 줍니다. 다음을 차례로 확인하세요:

  1. 카메라가 연결되어 있는지 (헤더에 연결 표시).
  2. 작업자가 로그인되어 있는지 (헤더 Operator 칩에 이름 표시).
  3. 작업지시가 선택되어 있는지 (헤더에 WO 칩 표시).
  4. 작업지시 상태가 예정(Planned) 또는 진행 중(InProgress)인지 — 완료된 작업지시로는 검사를 시작할 수 없습니다.

7.2 Web 측

⚙ 이 절은 관리자용입니다. 서버 로그 확인과 PowerShell 명령을 다룹니다.

Web 서비스가 시작되지 않음

  1. Windows 이벤트 뷰어에서 오류 로그를 확인합니다: Event Viewer → Windows Logs → Application → "BODA-VMS-Web".
  2. 가장 흔한 원인은 포트 충돌입니다. 다른 프로그램이 7144 포트를 쓰고 있는지 확인합니다: netstat -ano | findstr 7144
  3. HTTPS 인증서 문제라면 인증서를 신뢰 목록에 등록합니다: dotnet dev-certs https --trust

로그아웃한 작업자가 계속 "작업 중"으로 표시됨

VMS 가 비정상 종료되면 작업자 세션이 서버에 열린 채로 남을 수 있습니다. 보통은 다음처럼 자동으로 정리됩니다:

  • VMS 를 정상 종료하면 세션도 함께 종료됩니다.
  • 생존 신호(Heartbeat)가 5분 이상 끊긴 클라이언트의 세션은 Web 서버가 시작할 때 자동으로 정리합니다.
  • 바로 정리해야 한다면 Web 서비스를 재시작하세요.

Operators 의 Sessions 탭이 갱신되지 않음

이 화면은 원래 새로 고침 없이 자동으로 갱신됩니다. 갱신되지 않으면:

  • 로그인이 만료되었을 수 있습니다. 로그아웃했다가 다시 로그인해 보세요.
  • 페이지를 새로 고침(F5)해서 실시간 연결을 다시 맺어 보세요.

알림 종 배지가 보이지 않음

브라우저에 이전 버전 화면이 저장(캐시)되어 있는 경우입니다. 강력 새로 고침(Ctrl+Shift+R)으로 캐시를 지우면 해결됩니다.

7.3 통합 / 네트워크

⚙ 이 절은 관리자용입니다.

VMS 가 Web 서버에 연결하지 못함

  1. VMS 의 System Setup 에서 서버 주소(WebServerUrl)가 맞는지 확인합니다 (예: https://192.168.0.10:7144).
  2. Web 서버 PC 의 방화벽 규칙이 살아 있는지 확인합니다: Get-NetFirewallRule -DisplayName "BODA VMS Web*"
  3. 운영 환경에서는 신뢰할 수 있는 인증서(사설 CA) 사용을 권장합니다. 자체 서명(self-signed) 인증서는 개발 · 테스트용입니다.

다른 VMS 의 검사가 내 화면에 반영되지 않음

실시간 연결이 잠시 끊긴 경우입니다. 연결은 몇 초 간격으로 자동 재시도되므로 보통 스스로 복구됩니다. 오래 지속되면 네트워크 상태와 Web 서버가 켜져 있는지 확인하세요.

검사 결과가 Web 에 보이지 않음

  1. VMS 의 업로드 보관 폴더(%LocalAppData%\BODA VISION AI\upload_queue\)에 파일이 쌓여 있는지 확인합니다 — 쌓여 있다면 네트워크가 끊긴 것입니다 (§7.1 참고).
  2. Web 서버의 이벤트 뷰어 로그에서 검사 결과 수신 기록이 있는지 확인합니다.
  3. 레시피와 라인 번호(ClientIndex)가 VMS 와 Web 양쪽에서 일치하는지 확인합니다.

Web 에서 만든 레시피가 VMS 에 보이지 않음

  1. VMS 사이드 패널 Recipe 섹션의 새로고침(⟳) 버튼을 누르고, 상태바의 요약 메시지를 확인합니다 — "Web 레시피 N개 — 새 항목 M, 이름 연결 K" 형태로 방금 가져온 결과를 알려 줍니다 (§3.3).
  2. 요약이 0개로 나오면 레시피가 다른 라인으로 만들어진 경우가 대부분입니다. Web 의 검사 항목 화면에서 레시피의 대상 라인과 이 VMS 의 라인 번호(ClientIndex)가 같은지 확인하세요 (§4.9).
  3. VMS 나 비전 설정을 시작할 때 "Web 연동 비활성" 경고 창이 떴다면, 운영(Production) 보안 모드에서 서버 주소가 안전하지 않은 원격 http 주소로 설정되어 Web 연동이 꺼진 것입니다. System Setup 에서 서버 주소를 https://... 로 바꾸세요 (같은 PC 를 가리키는 localhost 주소는 http 여도 됩니다).
