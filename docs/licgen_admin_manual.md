# LicGen 라이선스 발급 — 관리자 매뉴얼

문서 버전: v1.0 (2026-10-26) · 대상: 본사 라이선스 발급 담당자 (사내 전용)

이 문서는 발급 프로그램 **LicGen(`LicGenApp.exe`)의 화면 사용법**을 설명한다.
키 체계·백업 규칙·키 교체(rotation) 같은 운영 원칙은 [license_operations.md](license_operations.md),
설계 근거는 [design/license-spec.md](design/license-spec.md) 가 기준이다.
고객 PC 에서 라이선스를 설치하는 방법은 사용자 매뉴얼 §2.6 · §3.8 에 있다.

---

## 1. 한눈에 보기

```
① 대상 PC 지문 받기 ─→ ② LicGen 에서 발급 ─→ ③ license.lic 를 대상 PC 에 설치 ─→ ④ USB 2부 백업
   (AppSetup 7단계)      (대장 자동 기록)        (AppSetup [가져오기])            (발급한 주 말일까지)
```

- 라이선스 파일은 **대상 PC 의 지문에 묶인다** — 다른 PC 에 복사하면 "지문 불일치"로 거부된다.
  그래서 파일을 USB · 메일 · 메신저로 보내도 안전하다.
- 발급할 때마다 **발급 대장**(`ledger.jsonl`)에 자동으로 한 줄이 기록된다. 계약 관리의 근거다.
- 서명에 쓰는 **개인키가 체계 전체의 급소**다. 키 폴더를 리포 · 클라우드 · 메신저 · 메일에 절대 올리지 않는다.

## 2. 준비

### 2.1 발급 PC 와 키 폴더

발급은 지정된 발급 PC(현재: 개발 PC) 한 대에서만 한다. 그 PC 의 사용자 폴더에 키 폴더가 있어야 한다.

```
C:\Users\<사용자>\.boda-licgen\
  ├─ prod-2026.private.pem   ← 고객 발급용 개인키 (Production · Trial)
  ├─ dev-2026.private.pem    ← 사내 발급용 개인키 (Internal)
  ├─ *.public.txt            ← 공개키 (참고용)
  ├─ ledger.jsonl            ← 발급 대장 (직접 편집 금지)
  ├─ ledger-notes.json       ← 대장 비고 (LicGen 이 관리)
  └─ backup-marker.json      ← 백업 기록 (LicGen 이 관리)
```

발급 PC 를 새로 세팅했거나 키 폴더가 없으면, USB 백업본(`<USB>\boda-licgen-backup\`)의 파일 전체를
위 폴더로 복사한다. **최신 대장이 있는 백업본**을 써야 한다 — 오래된 대장으로 복원하면 라이선스 번호가 겹친다
(두 백업본의 `ledger.jsonl` 줄 수를 비교해 많은 쪽을 쓴다).

### 2.2 프로그램 실행

LicGen 은 MSI 에 들어 있지 않다. 리포에서 직접 빌드해 실행한다.

```powershell
cd D:\Repo\VMS
dotnet build tools\LicGen.App
& "tools\LicGen.App\bin\Debug\net8.0-windows7.0\LicGenApp.exe"
```

관리자 권한은 필요 없다.

## 3. 화면 구성

창은 위에서부터 **상태 배너**와 **탭 2개**([라이선스 발급] · [발급 대장])로 되어 있다.

### 3.1 상태 배너 (창 상단)

| 표시 | 의미 | 할 일 |
|---|---|---|
| `서명 키: dev-2026 · prod-2026` | 키 폴더에서 찾은 개인키 | 정상 |
| `개인키 없음 — ...` (빨간 글자) | 키 폴더에 `*.private.pem` 이 없음 | §2.1 대로 키 폴더 복원 |
| `마지막 백업 2026-08-26 · 매체 2부 · 백업 미반영 발급 0건` | 백업이 최신 | 정상 |
| `... 백업 미반영 발급 N건 — 발급 주 말일까지 2부 갱신` (노란 글자) | 마지막 백업 뒤에 발급한 건이 있음 | 그 주 말일까지 USB 2개에 [백업 실행] (§6) |
| `백업 기록 없음 — ...` (노란 글자) | 이 PC 에서 백업한 적이 없음 | USB 2개에 [백업 실행] |

- **[새로 고침]**: 키 폴더 · 백업 상태 · 대장을 다시 읽는다. 키 파일을 복사해 넣은 뒤 누른다.
- **[백업 실행]**: §6 참조.

### 3.2 [라이선스 발급] 탭

| 항목 | 입력 | 설명 |
|---|---|---|
| 고객명 | 필수 | 대장에 남는 계약 이름. 나중에 찾기 쉽게 "고객사 + 설치 위치"로 적는다 (예: `세연공장 실증 PC`) |
| 종류 | Production / Trial / Internal | Production=고객 납품, Trial=데모·평가, Internal=사내 테스트·개발 |
| 서명 키 | 자동 | 종류를 고르면 자동으로 정해진다 — Production·Trial → `prod-*`, Internal → `dev-*`. 바꾸지 않는다 |
| 대상 PC 지문 | 필수 | 대상 PC 의 `XXXXX-XXXXX-XXXXX` 코드 (§4.1). 소문자로 쳐도 대문자로 바뀐다. Internal 만 `*` (모든 PC) 허용 |
| 좌석 수 | 숫자, 1 이상 | 단일 PC = `1`. 서버+다수 라인 PC 구성은 서버 지문으로 **계약 라인 PC 수** (§7.2) |
| 유지보수 만료 | 날짜 (기본: 오늘+1년) | 이 날짜가 지나면 **업데이트만 막히고 실행은 계속된다** |
| 실행 만료 | 날짜 또는 빈칸 | Production 은 **빈칸(영구)**. Trial · Internal 은 필수 — 지나면 14일 유예 뒤 사용 제한 대상. 날짜 글자를 지우면 빈칸이 된다 |
| [발급] | | 규칙 확인 → 요약 확인 → 저장 위치 선택 → 발급 (§4.2) |

### 3.3 [발급 대장] 탭

- 지금까지 발급한 라이선스 전체가 **최신순**으로 보인다 (위쪽 글에 총 건수와 대장 파일 위치).
- 열: 라이선스 ID · 고객명 · 종류 · 지문 · 좌석 · 유지보수 · 실행 만료(`영구` = 만료 없음) · 발급 시각 · 발급자 · 비고.
- 아래 **비고** 칸: 선택한 줄에 메모를 달고 **[비고 저장]**. 재발급 사유, 폐기 표시 등을 적는다.
  비고는 대장과 별도 파일(`ledger-notes.json`)에 저장되고, 대장 자체는 바뀌지 않는다.

## 4. 발급 절차

### 4.1 지문 받기

대상 PC 에서 다음 중 하나로 지문 코드를 확인한다.

- **AppSetup 7단계 (Security & License)** — 지문 코드 옆 [복사] 버튼. 현장 엔지니어가 전화 · 메신저로 불러준다.
  헷갈리는 글자(0/O, 1/I)는 코드에 쓰이지 않는다.
- 리포가 있는 PC 라면 CLI: `dotnet tools\licgen\bin\Debug\net8.0-windows7.0\licgen.dll fingerprint`

### 4.2 LicGen 에서 발급

1. [라이선스 발급] 탭에서 **종류**를 먼저 고른다 (서명 키가 자동으로 맞춰진다).
2. 고객명 · 지문 · 좌석 수 · 유지보수 만료 · 실행 만료를 입력한다.
3. **[발급]** 을 누른다.
   - 규칙에 맞지 않으면 **"발급 규칙 위반"** 창이 뜨고 아무것도 기록되지 않는다 (§8 표).
4. **"발급 확인"** 창에서 요약(고객명 · 종류 · 서명 키 · 지문 · 좌석 · 만료일)을 확인하고 [확인].
   - 여기서 취소하면 아무것도 기록되지 않는다.
5. **저장 위치**를 고른다. 파일 이름은 `license.lic` 그대로 둔다 (설치 시 이 이름을 찾는다).
   - 고객 PC 용이면 USB 나 바탕화면에, **발급 PC 자신에게 설치할 때는** `C:\ProgramData\BODA\VMS\` 에 바로 저장해도 된다 (§5.2).
   - 저장 창에서 취소하면 발급되지 않는다.
6. **"발급 완료"** 창에 라이선스 ID(`LIC-2026-000N`) · 파일 위치 · 대장 위치가 표시된다.
   고객명 · 지문 칸은 다음 발급을 위해 비워진다.
7. [발급 대장] 탭 맨 위에 새 줄이 생기고, 배너의 "백업 미반영 발급" 이 1 늘어난다 → §6.

> 라이선스 ID 는 대장 줄 수로 자동으로 매겨진다 (`LIC-연도-순번`). 직접 정할 수 없다.

### 4.3 발급 파일 확인 (선택)

설치 전에 파일이 대상 PC 지문에 맞는지 확인할 수 있다.

```powershell
dotnet tools\licgen\bin\Debug\net8.0-windows7.0\licgen.dll verify --file <license.lic 경로> --fingerprint <대상 PC 지문>
```

`상태: Valid` 면 정상. `--fingerprint` 를 빼면 지금 PC 의 지문으로 확인한다.

## 5. 설치

### 5.1 고객·현장 PC — AppSetup 으로 가져오기

1. `license.lic` 를 USB 등으로 대상 PC 에 옮긴다.
2. 대상 PC 에서 **AppSetup → 7단계 (Security & License) → [라이선스 파일 가져오기...]** 로 파일을 고른다.
   (쓰기 권한이 없으면 Windows 권한 확인 창이 한 번 뜬다.)
3. "현재 상태" 가 **정상**, 고객명 · 좌석 수가 발급 내용과 같은지 확인한다.

파일은 `C:\ProgramData\BODA\VMS\license.lic` 에 설치된다. VMS 와 Web 서버가 이 파일 하나를 함께 쓴다.

### 5.2 직접 복사로 설치

AppSetup 을 쓰지 않고 `C:\ProgramData\BODA\VMS\license.lic` 에 파일을 직접 두어도 된다 (같은 이름이 있으면 덮어쓰기).
설치 뒤 확인:

```powershell
dotnet tools\licgen\bin\Debug\net8.0-windows7.0\licgen.dll verify --file C:\ProgramData\BODA\VMS\license.lic
```

### 5.3 Web 서버 PC

- Web 서버는 요청마다 파일을 다시 읽으므로 **서비스 재시작이 필요 없다.**
- Web 에 관리자(Admin)로 로그인 → **시스템 관리 → SW 라이선스** (`/admin/license`, 사용자 매뉴얼 §8.24) 에서
  라이선스 정보 · 서버 지문 · 사용 중인 좌석을 확인한다.

## 6. 백업 (발급한 주 말일까지)

규칙: **발급이 있었던 주의 말일까지 USB 2개(서로 다른 장소 보관)를 모두 갱신**한다.

1. 백업용 USB(또는 외장 디스크)를 꽂는다.
2. 상단 **[백업 실행]** → 폴더 선택 창에서 **USB 드라이브 맨 위(예: `E:\`)** 를 고른다.
3. "백업 완료" 창: 복사한 파일 수 · 대상 폴더(`E:\boda-licgen-backup`) · 매체 이름 · 대장 건수.
   - "다른 USB 에도 한 번 더 실행하세요" 가 나오면 아직 1부뿐이다.
4. 두 번째 USB 로 바꿔 꽂고 1~3 을 반복한다.
5. 배너가 `매체 2부 · 백업 미반영 발급 0건` 이 되면 끝.

- 매체는 **볼륨 이름 + 일련번호**로 구분한다. 두 USB 가 같은 드라이브 문자(E:)로 잡혀도 따로 집계된다.
- 지금 등록된 백업 매체: `T7 Shield`, `KGD-SSD` (backup-marker.json 기준).
- "대장 복사 크기 불일치" 오류가 나면 매체 문제다 — 다른 매체로 다시 백업한다.

## 7. 상황별 발급 예

### 7.1 고객 단일 PC (가장 흔함)

| 항목 | 값 |
|---|---|
| 종류 | Production |
| 지문 | 그 PC 의 지문 |
| 좌석 | 1 |
| 유지보수 만료 | 계약 기간 끝 (기본 1년) |
| 실행 만료 | 빈칸 (영구) |

### 7.2 Web 서버 + 라인 PC 여러 대

- **서버 PC 한 대에만** 발급 · 설치한다. 지문 = **서버** 지문, 좌석 = **계약 라인 PC 수**.
- 라인 PC 는 발급하지 않는다 — 서버에서 좌석을 자동으로 빌려 쓴다.
- Web 서버가 여러 대인 현장은 서버마다 따로 발급하고, 좌석은 **그 서버에 붙는 라인 PC 수**로 나눠 적는다
  (합 = 계약 수). 라인을 다른 서버로 옮기면 재발급 대상이다.

### 7.3 데모 · 평가 (Trial)

종류 Trial · 고객 PC 지문 · 실행 만료 = 영업 협의 기간 끝. 서명 키는 prod 로 자동 지정된다.

### 7.4 사내 테스트 · 개발 (Internal)

종류 Internal · 지문은 특정 PC 지문 또는 `*`(모든 PC) · 실행 만료 **오늘부터 90일 이내** 필수.
서명 키는 dev 로 자동 지정된다. **고객에게 Internal 라이선스를 주지 않는다.**

### 7.5 재발급 (PC 교체 · 파일 분실 · 조건 변경)

- 지문은 3묶음 중 **2묶음이 같으면** 같은 PC 로 인정한다.
  (1묶음 = Windows 설치, 2묶음 = 네트워크 카드, 3묶음 = CPU 모델)
  Windows 재설치나 네트워크 카드 교체 하나만으로는 기존 파일이 계속 유효하다.
- 그 이상 바뀌었거나, 파일을 잃어버렸거나, 좌석 · 기간을 바꿀 때는 **새로 발급**한다. 라이선스 ID 는 새 번호가 된다.
- 발급 후 [발급 대장] 에서 **새 줄과 옛 줄 모두에 비고**를 단다.
  예: 새 줄 `LIC-2026-0003 재발급 — 파일 분실`, 옛 줄 `→ LIC-2026-0006 으로 대체`.
- 기존 조건(좌석 · 유지보수 만료)은 대장의 옛 줄을 보고 그대로 옮긴다.

## 8. 오류 · 경고 메시지

| 메시지 | 원인 | 조치 |
|---|---|---|
| 서명 키 없음 / 개인키 없음 | 키 폴더에 `*.private.pem` 없음 | §2.1 백업본에서 복원 후 [새로 고침] |
| 고객명은 비울 수 없음 | 고객명 빈칸 | 입력 |
| 지문 필수 | 지문 빈칸 | §4.1 |
| 좌석 수는 숫자로 입력하세요 / 좌석 수는 1 이상 | 좌석 칸 오류 | 1 이상의 숫자 |
| Production 은 지문 와일드카드 불가 | Production 에 `*` 입력 | 대상 PC 지문 입력 |
| Trial(Internal) 은 실행 만료(expires) 필수 | 실행 만료 빈칸 | 날짜 입력 |
| Internal 만료는 최대 90일 | 90일 넘는 만료일 | 90일 이내로 |
| 대상 PC 에서 "지문 불일치" | 다른 PC 지문으로 발급했거나 하드웨어가 2묶음 이상 바뀜 | 대상 PC 에서 지문을 다시 받아 재발급 |
| 대상 PC 에서 "유효하지 않음" | 파일이 손상됐거나 수정됨 | 원본 파일을 다시 전달 (메모장으로 열어 저장하지 않는다) |

## 9. 하지 말 것

- 개인키(`*.private.pem`)나 키 폴더를 리포 · 클라우드 · 메일 · 메신저로 옮기기
- `ledger.jsonl` 을 직접 편집하기 (줄 추가 · 삭제 시 라이선스 번호가 어긋난다) — 메모는 비고로
- 고객 발급에 dev 키 쓰기 / 고객에게 Internal 발급
- 발급한 `license.lic` 를 열어 수정하기 (서명이 깨져 무효가 된다)
- LicGen · licgen 을 MSI 나 고객 PC 에 넣기

## 부록. CLI 대응표

화면 없이 명령으로도 같은 일을 할 수 있다. 같은 키 폴더 · 같은 대장을 쓴다.
CLI 실행 파일: `dotnet tools\licgen\bin\Debug\net8.0-windows7.0\licgen.dll <명령>` (먼저 `dotnet build tools\licgen`).

| 화면 | CLI |
|---|---|
| 지문 확인 | `licgen fingerprint` |
| [발급] | `licgen issue --key <키 폴더>\prod-2026.private.pem --key-id prod-2026 --customer "고객명" --fingerprint XXXXX-XXXXX-XXXXX --max-clients 1 --maintenance-until 2027-10-26 --out license.lic` (Trial/Internal 은 `--kind`, `--expires` 추가) |
| 발급 파일 확인 | `licgen verify --file license.lic [--fingerprint <지문>]` |
| [백업 실행] | `licgen backup --to E:\` |
