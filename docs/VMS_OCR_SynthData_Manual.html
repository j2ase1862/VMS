OCR 합성 데이터 생성기

PP-OCR fine-tuning 및 OCV 학습용 라벨링된 합성 데이터셋 자동 생성

대상 VMS.VisionSetup ≥ 2026.05 출력 PaddleOCR rec / OCV char patches 사용 권한 비전 엔지니어

1. 개요

산업 라벨(LOT, 시리얼, 유통기한 등) OCR 인식률을 끌어올리기 위해 PP-OCRv4 rec 모델 fine-tuning 또는 OCV(Optical Character Verification) 폰트 라이브러리에 학습시킬 데이터를 자동 생성합니다. 사용자가 패턴(예: DD/MM/YYYY)과 폰트를 지정하면, 유효한 무작위 문자열을 생성 → 폰트로 렌더 → 배경 합성 → 증강을 거쳐 PaddleOCR 학습 포맷으로 저장합니다.

특징 — 토큰 기반 mini-DSL이라 OCR Output Format과 같은 표기법을 그대로 사용. 알려진 날짜 패턴은 실제 유효한 datetime 값으로 생성되어 학습 분포 가치를 보존합니다.

2. 언제 사용하나

  • PP-OCR가 산업용 폰트(스텐실, 도트, 임프린트)에서 / → 7처럼 시각적 혼동을 보일 때
  • 실제 라벨 이미지가 부족(50장 미만)해서 직접 학습이 어려울 때
  • 새로운 라벨 형식이 도입되어 모델 재학습이 필요할 때
  • OCV 폰트 라이브러리에 등록할 문자 patch가 부족할 때

3. 실행

▶ 메뉴 Run › OCR Synth Data... 클릭 → 설정 윈도우 오픈

4. 폰트 설정

항목설명권장
기본 폰트시스템 설치 폰트 콤보에서 선택Arial / Consolas
추가 폰트줄바꿈/콤마 구분 — 생성 시 무작위 선택다수 등록 시 분포 다양화
크기 Min/Max (px)이 범위에서 무작위 크기 선택28 / 64
Bold/Italic 무작위스타일 변동 추가ON
중요 — 학습 효과의 가장 큰 변수는 실제 라벨 폰트와 합성에 쓴 폰트의 유사도입니다. 대상 라벨이 OCR-A/B나 특수 산업 폰트면 해당 TTF를 시스템에 설치한 뒤 추가 폰트에 등록하세요. 일반 시스템 폰트로만 학습하면 distribution gap이 남습니다.

5. 패턴

한 줄에 한 패턴 입력. 프리셋 버튼으로 자주 쓰는 패턴 빠르게 추가:

DD/MM/YYYY
DDDDDDD
YYYY-MM-DD HH:MM:SS
LOT-DDDDDDDD

실행 시 패턴 하나가 무작위로 선택되어 샘플 생성. 각 패턴은 다음 규칙으로 무작위 문자열로 변환:

토큰의미예
D M Y H S f숫자 (0~9)D → 7
L영문자 대문자L → A
A영숫자A → K 또는 3
?임의 (영숫자)? → 5
그 외리터럴 — 그 자리에 그대로 출력/, -, :, ., 공백
스마트 생성 — 알려진 datetime 패턴(DD/MM/YYYY, YYYY-MM-DD HH:MM:SS 등)은 실제 유효한 날짜/시간 값으로 채워집니다 (예: 31일 ≠ 02월). 무의미한 조합 방지.

9. 생성 실행

1모든 설정 입력 후 Generate 클릭
2진행률 바로 상태 확인 (UI 멈춤 없음 — 백그라운드 비동기 실행)
3완료 후 상태 메시지에 train N + val M 표시

1,000샘플 약 30~60초 (폰트 크기와 증강 설정에 따라).

10. 출력 구조

output_dir/
├── train_crops/      # 000001.png ~ (학습 이미지)
├── val_crops/        # 000123.png ~ (검증 이미지)
├── train_rec.txt     # 각 줄: train_crops/000001.png\t31/03/2099
├── val_rec.txt       # 검증 라벨 파일
└── dict.txt          # 학습 데이터에 나타난 unique char 목록
dict.txt는 PP-OCR 학습 시 character set 정의에 그대로 사용됩니다. 생성된 데이터에 등장하지 않는 문자는 학습되지 않으므로, 모든 필요한 문자가 포함됐는지 생성 후 확인하세요.

11. PP-OCR Fine-tuning

이미 존재하는 VMS.VisionSetup/scripts/train_ppocr.py로 학습:

python VMS.VisionSetup/scripts/train_ppocr.py \
  --target recognition \
  --dataset output_dir \
  --output trained_model_dir \
  --epochs 50 \
  --pretrained models/ppocr/ch_PP-OCRv4_rec_infer
사전 학습 모델(ch_PP-OCRv4_rec_infer)부터 fine-tuning하면 훨씬 빠르게 수렴하고 generalization도 좋습니다. 0부터 학습은 권장하지 않음.

12. 학습 모델 적용

1 OCR Tool Settings → Engine = PPOcrOnnx
2 Custom Rec Model 필드의 📂 Browse 버튼 클릭 → 학습 결과 .onnx 선택
3 Custom Dict File → dict.txt 선택
4 Recipe 재실행 → 인식률 검증

13. 실전 팁

  • 현실 50장 + 합성 2,000장 혼합이 가장 안정적. 합성만으로는 distribution gap이 남습니다.
  • From Folder 모드 권장 — 실제 라벨에서 텍스트 없는 영역(여백, 라벨 가장자리)을 잘라 폴더에 모아두세요. 100~500장이면 충분히 다양성 확보.
  • 대상 폰트 확보 — 라벨 폰트와 다르면 효과 제한적. OCR-A/B 또는 산업용 폰트 .ttf를 구해 시스템에 설치 후 추가 폰트에 등록.
  • 증강 단계적 강화 — 첫 학습은 약한 증강(회전 3°, blur 3)으로 시작, 검증 인식률이 정체되면 강한 증강(회전 8°, blur 5, noise 15)으로 재학습.
  • RandomSeed 고정 (테스트용) — 디버깅 시 결과 재현 가능.

15. 문제 해결

생성된 텍스트가 잘림

폰트 크기가 너무 크거나 패딩 부족. FontSizeMax를 줄이거나 폰트 크기 분포 조정. 패딩은 코드 상수(10px)로 고정 — 글자 굵기 큰 폰트는 영향 받을 수 있음.

From Folder 모드인데 배경이 단색으로 나옴

지정 폴더에 jpg/png/bmp 파일이 없거나 경로 오류 → Solid 모드로 fallback. 폴더 경로와 파일 존재 확인. 1개라도 있어야 동작.

학습 모델 적용 후 오히려 인식률 저하

  • 합성 폰트가 실제 라벨 폰트와 너무 다름 → 폰트 교체
  • 증강이 너무 약함 → 회전/blur/노이즈 강화
  • 샘플 수 부족 → 5,000장 이상으로 증가
  • dict.txt에 실제 필요한 문자 누락 → 패턴 추가 후 재생성

dict.txt에 한국어/특수문자가 빠짐

패턴에 직접 리터럴로 포함되어야 합니다. ? 토큰은 영숫자만 생성하므로 한국어가 필요한 경우 Custom 패턴에 한국어 char를 직접 작성:

LOT-가나다-DDDDDD
유통기한: DD/MM/YYYY

UI 멈춤

샘플 수가 10,000을 넘으면 메모리 사용량과 처리 시간 증가. 첫 실행은 1,000~2,000으로 시작. 배치 분할 실행 권장.
