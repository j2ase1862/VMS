## 0. 이 문서의 사용법

각 항목은 **문제 → 근거(코드 위치) → 요구 동작 → 수용 기준** 형식이다.
수용 기준은 `VMS.WeldTeach.Tests`의 테스트로 검증 가능해야 한다.

**P0 실기 실증(두산 M 시리즈) 착수 전에 우선순위 1~3을 완료한다.** 실제 시편과 로봇에
경로를 내보내기 전에 닫아야 하는 항목이다.

리뷰 배경: 핵심 알고리즘(ICP 멀티스타트, 점-표면 RMSE 평가, 호길이 스텝오버 보정,
모폴로지 패딩, 반 스텝 인셋)은 수준이 높고 수정 대상이 아니다. 아래 항목은 대부분
**"감지했으나 행동하지 않음", "개별로는 옳으나 조합에서 깨짐", "미래 소비자를 위한 계약
미선언"** 세 유형에 속한다.

## 우선순위 1 — P0 착수 전 필수

### ① 2.5D 위반 셀이 경고만 되고 마스킹되지 않음 · **안전**

**문제.** 높이맵 셀 높이가 `hSum / cnt`(평균)이다. 한 셀에 상면과 하면이 함께 들어오면
평균은 두 면 사이의 허공이고, **경로점이 소재 내부에 생성된다.**

**근거.** `Services/CoveragePathService.cs`

```csharp
if (hMax[ia, ib] - hMin[ia, ib] > ambThresh) ambiguous++;   // occupied 는 true 유지
...
hVal[ia, ib] = hSum[ia, ib] / cnt[ia, ib];                  // 평균 → 내부
```

`Ambiguous25DCells`는 집계·반환되지만 `mask`에 반영되지 않는다. 합성 시편에서는 발현
하지 않고 실제 스캔(리브 모서리, 얇은 벽, 관통 구멍 테두리)에서 발현한다.

**요구 동작.** `CLAUDE.md §3.1`에 따라 위반 셀은 `mask`에서 제외한다.
`GrindingParams`에 `Ambiguous25DPolicy { Exclude, UseUpperSurface }` 를 추가하고
**기본값은 `Exclude`** 로 한다. `UseUpperSurface` 선택 시 평균 대신 `hMax`(+e3 극값)를
쓴다. 제외로 인해 영역이 소실되면 예외가 아니라 사용자 통지로 처리한다.

**수용 기준.**
- 오버행 합성 점군(상면 + 그 아래 하면)에서 생성된 경로점 중 소재 내부에 있는 점이 **0개**
- `Exclude` 정책에서 위반 셀을 지나는 스캔라인 점이 **0개**
- 기존 5종 합성 표면(평면·경사·원통·범프·구멍)의 라인 수·커버 면적 **변화 없음**
- `--selftest`의 `GRINDING M1~M6` 전부 통과 유지

---

### ② JSON에 공구축·좌표 규약이 선언되지 않음 · **계약**

**문제.** 내보내기 페이로드에 `eulerConvention: "ZYX(deg)"`는 있으나, **X = 공구축,
Z = 진행 방향**이라는 프레임 규약이 없다. 협동로봇 플랜지는 통상 Z가 어프로치 축이라
정확히 어긋나 있다. P0의 핵심 산출물이 JSON→DRL 변환기인데, 이 매핑이 변환기 코드에만
암묵적으로 존재하면 로봇 기종 추가 시 재현되는 사고가 된다.

**근거.** `Services/CoveragePoseService.ExportJson`

**요구 동작.** `CLAUDE.md §4`의 필수 필드를 페이로드 최상단에 추가한다.

```json
{
  "schemaVersion": "1.0",
  "units": "mm",
  "eulerConvention": "ZYX_intrinsic_deg",
  "toolAxis": "X",
  "travelAxis": "Z",
  "matrixConvention": "column_vector_row_major",
  "frame": "robot_base"
}
```

기존 `frame` 필드의 한국어 서술문("robot base coordinates (T_cam2base 적용됨)")은
기계 판독 가능한 열거값(`"robot_base"` / `"camera"`)으로 바꾸고, 서술은 별도
`frameNote`로 옮긴다.

**수용 기준.**
- 위 7개 필드가 모두 존재하고 값이 스키마와 일치
- `frame` 값이 `robot_base` 또는 `camera` 둘 중 하나
- `T_cam2base` 미입력 시 `frame == "camera"`, 입력 시 `"robot_base"`
- 내보낸 파일을 `HandEyeMatrix` 로더에 다시 넣는 왕복이 여전히 동작

---

### ③ 곡면 피팅 모드에서 후처리 평활이 그대로 실행됨 · **정밀도**

**문제.** `CloseSegment`가 `fitted` 여부와 무관하게 `SmoothHeights`를 호출한다.
`UseSurfaceFit`으로 해석적 곡면에서 높이를 얻은 뒤 다시 이동평균(창 3)을 먹이는 구조라,
M7에서 확인한 개선분(원통 표면편차 0.140 → 0.040 mm)을 일부 되돌린다.

부수적으로 `SmoothHeights`는 X·Y·Z를 함께 평균하므로 볼록 구간에서 코드 단축이 생기고,
`PointNormals`는 평활하지 않으므로 **평활 후 위치와 법선이 불일치**한다.

**근거.** `Services/CoveragePathService.CloseSegment` / `SmoothHeights`

**요구 동작.** `CLAUDE.md §3.2`에 따라,
1. `fitted != null` 이면 `SmoothHeights`를 **건너뛴다**
2. 높이맵 모드의 평활은 **높이(h) 성분만** 대상으로 한다. 주평면 좌표 (a, b)는 보존
3. 평활 후 법선을 갱신하거나, 갱신하지 않는다면 그 이유를 주석으로 남긴다

**수용 기준.**
- 원통 셸에서 `UseSurfaceFit = true`의 표면 편차가 `false` 대비 **개선**된다
  (등가 이하이면 실패 — 옵션의 존재 이유가 없으므로)
- 원통 셸 법선 요동(인접 포즈 간 각도차 표준편차)이 피팅 모드에서 더 작다
- 평면 표면에서 두 모드의 경로점 좌표 차이가 1e-6 mm 이내 (평면은 평활해도 불변)

## 우선순위 2 — P0 진행 중

### ④ 오목면 다층 패스 자기교차 미검사

**문제.** `p = f.P - depth * f.N` 으로 표면 법선 반대 방향 오프셋을 한다. 오목 구간에서
누적 깊이가 국부 곡률반경을 넘으면 오프셋 곡면이 접혀 경로가 자기교차한다. 검사가 없다.

타깃 공정이 **용접비드 경연삭**이면 대상 형상은 대부분 오목(필릿)이므로 실제로 만나는
조건이다.

**근거.** `Services/CoveragePoseService.ComputeSegmentPoses` 4) 다층 패스 블록

**요구 동작.** `CLAUDE.md §3.3` — 영역의 최소 오목 곡률반경 `R_min`을 산출하고,
누적 깊이 `(PassCount − 1) × DepthPerPassMm ≥ R_min` 이면 패스 수를 자동 제한하고
사용자에게 통지한다. 곡률은 `SurfacePatchFitService`의 다항식 계수에서 얻을 수 있고,
높이맵 모드에서는 인접 셀 유한차분으로 근사한다.

**수용 기준.**
- 오목 원통(R = 20) 영역, `DepthPerPassMm = 5`, `PassCount = 6`(누적 25 > 20) 요청 시
  패스가 4 이하로 제한되고 경고가 반환된다
- 볼록 원통에서는 제한이 걸리지 않는다 (오목 방향만 판정)
- 평면에서 `PassCount`가 요청값 그대로 유지된다

---

### ⑤ 절입 기준축이 명시되지 않음

**문제.** 절입은 표면 법선 `f.N` 기준인데 공구축 `f.X`는 리드·틸트만큼 기울어져 있다.
공구축 기준 실효 깊이는 `depth · cos(합성각)`이다. 리드 10°면 1.5%지만 틸트 20°까지
쓰면 5%를 넘는다. 현장에서 절입량을 캘리브레이션할 때 계통 오차로 나타난다.

**요구 동작.** `GrindingParams.DepthPerPassMm`의 기준축을 결정하고 명시한다
(권장: 공구축 기준). UI 툴팁과 JSON `parameters`에 `depthAxis: "toolAxis"` 또는
`"surfaceNormal"` 로 선언한다.

**수용 기준.**
- 리드 0°·틸트 0°에서 두 규약의 결과가 동일
- 리드 20°에서 공구축 기준 선택 시 법선 기준 대비 절입 깊이가 `1/cos(20°)` 배
- JSON에 `depthAxis` 필드 존재

---

### ⑥ 힘 파라미터가 영역 단위 — 스키마만 선반영

**문제.** `TargetForceN`이 영역당 하나다. 연마 품질이 갈리는 지점은 곡률 변화 구간의 힘
조절이므로, Lv3(적응 가공)에 가면 **포즈 단위**가 필요하다. 파일럿 고객이 붙은 뒤에
JSON 스키마를 바꾸는 것은 비용이 크다.

**요구 동작.** 지금은 구현하지 않는다. **스키마에만 옵셔널 필드를 뚫어둔다.**
`poses[]` 원소에 `forceN`(nullable), `feedRateMmS`(nullable)을 추가하고, 미지정 시
영역 파라미터를 상속한다는 규칙을 문서화한다.

**수용 기준.**
- 포즈에 값이 없으면 필드가 출력되지 않는다 (기존 파일 크기 회귀 방지)
- 값이 설정되면 포즈 단위로 출력되고, 소비자는 영역값보다 우선 적용한다는 규칙이
  `schemaVersion` 문서에 기재됨

## 우선순위 3 — P1 착수 전

### ⑦ Lv1 자동 곡면 분할의 판정 기준 — 로드맵 결합점

**문제.** 현재 경로 품질은 **오퍼레이터가 라쏘로 "자기 PCA 주평면에 단사 투영되는
패치"를 골라준다**는 암묵적 전제에 전적으로 의존한다. 사람은 대충 맞게 고른다.

P1의 Lv1(법선·곡률 리전 그로잉)을 **곡률 연속성만으로** 구현하면 원통 셸 전체가 하나의
연속 영역으로 나온다 — 곡률이 균일하므로. 그러나 그 영역은 자기 주평면에 단사 투영되지
않아 항목 ①의 조건에 직행한다. **자동 분할이 사람보다 자신 있게 틀린 영역을 만들어낸다.**

**요구 동작.** 분할 판정 기준에 **단사성 제약**을 포함한다.
후보 영역에 대해 자기 PCA 주평면 기준 2.5D 위반 셀 비율을 계산하고, 임계(권장 1%)를
넘으면 **분할을 계속**한다. 곡률 연속성은 필요조건이지 충분조건이 아니다.

`docs/design/robot-finishing-product-feasibility-review.md` §4.2 Lv1 항목에 이 제약을
반영한다.

**수용 기준.**
- 반각 40° 원통 셸을 자동 분할하면 단사 영역 2개 이상으로 쪼개진다
- 각 결과 영역의 2.5D 위반 셀 비율이 임계 이하
- 평면 패널은 1개 영역으로 유지된다 (과분할 방지)

---

### ⑧ 밴드 신장률에 상한이 없음

**문제.** 밴드 신장률을 `a` 전체의 **최대** 높이차로 계산한다. 주석에 "누락 연마 방지가
과커버보다 우선"이라는 의도가 명시돼 있으므로 버그는 아니다. 다만 **비용에 상한이 없다.**
넓은 평면 영역 한구석의 급경사 피처 하나가 영역 전체의 라인 간격을 좁혀 사이클 타임을
배로 만든다.

**근거.** `Services/CoveragePathService.cs` 4) 스캔라인 배치 블록

**요구 동작.** `CLAUDE.md §3.4` — 밴드 신장률에 상한(권장 1.5)을 두고, 초과 밴드가
존재하면 결과에 경고를 담아 **영역 분할을 권고**한다. Lv1 도입 후에는 자연히 완화된다.

**수용 기준.**
- 평면 한구석에 급경사 피처가 있는 합성 표면에서 라인 수가 상한 없는 경우 대비 감소
- 원통 셸의 기존 스텝오버 보정 동작(가장자리 1.10배 유지)은 변하지 않는다
- 신장률 초과 시 경고 플래그가 `CoverageResult`에 포함된다

---

### ⑨ 단위 테스트 프로젝트 부재

**문제.** `--selftest`의 M1~M6은 잘 만든 하네스지만 **엔드투엔드 스모크**다. 솔루션의
다른 프로젝트는 모두 xUnit 테스트를 갖고 있으나 `VMS.WeldTeach`만 없다. GS인증을
진행하는 조직 기준으로도 격차다.

**요구 동작.** `VMS.WeldTeach.Tests` (xUnit) 신설. 초기 구성은 첨부 스켈레톤 참조.
`--selftest`는 통합 스모크로 유지하고, 단위 테스트가 이를 대체하지 않는다.

**수용 기준.**
- `dotnet test VMS.sln` 에 포함되어 실행
- 항목 ①③④의 수용 기준이 테스트로 강제됨
- 5종 합성 표면의 수치 회귀 기준선(baseline)이 커밋에 기록됨

## 부록. 유지할 것 (수정 금지)

리팩터링 과정에서 아래를 단순화하려는 유혹이 있을 수 있으나, 모두 실측으로 도출된
대응이다. 제거 시 회귀한다.

| 항목 | 위치 | 이유 |
|---|---|---|
| ICP 멀티스타트 요 회전 16종 | `IcpService` | 부분 스캔 상면↔밑면 국소최소 — 실측 확인 |
| RMSE를 점-삼각형 거리로 평가 | `IcpService` | 점-점은 샘플 간격이 하한을 지배해 과대평가 |
| 닫힘 연산 1셀 패딩 | `CoveragePathService` | 침식이 경계 라인을 통째로 삭제 |
| 반 스텝 인셋 배치 | `CoveragePathService` | 경계 접선 슬리버 방지 |
| `OcctLifetime.Keep()` | `OcctLifetime` | 파이널라이저 힙 손상 (0xC0000374) |
| `LinesVisual3D` 일괄 교체 | `MainWindow` | `Points.Add` 반복은 O(N²), 14초 정지 |
| 그라인딩 모드의 OCCT 비의존 | 설계 | 라이선스 리스크를 용접 모드에 격리 |
