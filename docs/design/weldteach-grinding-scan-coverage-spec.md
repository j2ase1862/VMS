# 스캔 점군 기반 그라인딩 커버리지 경로 자동 생성 개발 명세서 (초안)

**Doc Version:** v0.1.0 (Draft)
**Target:** VMS.WeldTeach 확장 (Windows 11 / .NET 8.0 WPF)
**Domain:** 3D Vision & Robot Grinding/Polishing
**상위 문서:** CAD_Welding_Path_Specification v1.0.0 (용접 경로 명세 — 동일 앱 내 공정 모드 확장)

## 1. 개요 (Overview)

본 문서는 기존 VMS.WeldTeach(CAD 용접 경로 오프라인 티칭 PoC)를 확장하여,
**CAD 도면 없이** 3D 카메라 스캔 점군(Point Cloud)에서 직접 사용자가 가공 영역을
선택하고, 해당 표면을 덮는 **그라인딩 커버리지 경로(Coverage Path)** 와 공구 6-DoF
포즈를 자동 생성하는 모듈의 개발 명세서이다.

**접근 방식 (경로 B — 스캔 기반) 채택 사유:**

- CAD 도면과 그에 일치하는 실물 시편의 **페어 확보가 곤란** — CAD 기반(경로 A)은
  개발·정합 검증 모두 페어가 필요하다. 스캔 기반은 **임의 실물 스캔 또는 합성 점군**만으로
  전 단계 개발·검증이 가능하다.
- 경로가 처음부터 스캔(카메라) 좌표계에서 생성되므로 **CAD↔스캔 ICP 정합(T_align)이
  불필요** — 파이프라인이 한 단계 짧아진다.
- 그라인딩 모드에서 **OCCT(Occt.NET) 의존이 제거**된다 — 라이선스 불명 리스크가 용접
  모드에 국한된다.
- 참조 솔루션(HYM AARS)의 상용 검증된 워크플로우(스캔 → 곡면 분할 → 영역 선택 →
  궤적 생성)와 동일한 컨셉이다.

**용접 경로와의 차이:** 용접은 모서리를 따라가는 1D 곡선 경로, 그라인딩은 표면을
스텝오버(공구 폭 × 겹침률) 간격의 스캔라인으로 채우는 2D 면 커버리지 경로이다.
포즈 프레임/오일러 규약, 호 길이 재샘플·곡률 적응, 뷰어·다중 선택 UX, JSON 내보내기는
기존 WeldTeach 자산을 재사용한다.

### 범위 외 (Out of Scope)

- **실시간 힘 제어** — 그라인딩 품질의 핵심 절반은 로봇 컨트롤러단의 힘/임피던스 제어이다.
  본 모듈은 포즈별 목표 힘·이송 속도를 **파라미터로 내보내는 것까지**만 담당한다.
- 지능형 자동 곡면 분할(AARS 의 auto-segmentation) — 1차는 **수동 영역 선택**, 자동 분할은 차기.
- 오버행(주평면에 단사 투영 불가능한 표면)의 커버리지 — §3 Step S3 제약 참조.
- 카메라↔로봇 핸드-아이 캘리브레이션 산출(외부 입력 행렬로 수용만 한다), 충돌 검사,
  공구 마모 보상, 로봇 리치/특이점 검사.

## 2. 시스템 아키텍처 (System Architecture)

```
[3D Scan Point Cloud (.vpc / 실스캔)]        ※ 기존 PointCloudService 재사용
 │
 ▼
┌────────────────────────────────────────────────────────┐
│ [Step S1] 점군 전처리 & 법선 추정                        │  ← 신규 (kd트리는 IcpService 재사용)
│  (Voxel Downsample · Outlier 제거 · PCA k-NN Normal)   │
└──────────────────────────┬─────────────────────────────┘
 │ 정제 점군 + 지점별 법선
 ▼
┌────────────────────────────────────────────────────────┐
│ [Step S2] 점군 위 가공 영역 선택 (Lasso/Brush, WPF)      │  ← 신규 UI (다중 영역 순차 선택
└──────────────────────────┬─────────────────────────────┘     = 기존 UX 재사용)
 │ 영역 점군 부분집합 + 공정 파라미터
 ▼
┌────────────────────────────────────────────────────────┐
│ [Step S3] 2.5D Heightmap Raster Coverage Path 생성      │  ← 신규 핵심 (CoveragePathService)
│  (PCA 주평면 투영 · 그리드 보간 · 스텝오버 3D 보정)        │
└──────────────────────────┬─────────────────────────────┘
 │ 스캔라인 3D 폴리라인 + 지점별 표면 법선
 ▼
┌────────────────────────────────────────────────────────┐
│ [Step S4] 6-DoF Tool Pose (Lead/Tilt) & Export         │  ← TorchPoseService 일반화
└──────────────────────────┬─────────────────────────────┘
 │
 ▼
 [Robot Path JSON (poses + process params, 스캔 좌표계)]
```

용접 모드와 그라인딩 모드는 **공정 모드 토글**로 전환한다. 그라인딩 모드는 CAD 로드
단계 자체가 없다 (점군이 1차 입력).

## 3. 단계별 세부 기능 명세 (Feature Specifications)

### Step S1: 점군 전처리 및 법선 추정

**목적:** 실스캔 점군의 노이즈·밀도 편차를 정리하고, 커버리지·포즈 계산의 원천인
지점별 표면 법선을 추정한다.

**주요 기능:**

- **로드:** 기존 `PointCloudService`(.vpc) 재사용. VMS 본체 3D 카메라 실스캔 연동 경로도 기존과 동일.
- **Voxel Downsample:** 목표 해상도(기본 1.0 mm) 격자 평균 — 밀도 균일화 및 성능 확보.
- **통계적 이상치 제거:** k-NN 평균 거리의 μ + 2σ 초과 점 제거 (k=16 기본).
- **법선 추정:** 각 점의 k-NN(기본 k=20) 공분산 PCA 최소 고유벡터. kd트리는
  `IcpService` 의 기존 구현을 공용 유틸로 추출하여 재사용.
- **법선 방향 일관화:** 스캔 시점(카메라 원점) 방향으로 플립 — 단일 뷰 스캔 전제라
  MST 전파 없이 시점 기준으로 충분. 다중 뷰 병합 점군은 뷰별 원점 정보가 있으면 뷰별 적용.

**파라미터:** `voxelSizeMm`(1.0) / `outlierK`(16) / `outlierStdRatio`(2.0) / `normalK`(20)
— 진단용으로 노출하되 기본값으로 동작해야 한다.

### Step S2: 점군 위 가공 영역 선택

**목적:** 사용자가 뷰어에서 그라인딩할 표면 영역을 직접 지정한다 (AARS 의 "작업자 영역 선택" 대응).

**주요 기능:**

- **폴리곤 라쏘 선택:** 화면에 폴리곤을 그리면 점군을 화면 좌표로 투영해
  점-다각형 내부 판정으로 선택. 현재 카메라 시점 기준 (가림 점 포함 여부는 깊이
  필터 옵션 — 기본: 표면 첫 레이어만, 시점 깊이 중앙값 ± 밴드).
- **브러시 추가/제거:** 원형 브러시로 선택 확장·삭제 (Shift=추가, Ctrl=제거 — VMS ROI 관례 준수).
- **다중 영역 순차 선택:** 기존 다중 경로 UX 그대로 — 선택 순서 = 가공 순서,
  2D 오버레이 순번 라벨 재사용. 영역별 파라미터 개별 설정(기존 우선순위 규약).
- **선택 시각화:** 선택 점 하이라이트 색상. Helix 함정 준수(컬렉션 일괄 교체 — 반복 Add 금지).

### Step S3: 2.5D 높이맵 래스터 커버리지 경로 생성 (핵심 신규)

**목적:** 선택 영역 점군에서 스텝오버 간격의 스캔라인 경로를 생성한다.

**공정 파라미터:**

| 파라미터 | 기호/단위 | 기본값 | 설명 |
|---|---|---|---|
| 공구 직경 | `toolDiameterMm` | 50 | 그라인딩 디스크/패드 유효 폭 |
| 겹침률 | `overlapPct` | 30 % | 인접 스캔라인 겹침 비율 |
| 스텝오버 | `stepoverMm` (파생) | 35 | `toolDiameterMm × (1 − overlapPct/100)` |
| 래스터 방향 | `rasterDirection` | 자동 | 주평면 PCA 1축(영역 최장 방향) 또는 사용자 지정 각도 |
| 패턴 | `pattern` | Zigzag | `Zigzag`(왕복) / `OneWay`(편도) |
| 경계 마진 | `marginMm` | 0 | 영역 경계에서 안쪽으로 띄우는 거리 |
| 패스 수 | `passCount` | 1 | 다층 반복 가공 (블레이드 복원류 대응) |
| 패스당 깊이 | `depthPerPassMm` | 0 | 패스마다 법선 방향 오프셋 (0 = 표면 추종) |

**핵심 알고리즘:**

1. **주평면 적합 (PCA):** 영역 점군 공분산 PCA → 1·2축 = 투영 평면 기저,
   3축 = 평면 법선. 래스터 자동 방향 = 1축(최장 분산 방향).
2. **2.5D 높이맵 구성:** 점군을 주평면에 투영해 (a, b, h) 좌표화 → 셀 크기
   `voxelSizeMm` 그리드에 h(높이)와 법선을 집계. 빈 셀은 이웃 보간(작은 구멍)
   또는 **영역 외 처리**(큰 구멍 — 스캔라인이 자연 분할된다).
3. **영역 경계 마스크:** 점 존재 셀 기반 occupancy 마스크 + 모폴로지 닫힘(1셀)
   → 유효 셀 판정. `marginMm` 은 마스크 침식(erosion)으로 적용.
4. **스캔라인 배치:** 래스터 방향 등간격 라인. 간격은 평면상 등간격이 아니라
   **표면 3D 거리 기준** — 인접 라인의 3D 최대 간격이 `stepoverMm` 를 초과하면
   해당 구간의 라인 간격을 비례 축소(경사면·곡면에서 누락 연마 방지가 과커버보다 우선).
5. **폴리라인 생성:** 라인을 셀 단위로 샘플 → 유효 셀만 통과 → h·법선을 쌍선형
   보간해 3D 점·법선 산출 → 연속 유효 구간을 세그먼트로 분리(구멍·경계에서 분할).
6. **평활화·재샘플:** 폴리라인에 이동평균 평활(노이즈 완화, 창 3~5) 후 기존
   **호 길이 재샘플 + 곡률 적응**(`BuildAdaptiveStations`, 현 오차 0.05 mm) 그대로 적용.
7. **지그재그 연결:** 홀수 라인 역방향 정렬. 라인 간 이동은 경로에 포함하지 않고
   **세그먼트 분리**로 내보낸다 (접근/후퇴는 로봇단 책임 — 1차 단순화).

**제약 (명시):** 주평면에 **단사(1:1) 투영 가능한 2.5D 표면**만 지원한다 — 완만한
곡면 패널, 평면, 부분 뷰 원통면 등. 오버행/폐곡면(전체 원통 둘레 등)은 범위 외이며,
투영 시 같은 셀에 상·하면이 겹치면(높이 분산 임계 초과) 경고를 표시한다.

**데이터 구조 (의사 코드):**

```csharp
/// <summary>그라인딩 커버리지 영역 — 선택 점군 + 파라미터 + 생성된 스캔라인들.</summary>
public class GrindingPathRegion
{
    public string RegionId { get; set; }
    public int[] PointIndices { get; set; }            // 원본 점군 내 선택 인덱스
    public GrindingParams Params { get; set; }          // 위 파라미터 표
    /// <summary>스캔라인(구멍/경계 분할 포함) — 기존 WeldingPathContour 와 동형:
    /// PathPoints / PointNormals(법선) / PosePoints / Poses.</summary>
    public List<CoverageScanline> Scanlines { get; set; }
    public double TotalLengthMm { get; set; }
    public double CoveredAreaMm2 { get; set; }          // 검증용 추정 커버 면적
}
```

`CoverageScanline` 은 `WeldingPathContour` 구조(폴리라인 + 지점별 방향 벡터 + 포즈)를
따르되 `PointBisectors`(이등분) 대신 `PointNormals`(표면 법선)를 담는다. 공통 부분은
추출하여 두 공정이 공유한다.

### Step S4: 공구 포즈 계산 (Lead/Tilt) 및 내보내기

**목적:** 스캔라인 지점별 법선과 진행 방향으로 6-DoF 공구 포즈를 생성한다.
프레임/오일러 규약은 용접과 **완전히 동일**하다.

**1) 6-DoF 공구 포즈 생성 알고리즘**

1. **진행 방향 (Z-Axis):** 스캔라인 접선 `T = dP/dt` (재샘플 점 이웃 차분 — 기존과 동일)
2. **공구 축 (X-Axis):** 표면 법선 `N` 에 리드/틸트각을 적용한 벡터
   - 리드각 `leadAngleDeg` (기본 10°): 법선을 **진행 방향으로** 기울임 — 회전축 = 측면 벡터 `S = N × T`
   - 틸트각 `tiltAngleDeg` (기본 0°): 법선을 **측면으로** 기울임 — 회전축 = 진행 벡터 `T`
   - `V_tool = Rot(T, tilt) · Rot(S, lead) · N`, 이후 접선에 직교화 (기존 이등분 처리와 동일)
3. **Y-Axis:** `Y = Z × X`, **오일러:** ZYX(deg) — 기존 `ToZyxEuler` 재사용
4. **다층 패스:** `passCount > 1` 이면 패스 k 위치를 `P − k·depthPerPassMm·N` 으로 오프셋 반복

`TorchPose` 레코드(X, Y, Z, Roll, Pitch, Yaw)를 그대로 재사용한다
(필요 시 `ToolPose` 로 개명하되 구조 변경 없음).

**2) 좌표계 및 내보내기**

- 경로는 **스캔(카메라) 좌표계**에서 생성된다 — CAD↔스캔 ICP 정합(T_align) 불필요.
- 로봇 베이스 좌표계 변환은 **핸드-아이 캘리브레이션 행렬 `T_cam2base`** (외부 입력,
  4×4 row-major JSON/파일)를 받아 기존 `TransformPose` 로 적용한다. 미입력 시
  카메라 좌표계 그대로 내보내고 frame 필드에 명시.
- JSON 스키마 (기존 `ExportJson` 확장 — 용접 경로와 한 파일 공존 가능):

```jsonc
{
  "eulerConvention": "ZYX(deg)",
  "frame": "camera coordinates (T_cam2base 미적용)",   // 또는 "robot base coordinates"
  "tCam2BaseRowMajor": null,
  "paths": [
    {
      "order": 1,
      "processType": "grinding",            // "welding" | "grinding"
      "regionId": "Region1",
      "params": {                            // grinding 전용 — 로봇단 전달 메타 포함
        "toolDiameterMm": 50, "overlapPct": 30, "stepoverMm": 35,
        "leadAngleDeg": 10, "tiltAngleDeg": 0,
        "passCount": 1, "depthPerPassMm": 0,
        "feedRateMmS": 20, "targetForceN": 15   // 실행값 — 힘 제어는 로봇단 책임
      },
      "scanlines": [                         // 세그먼트별 포즈 배열 (라인 간 이동 미포함)
        { "index": 0, "reversed": false,
          "poses": [ { "x":0, "y":0, "z":0, "roll":0, "pitch":0, "yaw":0 } ] }
      ]
    }
  ]
}
```

## 4. UI/UX 명세

- **공정 모드 토글** (툴바): 용접(CAD+엣지) ↔ 그라인딩(점군+영역). 모드별 파라미터 패널 전환.
- **그라인딩 모드 흐름:** 점군 열기 → (전처리 자동) → 라쏘/브러시 영역 선택 →
  파라미터 조정 → 경로 생성 → 미리보기 → 내보내기.
- **파라미터 우선순위:** 기존 규약(전역 기본값 → 영역별 개별 설정 덮어쓰기) 그대로 적용.
- **미리보기:** 스캔라인 폴리라인 + 포즈 화살표(기존 렌더러 재사용), 스캔라인 인덱스
  그라데이션으로 진행 순서 표현, 영역 순번 2D 오버레이 라벨 재사용.
- **요약 표시:** 기존 `Summary` 형식 —
  예: `"점 12,400 · 라인 14 · 1,240 mm · 포즈 830 @35mm 스텝오버"`.
- **경고 표시:** 2.5D 위반(높이 겹침), 빈 셀 과다(스캔 품질), 법선 신뢰도 낮음(평면성 부족).
- **Helix 함정 준수:** 보이는 `LinesVisual3D.Points` 반복 Add 금지 — 채운 뒤 일괄 교체 할당.

## 6. 단계별 검증 및 테스트 계획 (Verification Plan)

**합성 점군 생성기 (1급 기능):** CAD·실물 없이 전 단계를 정량 검증하기 위해 해석적
표면에서 점군을 합성하는 루틴을 내장한다 (`GenerateSamplePointCloud` — 기존
`GenerateSampleStep` 의 그라인딩 대응물). 표면 종류: 평면 / 경사 평면(30°) /
원통 셸(부분 뷰) / 사인 범프 패널 / 중앙 원형 구멍 패널. 가우시안 노이즈
σ = 0 / 0.05 / 0.15 mm 주입 옵션. 해석 법선·면적과 비교해 오차를 수치화한다.

1. **S1 검증 (전처리·법선):** 합성 평면·원통에서 추정 법선 vs 해석 법선 각도 오차
   평균 ≤ 2°, 노이즈 σ=0.15 mm 에서도 ≤ 5°. 이상치 제거율·다운샘플 밀도 확인.
2. **S2 검증 (영역 선택):** 라쏘 다각형 내부 점 선택 정확성(투영 검증),
   10만 점 점군에서 선택 반응 ≤ 100 ms, 브러시 추가/제거 동작.
3. **S3 검증 (커버리지):**
   - *평면:* 스텝오버 간격 오차 ≤ 0.5 mm, 커버리지(라인 ± 공구 반경 합집합 / 영역 면적)
     ≥ 99 %, 라인 수 = ⌈폭/스텝오버⌉ + 1.
   - *경사 평면 30°:* 표면 3D 간격 기준 보정 확인 — 인접 라인 3D 간격 ≤ stepover × 1.05.
   - *원통 셸:* 스캔라인이 표면을 추종(점군까지 최대 편차 ≤ 복셀 크기), 법선 방향 정확.
   - *구멍 패널:* 스캔라인이 구멍에서 세그먼트 분할, 경계 침범 없음, `marginMm` 이격 확인.
   - *노이즈 강건성:* σ=0.15 mm 에서 경로 요동(이웃 포즈 각도 변화) ≤ 3°.
4. **S4 검증 (포즈·내보내기):** 평면 + 리드 10° → 공구축-법선 각도 = 10.0° ± 0.5°
   (수치 검증), 퇴화(법선 ∥ 접선) 폴백 동작, `T_cam2base` 적용 변환 검증
   (기존 `TransformPose` 테스트 재사용), JSON 스키마 필드 완전성.
5. **실스캔 스모크:** VMS 3D 카메라 실스캔 .vpc (임의 물체 — CAD 불필요) 로드 →
   영역 선택 → 경로 생성 → 미리보기 육안 확인.
6. **자가 진단:** `--selftest` 에 S1~S4 시나리오 추가, `--open <vpc> --capture` 진단
   경로에 그라인딩 모드 캡처 추가.

## 8. 미결정 사항 (Open Questions)

1. **라쏘 선택의 깊이 처리** — 화면 투영 선택은 뒤쪽 표면까지 잡힐 수 있다. 기본
   깊이 밴드 필터로 시작하되, 실사용에서 혼란스러우면 "보이는 표면만" (법선·시점
   내적 > 0) 필터 추가 검토.
2. **자동 곡면 분할** — AARS 의 지능형 분할(평면성/곡률 기반 리전 그로잉) 도입 시점.
   수동 선택으로 현장성 확인 후 결정.
3. **래스터 방향 지정 UX** — 자동(PCA 최장축)으로 시작. 사용자 지정은 "화면에서 방향
   드래그" vs 각도 입력 중 사용성 보고 결정.
4. **feedRateMmS / targetForceN 의 위치** — 영역 전체 값으로 시작. 구간별 가변(모서리
   감속 등)은 로봇 벤더 선정 후 결정.
5. **T_cam2base 확보 절차** — 핸드-아이 캘리브레이션은 별도 모듈/외부 도구 결과를
   행렬 파일로 받는 것으로 시작 (VMS 3D 측정 로드맵의 로봇 캘리브 자산과 연계 검토).
